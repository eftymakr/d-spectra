## Related Works

Serverless computing has emerged as a transformative paradigm in cloud computing, offering automatic scaling, efficient resource utilization, and cost-effective pricing models \[[1](https://www.semanticscholar.org/paper/d911b03bfda4fc6fc92f8080bb81b3a967d6a9e7)\]. However, the cold-start problem remains a critical challenge, significantly impacting end-to-end performance \[[1](https://www.semanticscholar.org/paper/d911b03bfda4fc6fc92f8080bb81b3a967d6a9e7)\]. Cold starts occur when a function container is provisioned on-demand, leading to delays in execution \[[1](https://www.semanticscholar.org/paper/d911b03bfda4fc6fc92f8080bb81b3a967d6a9e7)\]. This issue has been extensively studied, with various approaches proposed to mitigate its effects.

Several works have focused on reducing cold-start latency through container reuse and caching. For instance, Catalyzer introduces a sandbox system that restores function instances from checkpoint images, eliminating the need for initialization on the critical path \[[2](https://www.semanticscholar.org/paper/f14446970a5ed7145a6d350e1aff07ca203cece8)\]. This approach achieves sub-millisecond startup times and significantly reduces end-to-end latency \[[2](https://www.semanticscholar.org/paper/f14446970a5ed7145a6d350e1aff07ca203cece8)\]. Similarly, Xanadu addresses cascading cold starts in function chains by employing speculative and just-in-time provisioning, effectively eliminating cascading overheads \[[7](https://www.semanticscholar.org/paper/1cd137e77753ee6c51c97c520d64f91d484dbddc)\]. The system demonstrates substantial improvements over existing platforms, reducing platform overheads by up to 18x for short workflows \[[7](https://www.semanticscholar.org/paper/1cd137e77753ee6c51c97c520d64f91d484dbddc)\].

Function caching has also been explored as a means to alleviate cold starts. S-Cache proposes an adaptive caching policy for serverless edge computing, balancing cold-start overheads with resource utilization \[[10](https://www.semanticscholar.org/paper/f85fde870a1eb9c98c62ded89602e2bd1bab6a86)\]. The algorithm reduces both average response time and cold-start frequency by a factor of 3 compared to existing approaches \[[10](https://www.semanticscholar.org/paper/f85fde870a1eb9c98c62ded89602e2bd1bab6a86)\]. FaasCache further extends this idea by introducing a greedy-dual caching policy inspired by caching principles, reducing cold-start overhead by more than 3× compared to current methods \[[15](https://www.semanticscholar.org/paper/3c05fec4087d94c61233a482e59b613388b2c3ae)\]. This approach also enables more efficient resource provisioning, reducing resource requirements by up to 30% \[[15](https://www.semanticscholar.org/paper/3c05fec4087d94c61233a482e59b613388b2c3ae)\].

Prebaking functions to warm the serverless cold start is another promising technique. This method restores snapshots from previously executed function processes, significantly improving startup times \[[16](https://www.semanticscholar.org/paper/ab1c0062964a2df3d7f8d11da4a774530286b801)\]. Experiments show that this technique can reduce startup time by up to 71% for certain workloads \[[16](https://www.semanticscholar.org/paper/ab1c0062964a2df3d7f8d11da4a774530286b801)\]. Similarly, the Adaptive Warm-Up Strategy (AWUS) predicts function invocation times and pre-warms functions to reduce cold start latency \[[12](https://www.semanticscholar.org/paper/81b8db7a20f1aa859143c716b38a1443e3eca9a0)\]. This strategy, when combined with an Adaptive Container Pool Scaling Strategy (ACPSS), effectively minimizes resource waste while maintaining low latency \[[12](https://www.semanticscholar.org/paper/81b8db7a20f1aa859143c716b38a1443e3eca9a0)\].

Function fusion has also been proposed as a way to mitigate cold start latency in workflows. ### <a id='category-cold-start-problem-in-serverless'></a>Cold-Start Problem in Serverless: 8 papers found.
The cold-start problem in serverless computing remains a critical challenge, impacting the performance and efficiency of function-as-a-service (FaaS) platforms. This issue arises due to the overhead of initializing runtime environments and loading dependencies for each function invocation, leading to increased latency \[[1](https://www.semanticscholar.org/paper/d911b03bfda4fc6fc92f8080bb81b3a967d6a9e7)\]. Several studies have explored solutions to mitigate this problem. For instance, Catalyzer proposes a sandbox system that restores function instances from checkpoint images, significantly reducing startup latency by avoiding the initialization process \[[2](https://www.semanticscholar.org/paper/f14446970a5ed7145a6d350e1aff07ca203cece8)\]. Similarly, Xanadu addresses cascading cold starts in workflows by employing speculative and just-in-time provisioning of resources, effectively eliminating the latency overheads associated with sequential function invocations \[[7](https://www.semanticscholar.org/paper/1cd137e77753ee6c51c97c520d64f91d484dbddc)\]. Additionally, FaaSLight introduces an application-level optimization approach that identifies and loads only the necessary code for function execution, thereby reducing code loading latency and improving overall performance \[[17](http://arxiv.org/abs/2207.08175)\]. These approaches highlight the diverse strategies being developed to tackle cold starts, ranging from runtime optimizations to architectural innovations. Furthermore, research on Azure Functions has revealed that function invocation frequencies vary widely, prompting the development of resource management policies that minimize cold starts while maintaining low resource costs \[[5](http://arxiv.org/abs/2003.03423)\]. Overall, these works underscore the importance of addressing cold starts to enhance the scalability and responsiveness of serverless systems.

### <a id='category-container-reuse-and-caching-techniques'></a>Container Reuse and Caching Techniques: 2 papers found.
Container reuse and caching techniques have been extensively studied to address the cold-start problem in serverless computing. Existing approaches, such as fixed caching and histogram-based policies, often fail to account for the diverse characteristics of containers, including their frequency of use, size, and cold-start time, leading to suboptimal performance \[[10](https://www.semanticscholar.org/paper/f85fde870a1eb9c98c62ded89602e2bd1bab6a86)\]. Similarly, keep-alive policies, which aim to maintain functions in a ready state, face challenges due to the variability in FaaS workloads, and traditional methods lack the adaptability needed to handle such diversity \[[15](https://www.semanticscholar.org/paper/3c05fec4087d94c61233a482e59b613388b2c3ae)\]. To overcome these limitations, researchers have proposed adaptive caching policies that incorporate container-specific metrics, such as reuse distances and hit-ratio curves, to improve cache efficiency and reduce cold-start overhead \[[15](https://www.semanticscholar.org/paper/3c05fec4087d94c61233a482e59b613388b2c3ae)\]. These techniques not only enhance response times but also contribute to more efficient resource utilization, aligning with the core principles of serverless computing \[[10](https://www.semanticscholar.org/paper/f85fde870a1eb9c98c62ded89602e2bd1bab6a86)\]. By integrating caching-inspired strategies into system design, such as the Greedy-Dual keep-alive policy, it is possible to achieve significant performance improvements, with some studies reporting a reduction in cold-start frequency by a factor of 3 \[[10](https://www.semanticscholar.org/paper/f85fde870a1eb9c98c62ded89602e2bd1bab6a86)\]. These advancements highlight the importance of tailoring caching and reuse strategies to the unique demands of serverless environments.
