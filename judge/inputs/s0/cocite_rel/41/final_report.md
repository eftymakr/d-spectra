## Related Works

Serverless computing has emerged as a transformative paradigm in cloud computing, offering automatic scaling, efficient resource utilization, and cost-effective pricing models \[[16](http://arxiv.org/abs/1911.01296)\]. However, a significant challenge persists in the form of cold-start latency, which can severely impact end-to-end performance \[[16](http://arxiv.org/abs/1911.01296)\]. This issue arises due to the overhead of initializing runtime environments and dependencies before a function can execute \[[16](http://arxiv.org/abs/1911.01296)\]. Several approaches have been proposed to mitigate this problem, each with varying degrees of success.

One line of research focuses on reducing the startup latency of serverless functions by optimizing the initialization process. For instance, Catalyzer introduces a sandbox system that restores function instances from precomputed checkpoint images, thereby eliminating the need for initialization on the critical path \[[2](https://www.semanticscholar.org/paper/f14446970a5ed7145a6d350e1aff07ca203cece8)\]. This approach achieves sub-millisecond startup times, significantly outperforming traditional methods \[[2](https://www.semanticscholar.org/paper/f14446970a5ed7145a6d350e1aff07ca203cece8)\]. Similarly, the *Prebaking* technique restores snapshots of previously executed function processes, reducing startup times by up to 71% for certain workloads \[[6](https://www.semanticscholar.org/paper/ab1c0062964a2df3d7f8d11da4a774530286b801)\]. These methods demonstrate that minimizing initialization overhead is a promising avenue for addressing cold-start latency.

Another approach involves managing function instances to reduce the frequency of cold starts. The *LCS* (Least Recently Used Warm Container Selection) approach keeps containers alive for longer periods, reducing the need for frequent reinitialization \[[3](https://www.semanticscholar.org/paper/d45518ce5741587c4c37ccbc5e74b3fcfd6f80f1)\]. This method outperforms the MRU (Most Recently Used) approach by approximately 48% \[[3](https://www.semanticscholar.org/paper/d45518ce5741587c4c37ccbc5e74b3fcfd6f80f1)\]. Similarly, the *FaasCache* system employs a caching-inspired keep-alive policy that reduces cold-start overhead by more than 3× compared to current approaches \[[11](https://www.semanticscholar.org/paper/3c05fec4087d94c61233a482e59b613388b2c3ae)\]. These techniques highlight the importance of maintaining warm function instances to minimize latency.

Function fusion has also been explored as a way to mitigate cold-start latency in workflows. By combining multiple functions into a single function, the cold start of subsequent functions can be avoided \[[4](https://www.semanticscholar.org/paper/36338d869d7589b01c3707d70bece8c320e439e2)\]. However, this approach may increase response time for parallel workflows, as functions run sequentially \[[4](https://www.semanticscholar.org/paper/36338d869d7589b01c3707d70bece8c320e439e2)\]. The *Xanadu* system addresses cascading cold starts in function chains by employing speculative and just-in-time provisioning of resources, effectively eliminating cascading overheads \[[10](https://www.semanticscholar.org/paper/1cd137e77753ee6c51c97c520d64f91d484dbddc)\]. This approach demonstrates the potential of intelligent resource management in reducing cold-start latency.

Recent work has also focused on leveraging reinforcement learning to predict and prepare function instances based on invocation patterns \[[8](https://www.semanticscholar.org/paper/96d4fea8d034a7605af936f2e2b6a44becdf6585)\]. ### <a id='category-cold-start-latency-challenges'></a>Cold-Start Latency Challenges: 8 papers found.
Cold-start latency remains a critical challenge in serverless computing, affecting the performance and efficiency of function-as-a-service (FaaS) platforms \[[1](https://www.semanticscholar.org/paper/d911b03bfda4fc6fc92f8080bb81b3a967d6a9e7)\]. This issue arises due to the delay in provisioning runtime containers to execute functions, which can lead to significant delays ranging from hundreds of milliseconds to seconds \[[3](https://www.semanticscholar.org/paper/d45518ce5741587c4c37ccbc5e74b3fcfd6f80f1)\]. Various approaches have been proposed to mitigate this problem, including techniques such as keeping containers warm using scheduling strategies like Least Recently Used (LRS) \[[2](https://www.semanticscholar.org/paper/f14446970a5ed7145a6d350e1aff07ca203cece8)\], restoring function snapshots to reduce initialization time \[[6](https://www.semanticscholar.org/paper/ab1c0062964a2df3d7f8d11da4a774530286b801)\], and implementing caching-inspired keep-alive policies to maintain function availability \[[7](https://www.semanticscholar.org/paper/c066cf85b94846ddc057a113ce110e045f587375)\]. Additionally, some studies have focused on optimizing workflow execution by reducing cascading cold starts through speculative and just-in-time resource provisioning \[[10](https://www.semanticscholar.org/paper/1cd137e77753ee6c51c97c520d64f91d484dbddc)\]. These methods aim to improve the responsiveness of serverless systems by minimizing the overhead associated with cold starts. Furthermore, research has explored the use of adaptive caching policies that consider factors such as container frequency, size, and cold-start time to balance performance and resource utilization \[[8](https://www.semanticscholar.org/paper/96d4fea8d034a7605af936f2e2b6a44becdf6585)\]. While these approaches show promise, the challenge of efficiently managing cold starts remains an active area of research, especially as serverless computing continues to evolve and expand into edge environments \[[14](https://www.semanticscholar.org/paper/f85fde870a1eb9c98c62ded89602e2bd1bab6a86)\].

The evaluation shows that Catalyzer reduces startup latency by orders of magnitude, achieves < 1ms latency in the best case, and significantly reduces the end-to-end latency for real-world workloads. ### <a id='category-serverless-computing-overview'></a>Serverless Computing Overview: 4 papers found.
The emerging serverless computing paradigm has attracted significant attention from both academia and industry due to its benefits such as reduced operational complexity, pay-as-you-go pricing models, and auto-scaling capabilities \[[3](https://www.semanticscholar.org/paper/d45518ce5741587c4c37ccbc5e74b3fcfd6f80f1)\]. However, it also presents challenges, particularly in terms of cold-start latency, which can negatively impact end-to-end performance \[[3](https://www.semanticscholar.org/paper/d45518ce5741587c4c37ccbc5e74b3fcfd6f80f1)\]. Existing static analysis techniques can identify unreachable libraries but fail to address workload-dependent inefficiencies, resulting in limited performance improvements \[[3](https://www.semanticscholar.org/paper/d45518ce5741587c4c37ccbc5e74b3fcfd6f80f1)\]. To overcome these limitations, researchers have proposed tools like SLIMSTART, a profile-guided optimization tool designed to identify and mitigate inefficient library usage patterns in serverless applications \[[3](https://www.semanticscholar.org/paper/d45518ce5741587c4c37ccbc5e74b3fcfd6f80f1)\]. By leveraging statistical sampling and call-path profiling, SLIMSTART collects runtime library usage data, generates optimization reports, and applies automated code transformations to reduce cold-start overhead \[[3](https://www.semanticscholar.org/paper/d45518ce5741587c4c37ccbc5e74b3fcfd6f80f1)\]. Furthermore, SLIMSTART integrates seamlessly into CI/CD pipelines, enabling adaptive monitoring and continuous optimizations tailored to evolving workloads \[[3](https://www.semanticscholar.org/paper/d45518ce5741587c4c37ccbc5e74b3fcfd6f80f1)\]. Through extensive evaluation across three benchmark suites and four real-world serverless applications, SLIMSTART has demonstrated significant improvements, including up to a 2.30X speedup in initialization latency, a 2.26X improvement in end-to-end latency, and a 1.51X reduction in memory usage \[[3](https://www.semanticscholar.org/paper/d45518ce5741587c4c37ccbc5e74b3fcfd6f80f1)\]. These advancements highlight the ongoing efforts to address the challenges of serverless computing and optimize resource utilization \[[3](https://www.semanticscholar.org/paper/d45518ce5741587c4c37ccbc5e74b3fcfd6f80f1)\].
