## Related Works

Generative retrieval has emerged as a promising paradigm that replaces traditional search index data structures with a single large-scale neural network, enabling improved efficiency and seamless integration with generative large language models \[[12](http://arxiv.org/abs/2202.06991)\]. This approach leverages autoregressive generation to directly produce document identifiers from queries, eliminating the need for separate indexing and retrieval stages \[[12](http://arxiv.org/abs/2202.06991)\]. Several recent works have explored the potential of this paradigm, focusing on different aspects such as scalability, effectiveness, and end-to-end modeling \[[1](http://arxiv.org/abs/2204.10628)\]\[[2](http://arxiv.org/abs/2305.11841)\]\[[3](http://arxiv.org/abs/2304.04171)\]\[[4](http://arxiv.org/abs/2308.14968)\]\[[5](http://arxiv.org/abs/2311.09134)\]\[[6](http://arxiv.org/abs/2206.02743)\]\[[7](http://arxiv.org/abs/2007.00808)\]\[[8](http://arxiv.org/abs/2305.11161)\]\[[9](http://arxiv.org/abs/2010.00904)\]\[[10](http://arxiv.org/abs/2004.04906)\]\[[11](http://arxiv.org/abs/2108.05540)\]\[[12](http://arxiv.org/abs/2202.06991)\].

Early efforts in generative retrieval focused on using transformer-based models to encode entire document corpora and generate document identifiers during retrieval \[[12](http://arxiv.org/abs/2202.06991)\]. These models, often referred to as differentiable search indexes, have been shown to outperform traditional dual-encoder models in certain settings \[[12](http://arxiv.org/abs/2202.06991)\]. However, the effectiveness of these models on large-scale corpora has been limited by challenges such as computational cost and the need for synthetic queries during indexing \[[2](http://arxiv.org/abs/2305.11841)\]. To address these issues, researchers have proposed various techniques, including the use of synthetic queries as document representations \[[2](http://arxiv.org/abs/2305.11841)\], and the development of efficient indexing methods like Incremental Product Quantization \[[4](http://arxiv.org/abs/2308.14968)\].

A key challenge in generative retrieval is the definition of document identifiers. While some approaches rely on fixed rule-based identifiers, such as document titles or BERT embeddings \[[3](http://arxiv.org/abs/2304.04171)\], others propose learning-based methods to generate semantic docids \[[3](http://arxiv.org/abs/2304.04171)\]. The GenRet method, for example, learns to tokenize documents into short discrete representations using a discrete auto-encoding approach \[[3](http://arxiv.org/abs/2304.04171)\]. This enables end-to-end modeling of document retrieval tasks and has shown promising results on benchmark datasets \[[3](http://arxiv.org/abs/2304.04171)\].

Another important aspect of generative retrieval is the ability to handle dynamic and evolving corpora. The CLEVER model, for instance, addresses the challenge of continual learning by proposing an incremental indexing method and a memory-augmented learning mechanism to preserve previous knowledge while incorporating new documents \[[4](http://arxiv.org/abs/2308.14968)\]. This is crucial for real-world applications where document collections are frequently updated \[[4](http://arxiv.org/abs/2308.14968)\].

Recent research has also focused on improving the scalability of generative retrieval models. The RIPOR framework, for example, introduces a novel prefix-oriented ranking optimization algorithm and constructs document IDs based on relevance associations between queries and documents \[[5](http://arxiv.org/abs/2311.09134)\]. This approach has led to significant improvements in retrieval performance on large-scale benchmarks such as MS MARCO \[[5](http://arxiv.org/abs/2311.09134)\].

### <a id='category-document-identifier-generation'></a>Document Identifier Generation: 3 papers found.
Document Identifier Generation has been a focal point in recent advancements within generative retrieval systems. Researchers have explored various methods to define and generate document identifiers (docids) that enable end-to-end retrieval without relying on traditional index-based approaches \[[3](http://arxiv.org/abs/2304.04171)\]. One approach involves using autoregressive models to generate and score distinctive ngrams from passages, which are then mapped to full documents via efficient data structures \[[1](http://arxiv.org/abs/2204.10628)\]. This method allows for more flexible and semantically rich identifiers compared to fixed rule-based docids such as titles or clustered embeddings \[[2](http://arxiv.org/abs/2305.11841)\]. Another line of work proposes GenRet, a method that learns to tokenize documents into short discrete representations (docids) using a discrete auto-encoding framework, enabling fully end-to-end modeling of retrieval tasks \[[2](http://arxiv.org/abs/2305.11841)\]. Additionally, TOME introduces a two-stage generation architecture that utilizes tokenized URLs as identifiers and addresses challenges in model-based retrieval through novel training strategies \[[3](http://arxiv.org/abs/2304.04171)\]. These approaches highlight the evolving landscape of document identifier generation, emphasizing the need for more generalizable and robust methods that can effectively capture semantic information while maintaining efficiency \[[1](http://arxiv.org/abs/2204.10628)\]\[[2](http://arxiv.org/abs/2305.11841)\]\[[3](http://arxiv.org/abs/2304.04171)\].

### <a id='category-differentiable-search-indexes'></a>Differentiable Search Indexes: 4 papers found.
Differentiable search indexes represent a novel paradigm in information retrieval, where a single transformer model encodes all corpus information and directly maps queries to document identifiers \[[2](http://arxiv.org/abs/2305.11841)\]. This approach eliminates the need for traditional index structures, simplifying the retrieval process \[[2](http://arxiv.org/abs/2305.11841)\]. Research has shown that these models can be trained to perform effectively on large-scale benchmarks, surpassing state-of-the-art generative retrieval models by significant margins \[[1](http://arxiv.org/abs/2204.10628)\]. However, current DSI models face challenges due to data distribution mismatches between indexing and retrieval phases, particularly when dealing with cross-lingual retrieval \[[3](http://arxiv.org/abs/2304.04171)\]. To address this, DSI-QG was introduced, which generates potential relevant queries during indexing, allowing the model to better align with retrieval queries \[[3](http://arxiv.org/abs/2304.04171)\]. Additionally, generative retrieval models, such as RIPOR, have been developed to improve accuracy through prefix-oriented ranking optimization and relevance-based document ID construction \[[1](http://arxiv.org/abs/2204.10628)\]. These advancements highlight the ongoing efforts to enhance the generalization and robustness of differentiable search indexes, making them more viable for real-world applications \[[1](http://arxiv.org/abs/2204.10628)\]\[[2](http://arxiv.org/abs/2305.11841)\]\[[3](http://arxiv.org/abs/2304.04171)\].

### <a id='category-end-to-end-retrieval-models'></a>End-to-End Retrieval Models: 3 papers found.
End-to-end retrieval models have gained significant attention for their ability to unify training and indexing stages, improving recall performance over traditional methods. These models, such as the Neural Corpus Indexer (NCI), use sequence-to-sequence networks to directly generate relevant document identifiers for a query, avoiding the limitations of index-retrieve paradigms \[[6](http://arxiv.org/abs/2206.02743)\]. Additionally, dense retrieval approaches, which rely on embeddings learned from questions and passages using dual-encoder frameworks, have shown competitive performance compared to traditional sparse vector space models like TF-IDF or BM25, achieving improvements of up to 19% in top-20 passage retrieval accuracy \[[10](http://arxiv.org/abs/2004.04906)\]. Recent advancements have also focused on addressing the fragility of dense retrievers to training data noise and the need for large batches, with solutions like coCondenser leveraging contrastive losses to warm up the embedding space without heavy data engineering \[[11](http://arxiv.org/abs/2108.05540)\]. These developments highlight the ongoing efforts to enhance the robustness and generalization of end-to-end retrieval systems.

[Snippet]: «Entities are at the center of how we represent and aggregate knowledge. For instance, Encyclopedias such as Wikipedia are structured by entities (e.g., one per article). The ability to retrieve such entities given a query is fundamental for knowledge-intensive tasks such as entity linking and open-domain question answering. One way to understand current approaches is as classifiers among atomic labels, one for each entity. Their weight vectors are dense entity representations produced by encoding entity information such as descriptions. This approach leads to several shortcomings: i) context and entity affinity is mainly captured through a vector dot product, potentially missing fine-grained interactions between the two; ii) a large memory footprint is needed to store dense representations when considering large entity sets; iii) an appropriately hard set of negative data has to be subsampled at training time. We propose GENRE, the first system that retrieves entities by generating their unique names, left to right, token-by-token in an autoregressive fashion, and conditioned on the context. This enables to mitigate the aforementioned technical issues: i) the autoregressive formulation allows us to directly capture relations between context and entity name, effectively cross encoding both; ii) the memory footprint is greatly reduced because the parameters of our encoder-decoder architecture scale with vocabulary size, not entity count; iii) the exact softmax loss can be efficiently computed without the need to subsample negative data. We show the efficacy of the approach with more than 20 datasets on entity disambiguation, end-to-end entity linking and document retrieval tasks, achieving new SOTA, or very competitive results while using a tiny fraction of the memory of competing systems. Finally, we demonstrate that new entities can be added by simply specifying their unambiguous name.»
