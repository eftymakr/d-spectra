## Related Works

Serverless computing has emerged as a transformative paradigm in cloud computing, offering automatic scaling, efficient resource utilization, and cost-effective pricing models \[[1](https://www.semanticscholar.org/paper/d911b03bfda4fc6fc92f8080bb81b3a967d6a9e7)\]. However, the cold-start latency issue remains a significant challenge, adversely affecting end-to-end performance \[[2](http://arxiv.org/abs/2310.08437)\]. Several studies have explored solutions to mitigate this problem. For instance, \[[3](https://www.semanticscholar.org/paper/f14446970a5ed7145a6d350e1aff07ca203cece8)\] highlights that cold starts occur due to the delay in provisioning runtime containers, which is a critical factor in serverless platforms. This delay is exacerbated by the need to initialize containers for each function invocation, which can introduce non-negligible overhead \[[4](https://www.semanticscholar.org/paper/b99668ae35c4b6796b827657a318fe4b84a757ff)\].

To address the cold-start problem, various approaches have been proposed. One common strategy is to maintain a pool of warm containers to reduce the latency associated with initializing new containers \[[5](https://www.semanticscholar.org/paper/81b8db7a20f1aa859143c716b38a1443e3eca9a0)\]. This approach has been implemented in several platforms, including AWS Lambda and Knative Serving, where maintaining a pool of function instances significantly reduces the P99 response time \[[6](https://www.semanticscholar.org/paper/96d4fea8d034a7605af936f2e2b6a44becdf6585)\]. However, this method may lead to increased resource consumption if the idle container window is too long, which contradicts the scale-to-zero feature of serverless computing \[[7](https://www.semanticscholar.org/paper/27cd21426fe51167dd6ac79d1c83db55a07a2046)\].

Another approach involves using adaptive models to predict the optimal length of the idle container window and the number of pre-warmed containers required \[[8](https://www.semanticscholar.org/paper/c066cf85b94846ddc057a113ce110e045f587375)\]. This method leverages deep neural networks and LSTM models to capture previous function invocation patterns, allowing for more accurate predictions and reducing the frequency of cold starts \[[9](https://www.semanticscholar.org/paper/d9eaeccc9cca929af052aa362efaf83267daf614)\]. Additionally, \[[10](https://www.semanticscholar.org/paper/fde534d033dea54e1b9066bad32d7330febe54f3)\] proposes an adaptive warm-up strategy that predicts function invocation times and pre-warms functions to minimize cold-start latency. This strategy is further enhanced by a fine-grained regression method that improves the accuracy of predictions for non-first functions in a function chain \[[11](https://www.semanticscholar.org/paper/fbf4355d06ddb5f6c81e67cffadf57f6939b8940)\].

Reinforcement learning has also been applied to mitigate cold starts by analyzing factors such as CPU utilization and invocation concurrency \[[12](https://www.semanticscholar.org/paper/ab1c0062964a2df3d7f8d11da4a774530286b801)\]. This approach enables the platform to learn invocation patterns and prepare the optimal number of function instances in advance, reducing the cold start frequency \[[13](https://www.semanticscholar.org/paper/891a89fad669dc7d107ad2d5a047b288b5cc9832)\]. Furthermore, \[[14](https://www.semanticscholar.org/paper/1cd137e77753ee6c51c97c520d64f91d484dbddc)\] introduces a two-layer adaptive approach that combines reinforcement learning with LSTM to predict function invocation times and determine the required prewarmed containers, resulting in improved memory consumption and execution invocations \[[15](http://arxiv.org/abs/2003.03423)\].

In addition to these strategies, \[[16](http://arxiv.org/abs/2207.08175)\] proposes a technique that restores snapshots from previously executed function processes, significantly improving the start-up time of function replicas. This method, based on the CRIU process checkpoint/restore Linux tool, achieves up to a 71% improvement in start-up time for certain functions \[[17](http://arxiv.org/abs/1903.12221)\].

### <a id='category-serverless-computing-cold-start-solutions'></a>Serverless Computing Cold Start Solutions: 9 papers found.
The category "Serverless Computing Cold Start Solutions" explores various strategies to mitigate the cold start problem, a critical challenge in serverless computing that causes delays in function execution due to the lack of pre-initialized runtime environments \[[1](https://www.semanticscholar.org/paper/d911b03bfda4fc6fc92f8080bb81b3a967d6a9e7)\]. Several approaches have been proposed to address this issue. For instance, Catalyzer introduces a sandbox system that restores function instances from checkpoint images, bypassing the need for initialization and achieving sub-millisecond startup latency \[[3](https://www.semanticscholar.org/paper/f14446970a5ed7145a6d350e1aff07ca203cece8)\]. Similarly, the Adaptive Warm-Up Strategy (AWUS) predicts function invocation times and pre-warms functions to reduce cold start latency, while the Adaptive Container Pool Scaling Strategy (ACPSS) dynamically adjusts container pools to minimize resource waste \[[5](https://www.semanticscholar.org/paper/81b8db7a20f1aa859143c716b38a1443e3eca9a0)\]. Additionally, WLEC, a container management architecture, employs an optimized S2LRU structure to reduce cold start duration and memory consumption \[[6](https://www.semanticscholar.org/paper/96d4fea8d034a7605af936f2e2b6a44becdf6585)\]. The use of snapshot-based restoration, as demonstrated in a prototype leveraging the CRIU tool, also significantly improves startup times by up to 71% for certain functions \[[12](https://www.semanticscholar.org/paper/ab1c0062964a2df3d7f8d11da4a774530286b801)\]. Furthermore, Xanadu addresses cascading cold starts in workflows by employing speculative and just-in-time resource provisioning, effectively eliminating cascading delays \[[14](https://www.semanticscholar.org/paper/1cd137e77753ee6c51c97c520d64f91d484dbddc)\]. These solutions highlight the diverse methods employed to enhance the performance and responsiveness of serverless platforms by reducing cold start overhead.

### <a id='category-serverless-computing-cold-start-optimization'></a>Serverless Computing Cold Start Optimization: 5 papers found.
Serverless computing has emerged as a promising paradigm for scalable, cost-effective cloud services, but it faces the critical challenge of cold-start latency, which significantly impacts performance \[[1](https://www.semanticscholar.org/paper/d911b03bfda4fc6fc92f8080bb81b3a967d6a9e7)\]. This issue arises when a function's container must be initialized from scratch, leading to delays in execution \[[2](http://arxiv.org/abs/2310.08437)\]. Existing approaches to mitigate cold-start latency include pre-warming containers, caching, and application-level optimizations \[[1](https://www.semanticscholar.org/paper/d911b03bfda4fc6fc92f8080bb81b3a967d6a9e7)\]. However, these methods often rely on static policies or fail to adapt to dynamic workloads, resulting in suboptimal performance \[[2](http://arxiv.org/abs/2310.08437)\]. Recent research has focused on adaptive strategies, such as using machine learning models to predict invocation patterns and pre-warm containers accordingly \[[2](http://arxiv.org/abs/2310.08437)\]. For instance, some studies propose deep neural networks and LSTM models to forecast the optimal idle container window length, balancing resource efficiency and responsiveness \[[2](http://arxiv.org/abs/2310.08437)\]. Others introduce reinforcement learning and long short-term memory (LSTM) models to dynamically adjust container warm-up times based on historical function invocation data \[[3](https://www.semanticscholar.org/paper/f14446970a5ed7145a6d350e1aff07ca203cece8)\]. Additionally, application-level optimizations, such as identifying and loading only essential code, have been explored to reduce initialization overhead \[[5](https://www.semanticscholar.org/paper/81b8db7a20f1aa859143c716b38a1443e3eca9a0)\]. These approaches aim to improve both the speed and efficiency of serverless function execution while maintaining the scale-to-zero feature \[[1](https://www.semanticscholar.org/paper/d911b03bfda4fc6fc92f8080bb81b3a967d6a9e7)\]. Despite these advancements, challenges remain in ensuring consistent performance across varying workloads and minimizing resource consumption \[[4](https://www.semanticscholar.org/paper/b99668ae35c4b6796b827657a318fe4b84a757ff)\].

### <a id='category-others'></a>Others: 3 papers found.
Serverless computing has emerged as a promising paradigm for event-driven applications, offering automatic scaling and efficient resource utilization \[[17](http://arxiv.org/abs/1903.12221)\]. However, it is plagued by the cold start problem, where the platform takes time to set up the runtime environment and dependencies before serving requests \[[6](https://www.semanticscholar.org/paper/96d4fea8d034a7605af936f2e2b6a44becdf6585)\]. This issue is exacerbated by the need for lightweight function containers and the microservices model, which are essential for applications like IoT, edge computing, and stream processing \[[1](https://www.semanticscholar.org/paper/d911b03bfda4fc6fc92f8080bb81b3a967d6a9e7)\]. Existing approaches to mitigate cold starts include reducing startup time or minimizing the frequency of cold starts \[[6](https://www.semanticscholar.org/paper/96d4fea8d034a7605af936f2e2b6a44becdf6585)\]. For instance, maintaining a pool of warm containers has been shown to significantly reduce P99 response time \[[17](http://arxiv.org/abs/1903.12221)\]. Additionally, recent research has focused on leveraging AI and reinforcement learning to predict and manage cold start latency, such as the ATOM framework, which uses deep reinforcement learning to forecast cold start events and optimize resource management \[[13](https://www.semanticscholar.org/paper/891a89fad669dc7d107ad2d5a047b288b5cc9832)\]. These efforts highlight the ongoing challenge of balancing performance and resource efficiency in serverless environments.
