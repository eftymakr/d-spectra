## Related Works

Generative retrieval has emerged as a promising paradigm in information retrieval, shifting from traditional index-based methods to end-to-end neural models that directly generate document identifiers \[[12](http://arxiv.org/abs/2202.06991)\]. This approach leverages large language models to encode the entire corpus within a single Transformer, eliminating the need for external indexes \[[12](http://arxiv.org/abs/2202.06991)\]. Prior work has explored various methods to enable this, including the use of n-grams as document identifiers \[[1](http://arxiv.org/abs/2204.10628)\], the development of single-step generative retrieval models \[[2](http://arxiv.org/abs/2208.07652)\], and the use of autoregressive decoding to generate document identifiers \[[3](http://arxiv.org/abs/2304.04171)\]. These models aim to improve efficiency and integration with generative models, while also enabling better generalization across different corpora \[[1](http://arxiv.org/abs/2204.10628)\].

The concept of using autoregressive models for retrieval has been explored in several works. For instance, SEAL proposes using all n-grams in a passage as potential identifiers and maps them to full passages via an efficient data structure \[[1](http://arxiv.org/abs/2204.10628)\]. Similarly, GenRet introduces a tokenization learning method to generate semantic docids through a discrete auto-encoding approach \[[3](http://arxiv.org/abs/2304.04171)\]. These methods highlight the importance of defining meaningful document identifiers that capture semantic information, which is critical for effective retrieval \[[3](http://arxiv.org/abs/2304.04171)\].

Another key contribution in this area is the development of the Differentiable Search Index (DSI), which uses a single transformer model to perform both indexing and retrieval \[[12](http://arxiv.org/abs/2202.06991)\]. DSI-QG, an extension of this approach, addresses the issue of data distribution mismatch by generating relevant queries during indexing, which are then used to connect document identifiers to queries during retrieval \[[5](http://arxiv.org/abs/2206.10128)\]. This helps mitigate the mismatch between the indexing and retrieval phases, improving performance in both mono-lingual and cross-lingual settings \[[5](http://arxiv.org/abs/2206.10128)\].

The effectiveness of generative retrieval has also been evaluated on a variety of datasets, including the KILT benchmark, where it has shown significant improvements over traditional methods \[[2](http://arxiv.org/abs/2208.07652)\]. Moreover, the scalability of generative retrieval has been studied, revealing challenges in scaling to large corpora with millions of passages \[[10](http://arxiv.org/abs/2305.11841)\]. These studies highlight the importance of synthetic queries during indexing and the limitations of naive parameter scaling \[[10](http://arxiv.org/abs/2305.11841)\].

In addition to retrieval, generative retrieval has been applied to entity retrieval tasks, where models generate entity names in an autoregressive fashion \[[9](http://arxiv.org/abs/2010.00904)\]. This approach enables better handling of context and entity affinity, reducing memory footprint and improving performance \[[9](http://arxiv.org/abs/2010.00904)\]. The use of prompt learning to unify different retrieval tasks has also been explored, leading to the development of a unified generative retriever (UGR) that can handle various levels of semantic granularity

### <a id='category-document-identifier-generation'></a>Document Identifier Generation: 4 papers found.
Document Identifier Generation has seen significant advancements in recent years, with several approaches aiming to improve the efficiency and effectiveness of generative retrieval systems. Traditional methods rely on index-retrieve paradigms, which are challenging to optimize end-to-end \[[3](http://arxiv.org/abs/2304.04171)\]. In contrast, generative retrieval directly predicts document identifiers (docids) using parametric models, enabling seamless integration with large language models \[[7](http://arxiv.org/abs/2308.14968)\]. However, defining these identifiers remains an open challenge, as fixed rule-based methods such as using document titles or BERT embeddings often fail to capture complete semantic information \[[3](http://arxiv.org/abs/2304.04171)\]. To address this, GenRet introduces a discrete auto-encoding approach to learn semantic docids through tokenization and reconstruction models \[[3](http://arxiv.org/abs/2304.04171)\]. Similarly, the Neural Corpus Indexer (NCI) proposes a sequence-to-sequence network that generates docids directly for queries, incorporating a prefix-aware weight-adaptive decoder to enhance recall performance \[[4](http://arxiv.org/abs/2206.02743)\]. Additionally, the SEAL model explores using all ngrams in a passage as identifiers, allowing autoregressive models to generate and score distinctive ngrams for retrieval \[[1](http://arxiv.org/abs/2204.10628)\]. These methods highlight the ongoing efforts to improve the generalization and efficiency of document identifier generation in generative retrieval systems.

The presence of these queries at indexing allows the DSI models to connect a document identifier to a set of queries, hence mitigating data distribution mismatches present between the indexing and the retrieval phases. Empirical results on popular mono-lingual and cross-lingual passage retrieval datasets show that DSI-QG significantly outperforms the original DSI model.»

	Document 1: [Snippet]: «Entities are at the center of how we represent and aggregate knowledge. For instance, Encyclopedias such as Wikipedia are structured by entities (e.g., one per article). The ability to retrieve such entities given a query is fundamental for knowledge-intensive tasks such as entity linking and open-domain question answering. One way to understand current approaches is as classifiers among atomic labels, one for each entity. We show the efficacy of the approach with more than 20 datasets on entity disambiguation, end-to-end entity linking and document retrieval tasks, achieving new SOTA, or very competitive results while using a tiny fraction of the memory of competing systems. Finally, we demonstrate that new entities can be added by simply specifying their unambiguous name.»
