## Related Works

Semi-supervised learning (SSL) has emerged as a powerful paradigm for improving model performance when labeled data is scarce. Traditional SSL methods assume that labeled and unlabeled data share the same class distribution \[[1](https://www.semanticscholar.org/paper/f3df804a7eef204b0c4fc4b81166dec9b4abc073)\]. However, this assumption is often violated in practice, as unlabeled data may contain out-of-distribution (OOD) samples, i.e., outliers \[[2](http://arxiv.org/abs/2007.11330)\]. These outliers are typically treated as noise, leading to significant performance degradation \[[3](http://arxiv.org/abs/2105.14148)\]. To address this limitation, numerous approaches have been proposed to handle open-set SSL, where the presence of OOD samples is explicitly considered \[[4](http://arxiv.org/abs/2001.07685)\].

One line of work focuses on filtering OOD samples before applying SSL. For instance, \[[5](http://arxiv.org/abs/2108.05617)\] introduces a method that detects OOD samples in unlabeled data by estimating the probability of a sample belonging to OOD. This approach uses a joint optimization framework that alternates between updating network parameters and OOD scores. Similarly, \[[6](https://www.semanticscholar.org/paper/9e4376e0572de32236e408469ffb2173d89eaab5)\] proposes a multi-task curriculum learning framework that detects OOD samples and trains a classifier on in-distribution (ID) data simultaneously. Another approach, \[[7](http://arxiv.org/abs/1905.02249)\], leverages cross-modal matching to detect OOD samples by training the network to predict whether a data sample matches an assigned one-hot class label, generating a compatible feature space aligned with the core classification task.

Another line of work focuses on improving SSL performance by incorporating OOD data in a controlled manner. \[[8](http://arxiv.org/abs/2107.08943)\] proposes OpenMatch, which unifies FixMatch with novelty detection based on one-vs-all (OVA) classifiers. The OVA classifier outputs confidence scores for inlier detection, providing a threshold to detect outliers. Additionally, \[[9](http://arxiv.org/abs/2308.13168)\] introduces an open-set soft-consistency regularization loss that enhances the smoothness of the OVA classifier with respect to input transformations, improving outlier detection. \[[10](http://arxiv.org/abs/2102.03526)\] further explores the use of OOD data by proposing a warm-up training phase that leverages all unlabeled data, including both ID and OOD samples, to learn more discriminative features.

To address the issue of unreliable outlier detection when labeled data is scarce, \[[11](http://arxiv.org/abs/2205.07246)\] introduces IOMatch, a framework that jointly utilizes inliers and outliers. It employs a multi-binary classifier in combination with a standard closed-set classifier to produce unified open-set classification targets, treating all outliers as a single new class. This approach allows the model to optimize an open-set classifier using all unlabeled samples, including both inliers and outliers.

### <a id='category-dynamic-confidence-thresholding'></a>Dynamic Confidence Thresholding: 4 papers found.
Dynamic confidence thresholding has been a focal point in improving semi-supervised learning (SSL) performance by addressing the limitations of fixed or pre-defined thresholds. Existing methods, such as FixMatch \[[4](http://arxiv.org/abs/2001.07685)\], often use a constant threshold across all classes, which may not account for varying learning dynamics and class-specific difficulties \[[17](http://arxiv.org/abs/2110.08263)\]. This rigidity can lead to suboptimal pseudo-label selection and hinder performance, particularly when labeled data is scarce \[[11](http://arxiv.org/abs/2205.07246)\]. To overcome these challenges, researchers have proposed adaptive thresholding strategies. For instance, FreeMatch \[[11](http://arxiv.org/abs/2205.07246)\] introduces a self-adaptive mechanism to adjust the confidence threshold based on the model's learning status, enhancing convergence and performance. Similarly, Dash \[[13](http://arxiv.org/abs/2109.00650)\] dynamically adjusts thresholds during training to ensure only informative pseudo-labels are used, improving robustness. Additionally, FlexMatch \[[17](http://arxiv.org/abs/2110.08263)\] extends FixMatch by introducing class-specific thresholds, allowing for more flexible and effective utilization of unlabeled data. These approaches highlight the importance of dynamic thresholding in improving SSL performance, especially in scenarios with limited labeled data or imbalanced class distributions. The evolution of these methods underscores a growing emphasis on adaptive strategies to better leverage unlabeled data while mitigating the risks of noisy or outlier-laden samples \[[4](http://arxiv.org/abs/2001.07685)\]\[[11](http://arxiv.org/abs/2205.07246)\]\[[13](http://arxiv.org/abs/2109.00650)\]\[[17](http://arxiv.org/abs/2110.08263)\].

### <a id='category-assumptions-of-traditional-ssl'></a>Assumptions of Traditional SSL: 3 papers found.
The category "Assumptions of Traditional SSL" highlights key limitations in conventional semi-supervised learning (SSL) approaches. Traditional SSL methods often assume that labeled and unlabeled data share the same class distribution, which is frequently violated in practice due to the presence of outliers or unknown class data \[[7](http://arxiv.org/abs/1905.02249)\]. These outliers are typically treated as noise, leading to significant performance degradation \[[7](http://arxiv.org/abs/1905.02249)\]. This assumption is also echoed in other works, which emphasize the importance of handling unlabeled data that may not conform to the labeled distribution \[[25](http://arxiv.org/abs/2002.05709)\]. For instance, SimCLR, a contrastive self-supervised learning framework, demonstrates that data augmentation and the design of predictive tasks play a crucial role in learning robust visual representations, even when dealing with unlabeled data \[[25](http://arxiv.org/abs/2002.05709)\]. Similarly, S4L integrates self-supervised learning with semi-supervised learning to improve performance on limited labeled data, showing that combining these paradigms can lead to better results \[[29](http://arxiv.org/abs/1905.03670)\]. These findings underscore the need for more flexible SSL approaches that can handle the complexities of real-world data distributions, such as those involving outliers or unknown classes. The assumption of identical class distribution in traditional SSL is thus a critical point of focus for recent advancements in the field.

### <a id='category-impact-of-outliers-on-ssl-performance'></a>Impact of Outliers on SSL Performance: 2 papers found.
The impact of outliers on semi-supervised learning (SSL) performance has been extensively studied, highlighting the challenges posed by out-of-distribution (OOD) data. Existing methods often treat OOD data as noise, leading to significant performance degradation \[[26](http://arxiv.org/abs/2301.06010)\]. For instance, pseudo-labeling (PL) methods, which generate pseudo-labels for unlabeled data based on model predictions, suffer from imbalanced pseudo-labels when OOD data is present, exacerbating the problem \[[26](http://arxiv.org/abs/2301.06010)\]. Moreover, the presence of OOD data can introduce confirmation bias during the training process, as self-generated pseudo-labels may contain noise, leading to noisier model judgments in real-world applications \[[16](http://arxiv.org/abs/2203.02261)\]. To address these issues, recent approaches have focused on improving pseudo-label quality and enhancing model robustness. One such method is Class-aware Contrastive Semi-Supervised Learning (CCSSL), which separately handles in-distribution and out-of-distribution data through class-wise clustering and image-wise contrastive learning, respectively, to improve generalization \[[16](http://arxiv.org/abs/2203.02261)\]. Another approach, Re-balanced Pseudo-Labeling (RPL), aims to mitigate the imbalance of pseudo-labels by filtering out OOD data and re-balancing high-confidence predictions \[[26](http://arxiv.org/abs/2301.06010)\]. These strategies reflect a growing recognition of the importance of addressing outliers in SSL to achieve better performance in real-world settings.
