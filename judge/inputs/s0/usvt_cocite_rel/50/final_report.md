This limitation has motivated researchers to explore novel approaches to enhance the management and utilization of ML resources.

Several studies have examined the characteristics and usage patterns of ML models on Hugging Face. The category "Open Source ML Resource Platforms" encompasses several studies focused on the Hugging Face ecosystem, highlighting its role in the development, sharing, and analysis of machine learning models. Research has shown that Hugging Face serves as a critical platform for ML model development, hosting over 380,000 models and facilitating community engagement, model evolution, and maintenance \[[2](http://arxiv.org/abs/2311.13380)\]. However, existing platforms like Hugging Face lack structured representations, which limits advanced queries and analyses such as tracing model evolution and recommending relevant datasets \[[1](http://arxiv.org/abs/2305.11164)\]. To address this gap, HuggingKG was introduced as the first large-scale knowledge graph built from the Hugging Face community, capturing domain-specific relations and textual attributes to enhance resource management \[[1](http://arxiv.org/abs/2305.11164)\]. Additionally, studies have explored the carbon footprint of ML models on Hugging Face, revealing that while there is a slight decrease in reported emissions over time, the majority of models still lack comprehensive carbon reporting \[[1](http://arxiv.org/abs/2305.11164)\]. These findings underscore the need for improved transparency and sustainability in model development and resource sharing within the Hugging Face community \[[1](http://arxiv.org/abs/2305.11164)\]. Furthermore, efforts have been made to integrate Hugging Face with other tools, such as Pyserini, to facilitate qualitative analysis of large-scale textual corpora and enhance the usability of the platform for researchers \[[14](http://arxiv.org/abs/2306.01481)\]. Overall, these studies highlight the growing importance of Hugging Face as a central hub for ML resources and the ongoing efforts to improve its functionality and sustainability \[[1](http://arxiv.org/abs/2305.11164)\]\[[2](http://arxiv.org/abs/2311.13380)\]\[[14](http://arxiv.org/abs/2306.01481)\].

Overall, these works collectively emphasize the need for more rigorous documentation practices to support the growing demands of machine learning research.

### <a id='category-model-reuse-challenges'></a>Model Reuse Challenges: 5 papers found.
The category "Model Reuse Challenges" highlights several key issues faced by practitioners when reusing pre-trained models (PTMs). These challenges include the lack of essential attributes such as provenance, reproducibility, and portability, which are critical for effective model reuse \[[1](http://arxiv.org/abs/2305.11164)\]. Additionally, discrepancies between claimed and actual model performance, as well as potential risks associated with model usage, pose significant barriers to reliable PTM adoption \[[1](http://arxiv.org/abs/2305.11164)\]. These challenges are further compounded by limited guidance for novice users, difficulties in understanding model outputs, and a lack of comprehensive documentation, which hinder both model comprehension and selection \[[2](http://arxiv.org/abs/2311.13380)\]. The complexity of model ecosystems, such as those involving large language models for code (LLM4Code), adds another layer of difficulty, as models often depend on and interact with each other, requiring detailed documentation and clear licensing practices \[[3](http://arxiv.org/abs/2401.13822)\]. Furthermore, the rapid growth of these ecosystems has led to a need for automated tools to measure model attributes and detect potential issues, as well as infrastructure improvements for standardized model registries \[[1](http://arxiv.org/abs/2305.11164)\]. Overall, these challenges underscore the need for more robust frameworks and tools to support the reuse of PTMs in both traditional and emerging AI domains \[[1](http://arxiv.org/abs/2305.11164)\]\[[2](http://arxiv.org/abs/2311.13380)\]\[[3](http://arxiv.org/abs/2401.13822)\].

### <a id='category-model-documentation-and-versioning'></a>Model Documentation and Versioning: 2 papers found.
The category "Model Documentation and Versioning" highlights critical challenges and proposed solutions in documenting and versioning machine learning models. Existing practices on platforms like Hugging Face lack standardized naming conventions and transparent documentation, leading to inconsistencies in model release practices \[[13](http://arxiv.org/abs/2409.10472)\]. This issue is compounded by the fact that many model releases do not accurately reflect changes in model weights or training data, making it difficult to trace model evolution or ensure reproducibility \[[13](http://arxiv.org/abs/2409.10472)\]. To address these gaps, researchers have proposed frameworks such as model cards, which provide structured documentation detailing model performance across diverse groups, intended use cases, and evaluation procedures \[[11](http://arxiv.org/abs/1810.03993)\]. These model cards aim to enhance transparency and accountability in AI systems, particularly in human-centered applications like computer vision and natural language processing \[[11](http://arxiv.org/abs/1810.03993)\]. Additionally, the need for semantic versioning has been emphasized, as current versioning practices often fail to capture meaningful changes, leading to confusion and reduced trust in model reliability \[[13](http://arxiv.org/abs/2409.10472)\]. These efforts underscore a growing recognition of the importance of rigorous documentation and versioning in ensuring the responsible development and deployment of machine learning models.
