## Related Works

Cold start latency remains a critical challenge in serverless computing, impacting end-to-end performance and resource utilization \[[1](http://arxiv.org/abs/2406.11734)\]. Several studies have explored techniques to mitigate this issue, focusing on pre-warming, adaptive container management, and workload prediction. For instance, \[[1](http://arxiv.org/abs/2406.11734)\] introduces LibProf, a Python profiler that identifies inefficient library initializations through dynamic program analysis, achieving up to 2.26x speedup in cold-start execution time. This work highlights the importance of analyzing runtime behavior to optimize library usage, a concept closely aligned with the profile-guided optimization approach of SLIMSTART \[[14](http://arxiv.org/abs/2206.15176)\].

Pre-warming strategies have been widely adopted to reduce cold start latency by keeping containers warm in anticipation of incoming requests \[[14](http://arxiv.org/abs/2206.15176)\]. However, static pre-warming approaches often lead to resource wastage, especially when the workload is unpredictable \[[14](http://arxiv.org/abs/2206.15176)\]. To address this, \[[14](http://arxiv.org/abs/2206.15176)\] proposes a time series forecasting model using SARIMA to predict incoming request times and dynamically adjust the number of containers, minimizing resource consumption while reducing cold start latency. This method is similar to the adaptive container scaling strategies used in SLIMSTART \[[14](http://arxiv.org/abs/2206.15176)\].

Reinforcement learning has also been leveraged to optimize cold start frequency by learning function invocation patterns and pre-warming containers accordingly \[[14](http://arxiv.org/abs/2206.15176)\]. \[[14](http://arxiv.org/abs/2206.15176)\] introduces a two-layer adaptive approach that combines reinforcement learning with LSTM to predict future function invocations, improving execution performance on prewarmed containers by 22.65% \[[14](http://arxiv.org/abs/2206.15176)\]. This aligns with the adaptive warm-up strategies used in SLIMSTART, which dynamically adjust warm-up based on runtime data \[[14](http://arxiv.org/abs/2206.15176)\].

Several works have focused on reducing cold start latency through AI-driven resource management. \[[14](http://arxiv.org/abs/2206.15176)\] presents ATOM, an AI-powered framework that predicts cold start events using deep reinforcement learning, achieving better prediction accuracy than traditional warm-start approaches \[[14](http://arxiv.org/abs/2206.15176)\]. Similarly, \[[14](http://arxiv.org/abs/2206.15176)\] introduces SPES, a scheduler that optimizes function provision by categorizing functions based on invocation patterns, reducing cold start rates by 49.77% \[[14](http://arxiv.org/abs/2206.15176)\]. These approaches emphasize the importance of predictive models and dynamic resource allocation, which are also core components of SLIMSTART \[[14](http://arxiv.org/abs/2206.15176)\].

In addition to pre-warming and scheduling, some studies have focused on optimizing library initialization and reducing unnecessary overhead. \[[1](http://arxiv.org/abs/2406.11734)\] highlights that many serverless functions initialize rarely used libraries, contributing to cold start latency. While static analysis can identify unreachable libraries, it fails to address workload-dependent inefficiencies \[[1](http://arxiv.org/abs/2406.11734)\].
