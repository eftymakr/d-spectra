## Related Works

Federated Learning (FL) has emerged as a promising paradigm for collaborative machine learning while preserving data privacy by keeping raw data on client devices \[[15](http://arxiv.org/abs/2210.04505)\]. However, FL faces significant challenges due to data heterogeneity, which includes both statistical and system-level variations across clients \[[15](http://arxiv.org/abs/2210.04505)\]. This heterogeneity can lead to slow convergence and poor generalization of the global model \[[1](http://arxiv.org/abs/2504.01921)\]. To address these issues, various client selection strategies have been proposed to improve convergence and performance in FL settings \[[13](http://arxiv.org/abs/2010.01243)\]. For instance, Power-of-Choice selection strategies have been introduced to bias client selection toward those with higher local loss, leading to faster convergence \[[13](http://arxiv.org/abs/2010.01243)\]. Similarly, HiCS-FL leverages statistical heterogeneity to cluster clients and improve convergence efficiency \[[3](http://arxiv.org/abs/2310.00198)\]. 

Active learning (AL) has also been explored in the context of FL to reduce annotation costs by selecting the most informative unlabeled samples \[[18](https://www.semanticscholar.org/paper/6b0d47501ad9efd386837959ea31cd3f58199797)\]. However, existing methods often fail to account for the heterogeneity of data distributions and the associated fluctuations in model parameters, which can degrade model accuracy \[[1](http://arxiv.org/abs/2504.01921)\]. This limitation is particularly pronounced in federated active learning (FAL), where collaborative data selection and model training are required while preserving data privacy \[[1](http://arxiv.org/abs/2504.01921)\]. 

To address these challenges, recent works have focused on improving client selection and model personalization in FL. For example, FedDiverse introduces a client selection algorithm that promotes collaboration between clients with complementary data distributions, enhancing performance while maintaining low computational overhead \[[2](http://arxiv.org/abs/2504.11216)\]. Similarly, WAFFLE uses weighted averaging based on client updates to personalize models, achieving faster convergence and improved accuracy \[[12](http://arxiv.org/abs/2110.06978)\]. 

In addition, methods such as FLAME have been proposed to handle both statistical and system heterogeneity in multi-device environments, improving inference consistency across devices \[[4](http://arxiv.org/abs/2202.08922)\]. These approaches highlight the importance of addressing both data and system-level heterogeneity in FL systems. 

Furthermore, methods like HHHFL have been developed to handle heterogeneous EEG data in FL settings, ensuring privacy while improving model performance \[[14](http://arxiv.org/abs/1909.05784)\]. These works demonstrate the need for robust client selection and model personalization strategies in FL, especially when dealing with non-IID data and heterogeneous client resources \[[15](http://arxiv.org/abs/2210.04505)\].

In the context of unlabeled data, some works have explored clustering-based labeling methods to enable federated learning without requiring explicit labels \[[18](https://www.semanticscholar.org/paper/6b0d47501ad9efd386837959ea31cd3f58199797)\]. These methods are particularly useful in IoT environments where labeling is impractical.

### <a id='category-client-selection-strategies'></a>Client Selection Strategies: 6 papers found.
Client selection strategies in federated learning (FL) have been extensively studied to address the challenges posed by data and system heterogeneity. Existing methods often focus on mitigating either data heterogeneity or communication latency individually, but few address both simultaneously \[[1](http://arxiv.org/abs/2504.01921)\]. For instance, some approaches rely on uniform random sampling, which can lead to slow convergence due to high system heterogeneity \[[4](http://arxiv.org/abs/2202.08922)\]. Others attempt to improve convergence by selecting clients with more informative updates, but these methods often introduce significant computational overhead or perform poorly under varying heterogeneity conditions \[[2](http://arxiv.org/abs/2504.11216)\]. Recent work has proposed more sophisticated strategies, such as HiCS-FL, which clusters clients based on statistical heterogeneity to improve convergence speed and reduce computational costs \[[2](http://arxiv.org/abs/2504.11216)\]. Similarly, FedCS introduces a new FL protocol that actively manages clients based on their resource constraints, enabling more efficient aggregation of model updates \[[3](http://arxiv.org/abs/2310.00198)\]. Additionally, Power-of-Choice is a framework that biases client selection toward those with higher local loss, leading to faster error convergence and better test accuracy \[[5](http://arxiv.org/abs/2206.10032)\]. These approaches highlight the ongoing efforts to design adaptive and efficient client selection mechanisms that can handle the complexities of real-world FL systems.

### <a id='category-data-heterogeneity-in-fl'></a>Data Heterogeneity in FL: 7 papers found.
Data heterogeneity in Federated Learning (FL) is a critical challenge that affects model performance, convergence, and generalization. It arises from non-identically distributed (non-IID) data across clients, leading to statistical heterogeneity, such as class imbalance, attribute imbalance, and spurious correlations \[[1](http://arxiv.org/abs/2504.01921)\]. This issue is further compounded by system-level heterogeneity, including varying computational capabilities and communication constraints \[[3](http://arxiv.org/abs/2310.00198)\]. To address these challenges, several approaches have been proposed, such as FedDiverse, which introduces a client selection algorithm to promote collaboration between clients with complementary data distributions \[[1](http://arxiv.org/abs/2504.01921)\]. Similarly, FLAME focuses on user-centered FL training in multi-device environments, incorporating device selection strategies and model personalization to handle both statistical and system heterogeneity \[[2](http://arxiv.org/abs/2504.11216)\]. Additionally, RHFL tackles the problem of noisy and heterogeneous clients by introducing a robust framework that handles label noise and client confidence re-weighting \[[4](http://arxiv.org/abs/2202.08922)\]. In contrast, Hetero-SSFL enables self-supervised learning across heterogeneous clients without requiring labeled data, leveraging alignment of lower-dimensional representations \[[5](http://arxiv.org/abs/2206.10032)\]. These methods highlight the need for adaptive strategies that can effectively manage data and system heterogeneity while maintaining model performance and efficiency \[[6](http://arxiv.org/abs/2011.06393)\].

### <a id='category-model-personalization-techniques'></a>Model Personalization Techniques: 3 papers found.
Model personalization techniques in federated learning (FL) have been extensively explored to address the challenges posed by heterogeneous data distributions across clients. Researchers have proposed methods that allow for both global model aggregation and client-specific parameter adaptation. For instance, one approach introduces a novel method that aggregates generic model parameters on the server while maintaining task-specific parameters on each client, enabling better performance in scenarios with non-i.i.d data and disjoint classes \[[1](http://arxiv.org/abs/2504.01921)\]. Another study introduces WAFFLE, a personalized collaborative machine learning algorithm that leverages stochastic control variates to improve convergence by weighting client contributions based on their Euclidean distance from the global model \[[2](http://arxiv.org/abs/2504.11216)\]. Additionally, there is a growing interest in connecting FL with meta-learning frameworks, such as Model Agnostic Meta Learning (MAML), where FL can be interpreted as a meta-learning problem, allowing for more effective personalization of models across diverse client data \[[3](http://arxiv.org/abs/2310.00198)\]. These approaches highlight the importance of balancing global model consistency with local adaptation to achieve higher accuracy and better personalization in FL settings.

### <a id='category-handling-non-iid-data'></a>Handling Non-IID Data: 1 papers found.
Context: 
	Document 1: [_citation_number]: «19»
[Snippet]: «Federated learning (FL) has recently emerged as a popular privacy-preserving collaborative learning paradigm. However, it suffers from the non-independent and identically distributed (non-IID) data among clients. In this paper, we propose a novel framework, named Synthetic Data Aided Federated Learning (SDA-FL), to resolve this non-IID challenge by sharing synthetic data. Specifically, each client pretrains a local generative adversarial network (GAN) to generate differentially private synthetic data, which are uploaded to the parameter server (PS) to construct a global shared synthetic dataset. To generate confident pseudo labels for the synthetic dataset, we also propose an iterative pseudo labeling mechanism performed by the PS. A combination of the local private dataset and synthetic dataset with confident pseudo labels leads to nearly identical data distributions among clients, which improves the consistency among local models and benefits the global aggregation. Extensive experiments evidence that the proposed framework outperforms the baseline methods by a large margin in several benchmark datasets under both the supervised and semi-supervised settings.»
