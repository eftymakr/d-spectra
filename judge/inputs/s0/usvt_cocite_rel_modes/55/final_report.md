## Related Works

Conversational Recommender Systems (CRSs) have emerged as a promising approach to dynamically capture user preferences through multi-turn interactions. Unlike traditional recommender systems that rely on static models and historical data, CRSs enable systems to actively engage users by asking questions about item attributes and recommending items in real-time \[[1](http://arxiv.org/abs/2002.09102)\]. This interactive approach allows for more accurate and personalized recommendations, but it also introduces significant challenges in understanding user preferences, especially when preferences are multifaceted and complex \[[1](http://arxiv.org/abs/2002.09102)\].

Several works have explored the design and implementation of conversational recommendation frameworks. The Estimation-Action-Reflection (EAR) framework, for instance, introduces a three-stage process to better converse with users: (1) Estimation, which builds predictive models to estimate user preference on both items and item attributes; (2) Action, which learns a dialogue policy to determine whether to ask attributes or recommend items, based on Estimation stage and conversation history; and (3) Reflection, which updates the recommender model when a user rejects the recommendations made by the Action stage \[[2](http://arxiv.org/abs/2007.00194)\]. This framework has been evaluated on two datasets from Yelp and LastFM, showing significant improvements over state-of-the-art methods \[[2](http://arxiv.org/abs/2007.00194)\].

Another notable work is the Conversational Path Reasoning (CPR) framework, which models conversational recommendation as an interactive path reasoning problem on a graph. CPR walks through attribute vertices by following user feedback, utilizing the user preferred attributes in an explicit way. This approach enables the system to prune off many irrelevant candidate attributes, leading to a better chance of hitting user-preferred attributes \[[3](http://arxiv.org/abs/2105.09710)\]. The SCPR instantiation of CPR has been shown to significantly outperform existing methods such as EAR and CRM \[[3](http://arxiv.org/abs/2105.09710)\].

This work develops a dynamic weighted graph-based reinforcement learning method to learn a policy to select the action at each conversation turn, either asking an attribute or recommending items \[[4](https://www.semanticscholar.org/paper/3ae5bef6b0c8317603a2deab2527383580904fd8)\]. ### <a id='category-conversational-recommender-systems'></a>Conversational Recommender Systems: 12 papers found.
Conversational Recommender Systems (CRSs) have emerged as a promising approach to dynamically capture user preferences through multi-turn interactions, enabling more accurate and personalized recommendations \[[1](http://arxiv.org/abs/2002.09102)\]. Traditional recommendation systems often rely on static models that struggle to obtain fine-grained and dynamic user preferences, whereas CRSs leverage natural language dialogues to directly ask users about their preferred item attributes, allowing for more explicit and interactive preference elicitation \[[4](https://www.semanticscholar.org/paper/3ae5bef6b0c8317603a2deab2527383580904fd8)\]. This shift has led to the development of various frameworks, such as the Estimation-Action-Reflection (EAR) framework, which integrates predictive modeling, dialogue policy learning, and model adaptation based on user feedback \[[1](http://arxiv.org/abs/2002.09102)\]. Similarly, the Conversational Path Reasoning (CPR) framework models conversational recommendation as an interactive path reasoning problem on a graph, enabling more efficient exploration of attribute spaces and better alignment with user preferences \[[2](http://arxiv.org/abs/2007.00194)\]. Additionally, the System Ask -- User Respond (SAUR) paradigm provides a unified framework for conversational search and recommendation, incorporating multi-memory networks to understand user needs through structured question-asking and real-time search \[[3](http://arxiv.org/abs/2105.09710)\]. Furthermore, recent works have focused on integrating dialog systems and recommender systems through deep reinforcement learning, such as the personalized conversational recommendation agent that optimizes a session-based utility function by leveraging both historical and real-time user data \[[5](http://arxiv.org/abs/2101.09459)\]. These approaches highlight the growing interest in conversational recommendation, emphasizing the need for more sophisticated models that can handle multi-turn interactions, adapt to user feedback, and improve recommendation accuracy through continuous dialogue \[[6](http://arxiv.org/abs/1806.03277)\].

[Snippet]: «Conversational recommender systems (CRS) enable the traditional recommender systems to explicitly acquire user preferences towards items and attributes through interactive conversations. Reinforcement learning (RL) is widely adopted to learn conversational recommendation policies to decide what attributes to ask, which items to recommend, and when to ask or recommend, at each conversation turn. However, existing methods mainly target at solving one or two of these three decision-making problems in CRS with separated conversation and recommendation components, which restrict the scalability and generality of CRS and fall short of preserving a stable training procedure. In the light of these challenges, we propose to formulate these three decision-making problems in CRS as a unified policy learning task. In order to systematically integrate conversation and recommendation components, we develop a dynamic weighted graph based RL method to learn a policy to select the action at each conversation turn, either asking an attribute or recommending items. Further, to deal with the sample efficiency issue, we propose two action selection strategies for reducing the candidate action space according to the preference and entropy information. Experimental results on two benchmark CRS datasets and a real-world E-Commerce application show that the proposed method not only significantly outperforms state-of-the-art methods but also enhances the scalability and stability of CRS.»
