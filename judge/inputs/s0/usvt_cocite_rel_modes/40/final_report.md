## Related Works

Zero-Knowledge Proofs (ZKPs) have emerged as a critical cryptographic primitive for privacy-preserving computation, enabling a prover to demonstrate the validity of a statement without revealing additional information \[[5](https://www.semanticscholar.org/paper/9ccf7b6cb32cf89752a35bd910555adac54773e0)\]. Recent advancements have focused on accelerating the computational bottlenecks in ZKP generation, particularly for large-scale applications such as blockchain and machine learning \[[1](https://www.semanticscholar.org/paper/e149d93531d8c07cf43f6cae327a4795144d1304)\]. However, existing solutions face significant limitations, either requiring a trusted setup for each application \[[1](https://www.semanticscholar.org/paper/e149d93531d8c07cf43f6cae327a4795144d1304)\] or generating proofs with higher verification costs \[[1](https://www.semanticscholar.org/paper/e149d93531d8c07cf43f6cae327a4795144d1304)\]. This section reviews prior work on ZKP acceleration and related cryptographic protocols.

Several studies have explored hardware and software accelerations for ZKP protocols. GZKP leverages GPU acceleration to improve the performance of polynomial computations and multi-scalar multiplications (MSMs), achieving up to 48.1× speedup over state-of-the-art systems \[[1](https://www.semanticscholar.org/paper/e149d93531d8c07cf43f6cae327a4795144d1304)\]. Similarly, PipeZK introduces a pipelined architecture with two subsystems to handle large polynomial computations and elliptic curve operations, achieving 10× speedup on cryptographic benchmarks \[[2](https://www.semanticscholar.org/paper/6ee84674b7c426849c3da56cb278c08eb7a903cf)\]. cuZK further improves performance by optimizing the parallelization of MSM and matrix-vector multiplication (MUL) operations, achieving up to 4.86× speedup on Filecoin \[[3](https://www.semanticscholar.org/paper/e4a4608e8e35379e63b9df5bda1b7599ee8ab9ac)\]. These works highlight the importance of optimizing the key primitives in ZKP generation, particularly MSM and NTT, which are computationally intensive.

In the context of machine learning, zero-knowledge proofs have been applied to verify the correctness of decision tree and convolutional neural network (CNN) predictions \[[4](https://www.semanticscholar.org/paper/3becc2935d1f52c82ffd7216c28bc86f5e393208)\]\[[6](https://www.semanticscholar.org/paper/6336149196f02d0eb6c1a89bc6b662e4422bd794)\]. For example, zkCNN introduces a novel sumcheck protocol to efficiently prove CNN predictions, achieving 1264× speedup over existing schemes \[[6](https://www.semanticscholar.org/paper/6336149196f02d0eb6c1a89bc6b662e4422bd794)\]. These approaches demonstrate the potential of ZKPs in ensuring the integrity of machine learning models without exposing sensitive information about the model itself.

Recent hardware accelerators have also been proposed to address the computational overhead of ZKP protocols. CraterLake is the first FHE accelerator to support unbounded computation on encrypted data, achieving gmean 4,600× speedup over CPU implementations \[[8](https://www.semanticscholar.org/paper/b718a4b59ee6ee21c7c2ee1aa64085231853535e)\]. Similarly, F1 introduces a programmable accelerator for FHE, achieving up to 17,000× speedup over software implementations \[[10](http://arxiv.org/abs/2109.05371)\]. These works emphasize the need for specialized hardware to reduce the overhead of cryptographic computations, particularly for complex applications like deep learning.

Zero-knowledge proof (ZKP) acceleration has seen significant advancements through hardware and software optimizations, particularly in addressing the computational bottlenecks of proof generation. Researchers have focused on accelerating key primitives such as polynomial computations, multi-scalar multiplications, and number-theoretic transforms (NTT), which are critical for the performance of ZKP systems like zkSNARKs \[[1](https://www.semanticscholar.org/paper/e149d93531d8c07cf43f6cae327a4795144d1304)\]. For instance, GZKP leverages GPU acceleration to improve performance by optimizing memory access patterns and eliminating costly external shuffles, achieving up to 48.1× speedup on standard benchmarks \[[1](https://www.semanticscholar.org/paper/e149d93531d8c07cf43f6cae327a4795144d1304)\]. Similarly, PipeZK introduces a pipelined accelerator with two subsystems, one for handling large polynomial computations and another for managing multi-scalar multiplications, achieving 10× speedup on cryptographic benchmarks and 5× on Zcash \[[2](https://www.semanticscholar.org/paper/6ee84674b7c426849c3da56cb278c08eb7a903cf)\]. cuZK further enhances GPU-based ZKP implementations by introducing parallelized multi-scalar multiplication (MSM) algorithms and optimizing data transfer between CPU and GPU, resulting in up to 4.86× speedup on Filecoin \[[3](https://www.semanticscholar.org/paper/e4a4608e8e35379e63b9df5bda1b7599ee8ab9ac)\]. These efforts highlight the growing need for efficient ZKP acceleration to support real-world applications such as blockchain and verifiable machine learning \[[4](https://www.semanticscholar.org/paper/3becc2935d1f52c82ffd7216c28bc86f5e393208)\]. Additionally, SZKP represents a breakthrough by introducing an ASIC-based accelerator that leverages structured dataflows for both NTT and MSM operations, achieving over 400× speedup compared to CPU implementations \[[9](http://arxiv.org/abs/2408.05890)\]. These advancements collectively demonstrate the ongoing research into making ZKP more practical for widespread adoption.

### <a id='category-homomorphicencryptionaccelerators'></a>HomomorphicEncryptionAccelerators: 2 papers found.
The category "HomomorphicEncryptionAccelerators" focuses on hardware solutions designed to improve the performance of Fully Homomorphic Encryption (FHE), which enables secure computation on encrypted data. FHE is inherently computationally intensive, with overheads that can be up to 10,000X higher than unencrypted computation, limiting its practical adoption \[[8](https://www.semanticscholar.org/paper/b718a4b59ee6ee21c7c2ee1aa64085231853535e)\]. Recent accelerators like F1 and CraterLake aim to address these challenges by introducing specialized hardware and architectural innovations. F1, for instance, is a programmable FHE accelerator that uses a wide-vector processor with functional units optimized for FHE primitives such as modular arithmetic and number-theoretic transforms, significantly reducing execution time compared to software implementations \[[10](http://arxiv.org/abs/2109.05371)\]. Similarly, CraterLake introduces a new hardware architecture capable of handling large ciphertexts and complex FHE programs with unbounded multiplicative depth, achieving speedups of up to 4,600X over CPUs and 11.2X over prior accelerators \[[8](https://www.semanticscholar.org/paper/b718a4b59ee6ee21c7c2ee1aa64085231853535e)\]. These advancements highlight the growing focus on minimizing data movement and improving throughput to enable real-time FHE applications, such as private deep learning and secure cloud computing. Both accelerators emphasize the importance of compiler techniques and hardware-software co-design to optimize performance, demonstrating the field's progress toward practical deployment of FHE.
