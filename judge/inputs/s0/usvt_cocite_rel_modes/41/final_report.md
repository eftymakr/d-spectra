## Related Works

Serverless computing has emerged as a transformative paradigm in cloud computing, offering automatic scaling, efficient resource utilization, and cost-effective pricing models \[[16](http://arxiv.org/abs/1911.01296)\]. However, a significant challenge persists in the form of cold-start latency, which introduces delays during the initialization of function containers and negatively impacts end-to-end performance \[[16](http://arxiv.org/abs/1911.01296)\]. Several studies have explored strategies to mitigate this issue, ranging from optimizing container pre-warming to reducing initialization overhead through code-level optimizations.

Early work on cold starts focused on reducing the time required to launch new function instances. For instance, the *Adaptive Warm-Up Strategy (AWUS)* \[[3](https://www.semanticscholar.org/paper/81b8db7a20f1aa859143c716b38a1443e3eca9a0)\] predicts function invocation times and pre-warms containers to reduce cold start latency. Similarly, *Adaptive Container Pool Scaling Strategy (ACPSS)* \[[3](https://www.semanticscholar.org/paper/81b8db7a20f1aa859143c716b38a1443e3eca9a0)\] dynamically adjusts container pool capacity to minimize resource waste. These approaches aim to balance latency reduction with resource efficiency, but they often rely on static or fixed policies that may not adapt well to varying workloads.

More recent approaches leverage machine learning and reinforcement learning to better predict and manage cold starts. *WLEC* \[[10](https://www.semanticscholar.org/paper/fde534d033dea54e1b9066bad32d7330febe54f3)\] introduces a container management architecture that uses a modified S2LRU structure to minimize cold start time, achieving up to 31% average reduction in cold start duration. *FaaSLight* \[[6](http://arxiv.org/abs/2207.08175)\] focuses on application-level optimizations, such as loading only necessary code, to reduce cold-start latency by up to 78.95%. This approach is platform- and language-agnostic, making it broadly applicable to different serverless environments.

Another line of research explores the use of snapshots and prebaking techniques to accelerate function startup. *Prebaking Functions to Warm the Serverless Cold Start* \[[9](https://www.semanticscholar.org/paper/ab1c0062964a2df3d7f8d11da4a774530286b801)\] restores snapshots from previously executed function processes, improving startup times by up to 71% for certain workloads. This technique, based on the CRIU tool, demonstrates the potential of state restoration to reduce cold start overhead.

Additionally, *FaasCache* \[[14](https://www.semanticscholar.org/paper/3c05fec4087d94c61233a482e59b613388b2c3ae)\] introduces a caching-inspired keep-alive policy that keeps functions warm based on their usage patterns, reducing cold-start overhead by more than 3× compared to current approaches. This method aligns with the idea of maintaining function instances in memory to avoid the latency of reinitialization.

The category "Serverless Computing Optimization" encompasses a range of research efforts aimed at addressing the cold start problem and improving the performance of serverless computing platforms. Cold start latency, which occurs when a function is invoked and no pre-initialized container is available, has been a significant barrier to the adoption of serverless computing \[[2](https://www.semanticscholar.org/paper/d911b03bfda4fc6fc92f8080bb81b3a967d6a9e7)\]. Various approaches have been proposed to mitigate this issue, including the use of checkpointing and snapshot restoration techniques to reduce startup time \[[6](http://arxiv.org/abs/2207.08175)\]. For instance, Catalyzer restores a function instance from a checkpoint image, bypassing the need for full initialization and achieving sub-millisecond latency \[[1](https://www.semanticscholar.org/paper/f14446970a5ed7145a6d350e1aff07ca203cece8)\]. Similarly, a prototype based on the CRIU tool demonstrated a 40% to 71% reduction in startup time by restoring snapshots of previously executed functions \[[9](https://www.semanticscholar.org/paper/ab1c0062964a2df3d7f8d11da4a774530286b801)\]. Additionally, adaptive strategies such as the Adaptive Warm-Up Strategy (AWUS) and Adaptive Container Pool Scaling Strategy (ACPSS) have been introduced to predict function invocation times and dynamically manage container resources, thereby reducing cold start latency and resource waste \[[3](https://www.semanticscholar.org/paper/81b8db7a20f1aa859143c716b38a1443e3eca9a0)\]. Furthermore, the use of workflow-aware optimizations, such as speculative and just-in-time provisioning, has been explored to address cascading cold starts in function chains \[[13](https://www.semanticscholar.org/paper/1cd137e77753ee6c51c97c520d64f91d484dbddc)\]. These approaches collectively highlight the ongoing efforts to enhance the efficiency and responsiveness of serverless computing platforms by reducing cold start overhead while maintaining resource efficiency.

### <a id='category-serverless-computing-cold-start-solutions'></a>Serverless Computing Cold Start Solutions: 6 papers found.
Serverless computing has emerged as a transformative cloud paradigm, offering automatic scaling, cost efficiency, and reduced operational complexity \[[5](https://www.semanticscholar.org/paper/b99668ae35c4b6796b827657a318fe4b84a757ff)\]. However, it faces significant challenges, particularly the cold-start latency issue, which arises from the overhead of initializing functions and their dependencies \[[17](https://www.semanticscholar.org/paper/36338d869d7589b01c3707d70bece8c320e439e2)\]. This problem is exacerbated by the scale-to-zero feature, where idle functions are removed from memory, leading to increased latency upon subsequent invocations \[[12](https://www.semanticscholar.org/paper/27cd21426fe51167dd6ac79d1c83db55a07a2046)\]. Existing solutions, such as keeping containers warm or using fixed idle windows, often result in suboptimal resource usage or fail to adapt to dynamic workloads \[[5](https://www.semanticscholar.org/paper/b99668ae35c4b6796b827657a318fe4b84a757ff)\]. Recent research has focused on adaptive and intelligent approaches to mitigate cold-start delays. For instance, some studies propose using reinforcement learning to identify optimal times to keep containers warm, while others employ LSTM models to predict future function invocations and pre-warm containers accordingly \[[12](https://www.semanticscholar.org/paper/27cd21426fe51167dd6ac79d1c83db55a07a2046)\]. Additionally, caching-inspired keep-alive policies have been introduced to reduce cold-start overhead by maintaining frequently used functions in memory, drawing parallels to caching mechanisms \[[14](https://www.semanticscholar.org/paper/3c05fec4087d94c61233a482e59b613388b2c3ae)\]. Another approach, FaaSLight, focuses on application-level optimizations, such as reducing code loading latency by loading only essential code and separating optional components \[[6](http://arxiv.org/abs/2207.08175)\]. These methods aim to improve performance while maintaining the resource efficiency and scalability that define serverless computing \[[5](https://www.semanticscholar.org/paper/b99668ae35c4b6796b827657a318fe4b84a757ff)\].
