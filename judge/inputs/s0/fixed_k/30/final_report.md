## Related Works

Modern databases often trade strong transaction isolation for weak isolation guarantees to achieve low latency and high throughput \[[1](http://arxiv.org/abs/2504.02344)\]. This trade-off has led to the emergence of various techniques for detecting isolation bugs, particularly through black-box testing \[[2](http://arxiv.org/abs/2303.12606)\]. Black-box testing involves checking whether execution histories of database transactions adhere to a prescribed isolation level \[[2](http://arxiv.org/abs/2303.12606)\]. However, testing large-scale databases remains challenging due to the computational complexity of existing isolation checkers \[[3](http://arxiv.org/abs/2501.14421)\].

Several studies have explored the complexity of isolation testing. It is well known that testing strong isolation levels, such as serializability, is NP-complete \[[4](http://arxiv.org/abs/2103.02830)\]. In contrast, weak isolation levels, such as Read Committed (RC), Read Atomic (RA), and Causal Consistency (CC), have been shown to be testable in polynomial time, which has significantly improved the scalability of testing tools \[[5](http://arxiv.org/abs/2504.01477)\]. However, existing testers often have large polynomial complexities, limiting their applicability to moderate-sized workloads \[[6](http://arxiv.org/abs/2503.06284)\].

Recent work has introduced tools like MTC \[[1](http://arxiv.org/abs/2504.02344)\], which uses Mini-Transactions (MTs) to reduce overhead during history generation and verification. MTC is designed to detect bugs across various isolation levels in production databases while maintaining the effectiveness of randomized testing with general workloads \[[1](http://arxiv.org/abs/2504.02344)\]. Similarly, MonkeyDB \[[7](http://arxiv.org/abs/2206.14602)\] is a mock storage system that supports testing under multiple isolation levels and provides good coverage of weak behaviors. It uses a logical specification of the isolation level to compute possible return values for read operations and returns a value randomly from this set \[[7](http://arxiv.org/abs/2206.14602)\].

Dynamic partial order reduction \[[8](http://arxiv.org/abs/1105.5951)\] has also been proposed for checking correctness against transaction isolation levels. These algorithms work for widely-used weak isolation levels, including RC, CAusal Consistency, Snapshot Isolation, and Serializability. They are complete, sound, and optimal, with polynomial memory consumption \[[8](http://arxiv.org/abs/1105.5951)\]. Furthermore, the work on VerIso \[[9](http://arxiv.org/abs/1911.12711)\] presents a framework for formally verifying isolation guarantees for database transactions, using the theorem prover Isabelle/HOL. This framework has been used to verify the strict two-phase locking concurrency control protocol and identify isolation bugs during protocol design \[[9](http://arxiv.org/abs/1911.12711)\].

The paper also discusses the importance of consistency in modern databases, highlighting the challenges in checking consistency and the need for frameworks like Coo \[[10](http://arxiv.org/abs/1905.13503)\] that use partial order pair (POP) graphs to define consistency completely \[[10](http://arxiv.org/abs/1905.13503)\]. Coo can construct inconsistent test cases based on POP cycles, which are used to check the consistency of databases in accurate, user-friendly, and cost-effective ways \[[10](http://arxiv.org/abs/1905.13503)\].

[Snippet]: «Transactional isolation guarantees are crucial for database correctness. However, recent studies have uncovered numerous isolation bugs in production databases. The common black-box approach to isolation checking stresses databases with large, concurrent, randomized transaction workloads and verifies whether the resulting execution histories satisfy specified isolation levels. For strong isolation levels such as strict serializability, serializability, and snapshot isolation, this approach often incurs significant end-to-end checking overhead during both history generation and verification. We address these inefficiencies through the novel design of Mini-Transactions (MTs). MTs are compact, short transactions that execute much faster than general workloads, reducing overhead during history generation by minimizing database blocking and transaction retries. By leveraging MTs' read-modify-write pattern, we develop highly efficient algorithms to verify strong isolation levels in linear or quadratic time. Despite their simplicity, MTs are semantically rich and effectively capture common isolation anomalies described in the literature. We implement our verification algorithms and an MT workload generator in a tool called MTC. Experimental results show that MTC outperforms state-of-the-art tools in both history generation and verification. Moreover, MTC can detect bugs across various isolation levels in production databases while maintaining the effectiveness of randomized testing with general workloads, making it a cost-effective solution for black-box isolation checking.»

### <a id='category-formal-verification-of-isolation-guarantees'></a>Formal Verification of Isolation Guarantees: 4 papers found.
The category "Formal Verification of Isolation Guarantees" explores the challenges and methodologies for ensuring correctness in database systems, particularly concerning transaction isolation levels. Recent research has focused on formalizing weak isolation levels such as read uncommitted, read committed, and snapshot isolation using separation logic, enabling modular and implementation-independent specifications \[[3](http://arxiv.org/abs/2501.14421)\]. These formalisms are crucial as industrial databases predominantly use weak isolation levels, which are more concurrent but less strict than serializability, and yet they are often implemented without rigorous verification \[[3](http://arxiv.org/abs/2501.14421)\]. The verification of these levels has been demonstrated using frameworks like Rocq, which mechanize proofs in the Iris separation logic framework \[[3](http://arxiv.org/abs/2501.14421)\]. Additionally, frameworks like VerIso, developed within Isabelle/HOL, offer a mathematically rigorous approach to verify isolation guarantees, such as strict serializability, and have been used to identify isolation bugs in protocols like TAPIR \[[6](http://arxiv.org/abs/2503.06284)\]. Furthermore, tools like Coo provide a framework for checking database consistency by modeling transaction conflicts through partial order pair (POP) graphs, enabling the detection of inconsistencies across various isolation levels \[[7](http://arxiv.org/abs/2206.14602)\]. These advancements highlight the growing need for systematic and scalable verification techniques to address the practical challenges of maintaining data consistency in modern, high-concurrency database systems.

### <a id='category-efficiency-and-scalability-of-testing-tools'></a>Efficiency and Scalability of Testing Tools: 4 papers found.
Efficiency and scalability in testing tools for database systems have been a focal point of recent research, with a particular emphasis on improving the performance of isolation checking and transactional consistency verification. Traditional approaches to isolation checking, such as those based on snapshot isolation (SI) and serializability (SER), often require offline processing and full history availability to construct dependency graphs, limiting their applicability to continuous and growing transactional workloads \[[1](http://arxiv.org/abs/2504.02344)\]. To address these limitations, researchers have developed online checking frameworks, such as Chronos and Aion, which enable incremental and real-time validation of transactional histories without requiring the entire history upfront \[[1](http://arxiv.org/abs/2504.02344)\]. These tools demonstrate significant improvements in throughput, with Aion and Aion-SER achieving up to 12K transactions per second \[[1](http://arxiv.org/abs/2504.02344)\]. Additionally, the challenge of performance predictability in transaction processing has been explored, with frameworks like VProfiler identifying key sources of latency variance, such as lock scheduling and centralized logging, and proposing optimizations to reduce such variability \[[2](http://arxiv.org/abs/2303.12606)\]. Furthermore, the scalability of database replication systems has been enhanced through middleware solutions like Hihooi, which provide strong consistency guarantees while maintaining high throughput and workload elasticity \[[3](http://arxiv.org/abs/2501.14421)\]. These advancements collectively highlight the ongoing efforts to improve the efficiency, scalability, and reliability of testing tools in modern database systems.
