## Related Works

Serverless computing has emerged as a transformative paradigm in cloud computing, offering automatic scaling, efficient resource utilization, and cost-effective pricing models \[[1](https://www.semanticscholar.org/paper/d911b03bfda4fc6fc92f8080bb81b3a967d6a9e7)\]. However, the cold-start problem remains a critical challenge, significantly impacting end-to-end performance \[[1](https://www.semanticscholar.org/paper/d911b03bfda4fc6fc92f8080bb81b3a967d6a9e7)\]. Cold starts occur when a function container is provisioned on-demand, leading to delays in execution \[[1](https://www.semanticscholar.org/paper/d911b03bfda4fc6fc92f8080bb81b3a967d6a9e7)\]. This issue has been extensively studied, with various approaches proposed to mitigate its effects.

Several works have focused on reducing cold-start latency through container reuse and caching. For instance, Catalyzer introduces a sandbox system that restores function instances from checkpoint images, eliminating the need for initialization on the critical path \[[2](https://www.semanticscholar.org/paper/f14446970a5ed7145a6d350e1aff07ca203cece8)\]. This approach achieves sub-millisecond startup times and significantly reduces end-to-end latency \[[2](https://www.semanticscholar.org/paper/f14446970a5ed7145a6d350e1aff07ca203cece8)\]. Similarly, Xanadu addresses cascading cold starts in function chains by employing speculative and just-in-time provisioning, effectively eliminating cascading overheads \[[7](https://www.semanticscholar.org/paper/1cd137e77753ee6c51c97c520d64f91d484dbddc)\]. The system demonstrates substantial improvements over existing platforms, reducing platform overheads by up to 18x for short workflows \[[7](https://www.semanticscholar.org/paper/1cd137e77753ee6c51c97c520d64f91d484dbddc)\].

Function caching has also been explored as a means to alleviate cold starts. S-Cache proposes an adaptive caching policy for serverless edge computing, balancing cold-start overheads with resource utilization \[[10](https://www.semanticscholar.org/paper/f85fde870a1eb9c98c62ded89602e2bd1bab6a86)\]. The algorithm reduces both average response time and cold-start frequency by a factor of 3 compared to existing approaches \[[10](https://www.semanticscholar.org/paper/f85fde870a1eb9c98c62ded89602e2bd1bab6a86)\]. FaasCache further extends this idea by introducing a greedy-dual caching policy inspired by caching principles, reducing cold-start overhead by more than 3× compared to current methods \[[15](https://www.semanticscholar.org/paper/3c05fec4087d94c61233a482e59b613388b2c3ae)\]. This approach also enables more efficient resource provisioning, reducing resource requirements by up to 30% \[[15](https://www.semanticscholar.org/paper/3c05fec4087d94c61233a482e59b613388b2c3ae)\].

Prebaking functions to warm the serverless cold start is another promising technique. This method restores snapshots from previously executed function processes, significantly improving startup times \[[16](https://www.semanticscholar.org/paper/ab1c0062964a2df3d7f8d11da4a774530286b801)\]. Experiments show that this technique can reduce startup time by up to 71% for certain workloads \[[16](https://www.semanticscholar.org/paper/ab1c0062964a2df3d7f8d11da4a774530286b801)\]. Similarly, the Adaptive Warm-Up Strategy (AWUS) predicts function invocation times and pre-warms functions to reduce cold start latency \[[12](https://www.semanticscholar.org/paper/81b8db7a20f1aa859143c716b38a1443e3eca9a0)\]. This strategy, when combined with an Adaptive Container Pool Scaling Strategy (ACPSS), effectively minimizes resource waste while maintaining low latency \[[12](https://www.semanticscholar.org/paper/81b8db7a20f1aa859143c716b38a1443e3eca9a0)\].

Function fusion has also been proposed as a way to mitigate cold start latency in workflows. By merging functions, the cold start of the second function can be eliminated, although this may affect parallel execution \[[9](https://www.semanticscholar.org/paper/36338d869d7589b01c3707d70bece8c320e439e2)\].
