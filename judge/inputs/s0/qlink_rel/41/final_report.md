## Related Works

Serverless computing has gained significant traction due to its ability to abstract server management, enabling automatic scaling, efficient resource utilization, and cost-effective pricing models \[[8](http://arxiv.org/abs/1911.01296)\]. However, a critical challenge remains: cold-start latency, which significantly impacts end-to-end performance \[[1](https://www.semanticscholar.org/paper/d911b03bfda4fc6fc92f8080bb81b3a967d6a9e7)\]. This issue arises when a function is invoked and no pre-provisioned "warm" container is available, leading to delays in initializing the runtime environment and dependencies \[[16](http://arxiv.org/abs/1903.12221)\]. Several studies have explored strategies to mitigate this problem.

Early work focused on reducing the duration of cold starts by optimizing the initialization process. For instance, Catalyzer introduces an initialization-less booting mechanism, restoring function instances from checkpoint images to achieve sub-millisecond startup latency \[[2](https://www.semanticscholar.org/paper/f14446970a5ed7145a6d350e1aff07ca203cece8)\]. Similarly, FaaSLight reduces cold-start latency by optimizing code loading through application-level analysis, separating essential code from optional components \[[10](http://arxiv.org/abs/2207.08175)\]. These approaches demonstrate that reducing initialization overhead can significantly improve performance.

Another line of research addresses the frequency of cold starts rather than their duration. Techniques such as adaptive warm-up strategies and container pool management aim to pre-warm resources based on predicted invocation patterns \[[5](https://www.semanticscholar.org/paper/81b8db7a20f1aa859143c716b38a1443e3eca9a0)\]. For example, the Adaptive Function Launching Acceleration approach predicts function invocation times and pre-warms functions, thereby reducing cold starts \[[5](https://www.semanticscholar.org/paper/81b8db7a20f1aa859143c716b38a1443e3eca9a0)\]. Similarly, the WLEC architecture minimizes cold start time by managing containers using an optimized S2LRU++ structure \[[13](https://www.semanticscholar.org/paper/fde534d033dea54e1b9066bad32d7330febe54f3)\]. These methods highlight the importance of proactive resource management in mitigating cold starts.

Recent work has also explored the use of caching and keep-alive policies to maintain warm containers. FaasCache introduces a greedy-dual caching strategy, keeping functions alive based on their usage patterns, which reduces cold-start overhead by more than 3× compared to current approaches \[[15](https://www.semanticscholar.org/paper/3c05fec4087d94c61233a482e59b613388b2c3ae)\]. Additionally, the SAND project focuses on high-performance serverless computing by optimizing resource allocation and reducing latency \[[11](https://www.semanticscholar.org/paper/1a937f78c2d968d134981b5c82adba6495e470e5)\]. These studies underscore the potential of caching and resource management in improving serverless performance.

Furthermore, the use of reinforcement learning to predict function invocation patterns and pre-warm instances has shown promise. A Q-Learning agent can analyze function behavior and prepare instances in advance, reducing cold start frequency \[[7](https://www.semanticscholar.org/paper/96d4fea8d034a7605af936f2e2b6a44becdf6585)\]. This approach aligns with the broader goal of making serverless platforms more responsive to dynamic workloads.

In summary, existing research has explored various strategies to mitigate cold starts, including optimizing initialization, managing resource pools, and leveraging caching and machine learning techniques. While these approaches have shown promising results, further research is needed to address the diverse and evolving nature of serverless work
