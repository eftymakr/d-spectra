Several studies have explored mitigation strategies, focusing on container warming, prediction-based resource allocation, and optimization of function initialization. For instance, LibProf introduces a Python profiler that identifies inefficient library initializations through dynamic program analysis and statistical sampling, leading to up to 2.26x speedup in cold-start execution time \[[1](http://arxiv.org/abs/2406.11734)\]. Similarly, the LCS approach employs an LRU-based warm container selection strategy to reduce cold start occurrences by keeping containers alive for longer periods, achieving a 48% improvement over MRU-based methods \[[15](https://www.semanticscholar.org/paper/d45518ce5741587c4c37ccbc5e74b3fcfd6f80f1)\].

This method leverages a two-layer adaptive system, combining reinforcement learning for optimal warm-up timing and LSTM for future invocation prediction, resulting in a 22.65% improvement in execution invocations on prewarmed containers \[[3](https://www.semanticscholar.org/paper/27cd21426fe51167dd6ac79d1c83db55a07a2046)\]. Additionally, the ATOM framework utilizes deep reinforcement learning to predict cold start events and optimize resource management in edge computing environments, demonstrating superior prediction accuracy compared to traditional warm-start approaches \[[8](https://www.semanticscholar.org/paper/891a89fad669dc7d107ad2d5a047b288b5cc9832)\].

Existing solutions often rely on simplistic strategies for pre-loading or unloading functions, which fail to fully exploit invocation patterns and result in suboptimal trade-offs between latency and resource usage \[[4](https://www.semanticscholar.org/paper/b99668ae35c4b6796b827657a318fe4b84a757ff)\]. Similarly, the Adaptive Warm-Up Strategy (AWUS) and Adaptive Container Pool Scaling Strategy (ACPSS) aim to reduce cold start latency while minimizing resource consumption by dynamically adjusting function warm-up and container pool capacity \[[6](https://www.semanticscholar.org/paper/d911b03bfda4fc6fc92f8080bb81b3a967d6a9e7)\].
