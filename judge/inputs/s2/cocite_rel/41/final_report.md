## Related Works

Serverless computing has emerged as a transformative paradigm in cloud computing, offering automatic scaling, efficient resource utilization, and cost-effective pricing models \[[16](http://arxiv.org/abs/1911.01296)\]. However, a significant challenge persists in the form of cold-start latency, which can severely impact end-to-end performance \[[16](http://arxiv.org/abs/1911.01296)\]. This issue arises due to the overhead of initializing runtime environments and dependencies before a function can execute \[[16](http://arxiv.org/abs/1911.01296)\]. Several studies have explored strategies to mitigate this problem, including pre-warming, function fusion, and caching techniques \[[16](http://arxiv.org/abs/1911.01296)\].

Pre-warming strategies aim to keep function instances ready to execute, thereby reducing cold-start latency. For instance, the LCS approach utilizes an LRU-based warm container selection mechanism to keep containers alive for longer periods, reducing cold-start occurrences by approximately 48% compared to MRU-based methods \[[3](https://www.semanticscholar.org/paper/d45518ce5741587c4c37ccbc5e74b3fcfd6f80f1)\]. Similarly, FaasCache introduces a greedy-dual caching policy inspired by caching principles, significantly reducing cold-start overhead by more than 3× compared to current approaches \[[11](https://www.semanticscholar.org/paper/3c05fec4087d94c61233a482e59b613388b2c3ae)\]. These methods demonstrate that maintaining warm function instances can effectively alleviate cold-start delays.

Function fusion is another approach that reduces cold-start latency by combining multiple functions into a single unit, thereby eliminating the need to initialize separate functions \[[4](https://www.semanticscholar.org/paper/36338d869d7589b01c3707d70bece8c320e439e2)\]. However, this technique may introduce trade-offs, as it can increase workflow response time for parallel functions \[[4](https://www.semanticscholar.org/paper/36338d869d7589b01c3707d70bece8c320e439e2)\]. The study by Xanadu addresses cascading cold starts in function chain deployments by employing speculative and just-in-time provisioning, effectively reducing platform overheads by up to 18× for short workflows \[[10](https://www.semanticscholar.org/paper/1cd137e77753ee6c51c97c520d64f91d484dbddc)\]. This highlights the importance of optimizing resource provisioning to mitigate cold-start cascading effects.

Caching techniques, such as those proposed in the Catalyzer system, focus on restoring function instances from checkpoint images, thereby skipping initialization on the critical path \[[2](https://www.semanticscholar.org/paper/f14446970a5ed7145a6d350e1aff07ca203cece8)\]. This results in sub-millisecond startup times, significantly improving performance \[[2](https://www.semanticscholar.org/paper/f14446970a5ed7145a6d350e1aff07ca203cece8)\]. Additionally, the S-Cache system introduces an adaptive caching policy that considers container frequency, size, and cold-start time, achieving a 3× reduction in average response time and cold-start frequency \[[13](https://www.semanticscholar.org/paper/f85fde870a1eb9c98c62ded89602e2bd1bab6a86)\]. These methods underscore the potential of caching to mitigate cold-start overhead while balancing resource utilization.

### <a id='category-cold-start-latency-challenges'></a>Cold-Start Latency Challenges: 6 papers found.
Cold-start latency remains a critical challenge in serverless computing, impacting the performance and user experience of serverless functions \[[1](https://www.semanticscholar.org/paper/d911b03bfda4fc6fc92f8080bb81b3a967d6a9e7)\]. This issue arises due to the delay in provisioning a runtime container to execute functions, particularly when the function instance is not already running \[[3](https://www.semanticscholar.org/paper/d45518ce5741587c4c37ccbc5e74b3fcfd6f80f1)\]. Various platforms have developed their own solutions to mitigate this problem, but the root cause—initialization overhead—remains a significant bottleneck \[[1](https://www.semanticscholar.org/paper/d911b03bfda4fc6fc92f8080bb81b3a967d6a9e7)\]. Recent research has focused on optimizing the startup process by leveraging state reuse and checkpointing techniques. For instance, Catalyzer proposes a sandbox system that restores function instances from checkpoint images, thereby eliminating the need for initialization on the critical path and achieving sub-millisecond startup latency \[[2](https://www.semanticscholar.org/paper/f14446970a5ed7145a6d350e1aff07ca203cece8)\]. Additionally, scheduling approaches such as the Least Recently Used warm Container Selection (LCS) have been introduced to keep containers active for longer periods, reducing the frequency of cold starts \[[3](https://www.semanticscholar.org/paper/d45518ce5741587c4c37ccbc5e74b3fcfd6f80f1)\]. These advancements highlight the ongoing efforts to address cold-start latency through both architectural innovations and runtime optimizations \[[1](https://www.semanticscholar.org/paper/d911b03bfda4fc6fc92f8080bb81b3a967d6a9e7)\]\[[2](https://www.semanticscholar.org/paper/f14446970a5ed7145a6d350e1aff07ca203cece8)\]\[[3](https://www.semanticscholar.org/paper/d45518ce5741587c4c37ccbc5e74b3fcfd6f80f1)\].

### <a id='category-resource-provisioning-optimization'></a>Resource Provisioning Optimization: 4 papers found.
Resource provisioning optimization in serverless computing has been a focal point for improving performance and reducing costs, particularly in addressing the cold start problem. Existing studies highlight that serverless platforms often suffer from high initialization latency due to the need to set up runtime environments and dependencies for each function invocation \[[1](https://www.semanticscholar.org/paper/d911b03bfda4fc6fc92f8080bb81b3a967d6a9e7)\]. For instance, Azure Functions has been characterized to exhibit an 8-order-of-magnitude range in invocation frequencies, with most functions invoked infrequently \[[1](https://www.semanticscholar.org/paper/d911b03bfda4fc6fc92f8080bb81b3a967d6a9e7)\]. This variability necessitates efficient resource management strategies to minimize cold starts while maintaining low operational costs \[[1](https://www.semanticscholar.org/paper/d911b03bfda4fc6fc92f8080bb81b3a967d6a9e7)\]. Research has also shown that factors such as runtime environment, CPU and memory settings, invocation concurrency, and networking requirements significantly influence cold start behavior \[[2](https://www.semanticscholar.org/paper/f14446970a5ed7145a6d350e1aff07ca203cece8)\]. To mitigate these challenges, several approaches have been proposed, including the use of reinforcement learning agents to predict invocation patterns and pre-provision function instances \[[2](https://www.semanticscholar.org/paper/f14446970a5ed7145a6d350e1aff07ca203cece8)\]. Additionally, tools like Xanadu have been developed to address cascading cold starts in workflows by employing speculative and just-in-time provisioning techniques, achieving near-complete elimination of such overheads \[[3](https://www.semanticscholar.org/paper/d45518ce5741587c4c37ccbc5e74b3fcfd6f80f1)\]. Similarly, frameworks like SSC introduce gradient-based pre-warming algorithms and critical path-based resource allocation strategies to reduce cold start hit rates and improve cost efficiency \[[4](https://www.semanticscholar.org/paper/36338d869d7589b01c3707d70bece8c320e439e2)\]. These advancements collectively underscore the importance of dynamic and adaptive resource provisioning in enhancing the performance and scalability of serverless computing environments.
