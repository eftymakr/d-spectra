## Related Works

Serverless computing has emerged as a transformative paradigm in cloud computing, offering automatic scaling, efficient resource utilization, and cost-effective pricing models \[[16](http://arxiv.org/abs/1911.01296)\]. However, a significant challenge persists in the form of cold-start latency, which can severely impact end-to-end performance \[[16](http://arxiv.org/abs/1911.01296)\]. This issue arises due to the overhead of initializing runtime environments and dependencies before a function can execute \[[16](http://arxiv.org/abs/1911.01296)\]. Several studies have explored strategies to mitigate this problem, including pre-warming, function fusion, and caching techniques \[[16](http://arxiv.org/abs/1911.01296)\].

Pre-warming strategies aim to keep function instances ready to execute, thereby reducing cold-start latency. For instance, the LCS approach utilizes an LRU-based warm container selection mechanism to keep containers alive for longer periods, reducing cold-start occurrences by approximately 48% compared to MRU-based methods \[[3](https://www.semanticscholar.org/paper/d45518ce5741587c4c37ccbc5e74b3fcfd6f80f1)\]. Similarly, FaasCache introduces a greedy-dual caching policy inspired by caching principles, significantly reducing cold-start overhead by more than 3× compared to current approaches \[[11](https://www.semanticscholar.org/paper/3c05fec4087d94c61233a482e59b613388b2c3ae)\]. These methods demonstrate that maintaining warm function instances can effectively alleviate cold-start delays.

Function fusion is another approach that reduces cold-start latency by combining multiple functions into a single unit, thereby eliminating the need to initialize separate functions \[[4](https://www.semanticscholar.org/paper/36338d869d7589b01c3707d70bece8c320e439e2)\]. However, this technique may introduce trade-offs, as it can increase workflow response time for parallel functions \[[4](https://www.semanticscholar.org/paper/36338d869d7589b01c3707d70bece8c320e439e2)\]. The study by Xanadu addresses cascading cold starts in function chain deployments by employing speculative and just-in-time provisioning, effectively reducing platform overheads by up to 18× for short workflows \[[10](https://www.semanticscholar.org/paper/1cd137e77753ee6c51c97c520d64f91d484dbddc)\]. This highlights the importance of optimizing resource provisioning to mitigate cold-start cascading effects.

Caching techniques, such as those proposed in the Catalyzer system, focus on restoring function instances from checkpoint images, thereby skipping initialization on the critical path \[[2](https://www.semanticscholar.org/paper/f14446970a5ed7145a6d350e1aff07ca203cece8)\]. This results in sub-millisecond startup times, significantly improving performance \[[2](https://www.semanticscholar.org/paper/f14446970a5ed7145a6d350e1aff07ca203cece8)\]. Additionally, the S-Cache system introduces an adaptive caching policy that considers container frequency, size, and cold-start time, achieving a 3× reduction in average response time and cold-start frequency \[[13](https://www.semanticscholar.org/paper/f85fde870a1eb9c98c62ded89602e2bd1bab6a86)\]. These methods underscore the potential of caching to mitigate cold-start overhead while balancing resource utilization.

Moreover, reinforcement learning has been applied to predict function invocation patterns and prepare function instances in advance, thereby reducing cold-start frequency \[[9](https://www.semanticscholar.org/paper/96d4fea8d034a7605af936f2e2b6a44becdf6585)\]. This approach demonstrates the value of machine learning in optimizing resource allocation for serverless environments.
