## Related Works

Modern databases often adopt weak isolation levels to achieve high availability and performance, sacrificing some consistency guarantees in favor of scalability \[[1](https://www.semanticscholar.org/paper/cbe191bda20907994d45bc835d20446968370add)\]. This trade-off has led to the emergence of isolation bugs in production systems, which can compromise data consistency \[[1](https://www.semanticscholar.org/paper/cbe191bda20907994d45bc835d20446968370add)\]. Black-box testing has emerged as a key technique for detecting such bugs by verifying whether transaction histories adhere to prescribed isolation levels \[[1](https://www.semanticscholar.org/paper/cbe191bda20907994d45bc835d20446968370add)\]. However, testing large-scale databases remains challenging due to the computational complexity of existing isolation checkers \[[1](https://www.semanticscholar.org/paper/cbe191bda20907994d45bc835d20446968370add)\].

Several works have explored the complexity of checking transactional consistency. For instance, it has been shown that consistency models like read committed, read atomic, and causal consistency are polynomial-time checkable, while snapshot isolation and prefix consistency are NP-complete in general \[[4](http://arxiv.org/abs/1908.04509)\]. These results highlight the computational challenges associated with verifying weak isolation levels, especially in large-scale systems. However, recent advances have demonstrated that weak isolation levels can be tested in polynomial time, enabling the development of scalable testing tools \[[1](https://www.semanticscholar.org/paper/cbe191bda20907994d45bc835d20446968370add)\].

Efforts to improve the efficiency of isolation testing have led to the development of specialized checkers. For example, Viper is a fast snapshot isolation checker that is sound, complete, and significantly faster than existing baselines \[[3](https://www.semanticscholar.org/paper/9f96a48d2bc0e77004b32960495685be6c301c63)\]. It introduces BC-polygraphs, a novel representation of transaction dependencies, and leverages heuristic pruning to accelerate the checking process. Similarly, Plume is a black-box checker for weak isolation levels that uses vectors and tree clocks to accelerate isolation checking \[[1](https://www.semanticscholar.org/paper/cbe191bda20907994d45bc835d20446968370add)\]. These tools represent significant progress in the field, but they still face limitations in terms of polynomial complexity, which restricts their applicability to large-scale workloads \[[1](https://www.semanticscholar.org/paper/cbe191bda20907994d45bc835d20446968370add)\].

The paper at hand introduces AWDIT, a highly-efficient and provably optimal tester for weak database isolation. AWDIT improves upon existing tools by achieving better time complexity for common weak isolation levels such as Read Committed (RC), Read Atomic (RA), and Causal Consistency (CC), with time complexities of $O(n^(3/2))$, $O(n^(3/2))$, and $O(n \cdot k)$, respectively \[[1](https://www.semanticscholar.org/paper/cbe191bda20907994d45bc835d20446968370add)\]. This represents a significant improvement over the state of the art, particularly for large-scale databases. Moreover, the paper establishes a conditional lower bound of $n^(3/2)$ for any weak isolation level between RC and CC, proving that AWDIT is essentially optimal \[[1](https://www.semanticscholar.org/paper/cbe191bda20907994d45bc835d20446968370add)\].

	Document 1: [Snippet]: «Modern applications, such as social networking systems and e-commerce platforms are centered around using large-scale storage systems for storing and retrieving data. In the presence of concurrent accesses, these storage systems trade off isolation for performance. The weaker the isolation level, the more behaviors a storage system is allowed to exhibit and it is up to the developer to ensure that their application can tolerate those behaviors. It uses a logical specification of the isolation level to compute, on a read operation, the set of all possible return values. MonkeyDB then returns a value randomly from this set. We show that MonkeyDB provides good coverage of weak behaviors, which is complete in the limit. We test a variety of applications for assertions that fail only under weak isolation. MonkeyDB is able to break each of those assertions in a small number of attempts.»
