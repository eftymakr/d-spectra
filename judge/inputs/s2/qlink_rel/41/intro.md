## Related Works

Serverless computing has emerged as a transformative paradigm in cloud computing, offering automatic scaling, efficient resource utilization, and cost-effective pricing models \[[16](https://www.semanticscholar.org/paper/d9eaeccc9cca929af052aa362efaf83267daf614)\]. However, a significant challenge remains in the form of cold-start latency, which occurs when a function is invoked and no pre-provisioned runtime container is available, leading to increased initialization overhead \[[14](http://arxiv.org/abs/1903.12221)\]. This issue has been extensively studied, with various approaches proposed to mitigate its impact.

Early work focused on reducing cold-start latency by maintaining pools of warm containers to avoid the overhead of on-demand provisioning \[[14](http://arxiv.org/abs/1903.12221)\]. These approaches, while effective, often come at the cost of increased resource consumption, as they require keeping containers idle to ensure readiness \[[4](https://www.semanticscholar.org/paper/81b8db7a20f1aa859143c716b38a1443e3eca9a0)\]. To address this, researchers have explored adaptive strategies that dynamically adjust container pools based on predicted workload patterns \[[4](https://www.semanticscholar.org/paper/81b8db7a20f1aa859143c716b38a1443e3eca9a0)\]. For instance, the Adaptive Warm-Up Strategy (AWUS) leverages function chain models and fine-grained regression to predict invocation times and warm up functions preemptively, thereby reducing cold-start latency and resource waste \[[4](https://www.semanticscholar.org/paper/81b8db7a20f1aa859143c716b38a1443e3eca9a0)\]. Similarly, the Adaptive Container Pool Scaling Strategy (ACPSS) dynamically adjusts container pool capacity to minimize resource waste while maintaining performance \[[4](https://www.semanticscholar.org/paper/81b8db7a20f1aa859143c716b38a1443e3eca9a0)\].

Other approaches focus on optimizing the initialization process itself. For example, Catalyzer introduces an initialization-less booting mechanism by restoring function instances from checkpoint images, significantly reducing startup latency to sub-millisecond levels \[[2](https://www.semanticscholar.org/paper/f14446970a5ed7145a6d350e1aff07ca203cece8)\]. This approach eliminates the need to initialize sandbox environments, which is a major contributor to cold-start overhead in traditional serverless platforms \[[2](https://www.semanticscholar.org/paper/f14446970a5ed7145a6d350e1aff07ca203cece8)\]. Similarly, FaaSLight employs application-level optimizations to reduce code loading latency by identifying and loading only the necessary code for function execution \[[6](http://arxiv.org/abs/2207.08175)\]. This method is platform- and language-agnostic, making it applicable across a wide range of serverless environments \[[6](http://arxiv.org/abs/2207.08175)\].

Prebaking techniques have also been proposed to mitigate cold starts by restoring snapshots of previously executed functions \[[7](https://www.semanticscholar.org/paper/ab1c0062964a2df3d7f8d11da4a774530286b801)\]. This approach can reduce startup times by up to 71% for certain workloads, demonstrating the potential of state reuse in minimizing initialization overhead \[[7](https://www.semanticscholar.org/paper/ab1c0062964a2df3d7f8d11da4a774530286b801)\]. Furthermore, reinforcement learning has been applied to predict function invocation patterns and optimize the number of function instances kept ready, thereby reducing cold-start frequency \[[8](https://www.semanticscholar.org/paper/96d4fea8d034a7605af936f2e2b6a44becdf6585)\]. These methods leverage machine learning to adapt to varying workloads, improving both performance and resource efficiency \[[8](https://www.semanticscholar.org/paper/96d4fea8d034a7605af936f2e2b6a44becdf6585)\].

In addition to runtime optimizations, caching-based keep-alive policies have been proposed to maintain function instances in a ready state, reducing the need for frequent cold starts \[[13](https://www.semanticscholar.org/paper/3c05fec4087d94c61233a482e59b613388b2c3ae)\].
