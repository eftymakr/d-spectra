## Related Works

The rapid growth of open-source machine learning (ML) resources has significantly impacted information retrieval (IR) research, particularly in the areas of resource management and advanced querying \[[1](http://arxiv.org/abs/2305.11164)\]. While platforms like Hugging Face have become central hubs for sharing ML models and datasets, they lack structured representations that enable sophisticated analyses such as tracing model evolution and recommending relevant datasets \[[1](http://arxiv.org/abs/2305.11164)\]. This limitation has motivated the development of knowledge graphs and benchmarking frameworks to enhance the usability of these resources.

Several studies have explored the characteristics and challenges of ML model repositories. For instance, \[[2](http://arxiv.org/abs/2311.13380)\] conducted a repository mining study on Hugging Face, revealing that only a small proportion of models report carbon emissions, and that there is a strong correlation between model size, dataset size, and carbon footprint. This highlights the need for more transparent and standardized reporting practices in the ML community. Similarly, \[[3](http://arxiv.org/abs/2303.02552)\] investigated the reuse of pre-trained models on Hugging Face, identifying challenges such as missing attributes, discrepancies between claimed and actual performance, and model risks. These findings underscore the importance of improving model documentation and metadata to support better reuse and evaluation.

The lack of structured data in ML repositories has also been a focus of other studies. \[[4](https://www.semanticscholar.org/paper/e9270f790459c84c3d16e2bb29bd1ab311ec5c78)\] analyzed the Hugging Face platform to assess the vulnerabilities of open-source AI models, revealing that a significant percentage of models contain high-severity vulnerabilities. This work emphasizes the need for improved security practices and automated vulnerability detection in ML ecosystems. Additionally, \[[5](http://arxiv.org/abs/2401.13822)\] examined dataset documentation on Hugging Face, finding that while dataset cards are widely used, there is significant variability in their completeness and quality. This variability affects the reproducibility and reliability of ML research, further highlighting the need for standardized documentation practices.

In the context of knowledge graphs, \[[6](http://arxiv.org/abs/2303.17580)\] introduced HuggingKG, the first large-scale knowledge graph built from the Hugging Face community, which captures domain-specific relations and textual attributes to support advanced querying and analysis. This work builds on earlier efforts to enhance the usability of ML resources, such as \[[7](http://arxiv.org/abs/2406.08205)\], which proposed HuggingGPT, an agent that leverages large language models to connect various AI models on Hugging Face to solve complex tasks. ### <a id='category-security-vulnerabilities-in-open-source-models'></a>Security Vulnerabilities in Open-Source Models: 2 papers found.
The category "Security Vulnerabilities in Open-Source Models" highlights critical security risks associated with the widespread use of open-source machine learning models on platforms like Hugging Face. These platforms, which host millions of models and are utilized by major organizations, may contain significant security vulnerabilities, such as unsafe serialization methods that enable object injection attacks \[[13](http://arxiv.org/abs/2410.04490)\]. Research has shown that a substantial percentage of models on Hugging Face are vulnerable, with high-severity vulnerabilities accounting for 35.98% of all detected issues, compared to only 6.79% of low-severity ones \[[4](https://www.semanticscholar.org/paper/e9270f790459c84c3d16e2bb29bd1ab311ec5c78)\]. This indicates a concerning trend in the security landscape of open-source AI models. Furthermore, many of these vulnerabilities exist in foundational repositories like Transformers, which are widely used in the AI community, thereby posing a significant risk to the broader software supply chain \[[4](https://www.semanticscholar.org/paper/e9270f790459c84c3d16e2bb29bd1ab311ec5c78)\]. The lack of robust security measures and the prevalence of unsafe practices in model serialization underscore the need for improved detection and mitigation strategies. Existing studies have also demonstrated that Hugging Face's current mechanisms for identifying and flagging vulnerable models are insufficient, necessitating the development of more advanced detection techniques \[[13](http://arxiv.org/abs/2410.04490)\]. These findings emphasize the importance of addressing security concerns in open-source AI ecosystems to ensure the safety and reliability of AI systems.

In order to clarify the intended use cases of machine learning models and minimize their usage in contexts for which they are not well suited, we recommend that released models be accompanied by documentation detailing their performance characteristics. In this paper, we propose a framework that we call model cards, to encourage such transparent model reporting. Model cards are short documents accompanying trained machine learning models that provide benchmarked evaluation in a variety of conditions, such as across different cultural, demographic, or phenotypic groups (e.g., race, geographic location, sex, Fitzpatrick skin type \[[15](http://arxiv.org/abs/1409.0575)\]) and intersectional groups (e.g., age and race, or sex and Fitzpatrick skin type) that are relevant to the intended application domains. Model cards also disclose the context in which models are intended to be used, details of the performance evaluation procedures, and other relevant information. While we focus primarily on human-centered machine learning models in the application fields of computer vision and natural language processing, this framework can be used to document any trained machine learning model. To solidify the concept, we provide cards for two supervised models: One trained to detect smiling faces in images, and one trained to detect toxic comments in text. We propose model cards as a step towards the responsible democratization of machine learning and related artificial intelligence technology, increasing transparency into how well artificial intelligence technology works. We hope this work encourages those releasing trained machine learning models to accompany model releases with similar detailed evaluation numbers and other relevant documentation.»
