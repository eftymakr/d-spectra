## Related Works

Cold start latency remains a critical challenge in serverless computing, impacting the performance and scalability of function-as-a-service (FaaS) platforms \[[16](http://arxiv.org/abs/1911.01296)\]. Existing approaches have attempted to mitigate this issue through various strategies, including pre-warming containers, optimizing function initialization, and reducing resource consumption \[[16](http://arxiv.org/abs/1911.01296)\]. For instance, some works focus on reducing cold start latency by keeping containers warm for a fixed period, but this approach may lead to increased resource consumption and conflicts with the scale-to-zero feature of serverless platforms \[[13](https://www.semanticscholar.org/paper/b99668ae35c4b6796b827657a318fe4b84a757ff)\]. Others propose adaptive models to predict the optimal length of idle container windows based on historical invocation patterns \[[13](https://www.semanticscholar.org/paper/b99668ae35c4b6796b827657a318fe4b84a757ff)\]. These methods, however, often rely on static policies that do not adapt well to dynamic workloads \[[17](https://www.semanticscholar.org/paper/27cd21426fe51167dd6ac79d1c83db55a07a2046)\].

Several studies have explored the use of reinforcement learning to predict function invocation patterns and optimize pre-warmed container allocation \[[17](https://www.semanticscholar.org/paper/27cd21426fe51167dd6ac79d1c83db55a07a2046)\]. This approach allows for more intelligent and adaptive resource management, reducing both cold start frequency and memory consumption. Additionally, some works have focused on reducing cold start latency by leveraging caching mechanisms and keep-alive policies, drawing parallels between serverless function management and traditional caching techniques \[[12](https://www.semanticscholar.org/paper/3c05fec4087d94c61233a482e59b613388b2c3ae)\]. These caching-inspired approaches have shown promising results, reducing cold start overhead by more than 3× compared to existing methods \[[12](https://www.semanticscholar.org/paper/3c05fec4087d94c61233a482e59b613388b2c3ae)\].

Another line of research focuses on function fusion, where multiple functions are combined into a single unit to eliminate the cold start latency of subsequent functions in a workflow \[[15](https://www.semanticscholar.org/paper/36338d869d7589b01c3707d70bece8c320e439e2)\]. While this approach can reduce cold start latency, it may also increase workflow response time if parallel functions are executed sequentially \[[15](https://www.semanticscholar.org/paper/36338d869d7589b01c3707d70bece8c320e439e2)\]. To address this, researchers have proposed workflow response time models that consider cold start latencies and optimize function fusion strategies accordingly \[[15](https://www.semanticscholar.org/paper/36338d869d7589b01c3707d70bece8c320e439e2)\].

Furthermore, some studies have investigated the use of application-level optimizations to reduce cold start latency by identifying and eliminating unnecessary code loading overhead \[[6](http://arxiv.org/abs/2207.08175)\]. This includes techniques such as on-demand loading of optional code and separating essential code from FaaS applications \[[6](http://arxiv.org/abs/2207.08175)\]. These methods have shown significant improvements in reducing code loading latency and, consequently, cold start latency \[[6](http://arxiv.org/abs/2207.08175)\].

In addition, there are approaches that utilize checkpointing and snapshot restoration to accelerate function startup \[[8](https://www.semanticscholar.org/paper/ab1c0062964a2df3d7f8d11da4a774530286b801)\]. By restoring previously executed function processes, these techniques can significantly reduce startup time, with some studies reporting up to a 71% improvement in function replica startup times \[[8](https://www.semanticscholar.org/paper/ab1c0062964a2df3d7f8d11da4a774530286b801)\]. 	Document 1: [Snippet]: «As Artificial Intelligence (AI) is becoming ubiquitous in many applications, serverless computing is also emerging as a building block for developing cloud-based AI services. Serverless computing has received much interest because of its simplicity, scalability, and resource efficiency. However, due to the trade-off with resource efficiency, serverless computing suffers from the cold start problem, that is, a latency between a request arrival and function execution. The cold start problem significantly influences the overall response time of workflow that consists of functions because the cold start may occur in every function within the workflow. Function fusion can be one of the solutions to mitigate the cold start latency of a workflow. If two functions are fused into a single function, the cold start of the second function is removed; however, if parallel functions are fused, the workflow response time can be increased because the parallel functions run sequentially even if the cold start latency is reduced. This study presents an approach to mitigate the cold start latency of a workflow using function fusion while considering a parallel run. First, we identify three latencies that affect response time, present a workflow response time model considering the latency, and efficiently find a fusion solution that can optimize the response time on the cold start. Our method shows a response time of 28–86% of the response time of the original workflow in five workflows.»
