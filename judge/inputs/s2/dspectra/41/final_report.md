## Related Works

Serverless computing has gained significant traction due to its ability to abstract away server management, enabling automatic scaling, efficient resource utilization, and cost-effective pricing models \[[14](https://www.semanticscholar.org/paper/fbf4355d06ddb5f6c81e67cffadf57f6939b8940)\]. However, one of the major challenges in this paradigm is the cold-start latency, which significantly impacts end-to-end performance \[[14](https://www.semanticscholar.org/paper/fbf4355d06ddb5f6c81e67cffadf57f6939b8940)\]. Cold starts occur when a new function container must be provisioned to handle a request, introducing additional latency \[[4](https://www.semanticscholar.org/paper/d911b03bfda4fc6fc92f8080bb81b3a967d6a9e7)\]. This issue has been extensively studied, and various approaches have been proposed to mitigate it.

Several works focus on reducing cold-start latency by maintaining a pool of warm containers \[[5](http://arxiv.org/abs/1903.12221)\]. For instance, \[[5](http://arxiv.org/abs/1903.12221)\] proposes a pool-based approach where a set of function instances is kept pre-provisioned to reduce the need for on-demand container creation. This approach achieves an 85% reduction in P99 response time for a single instance pool. Similarly, \[[11](https://www.semanticscholar.org/paper/81b8db7a20f1aa859143c716b38a1443e3eca9a0)\] introduces an adaptive warm-up strategy that predicts function invocation times and pre-warms containers, thereby reducing cold-start latency while minimizing resource consumption. The adaptive container pool scaling strategy proposed in \[[11](https://www.semanticscholar.org/paper/81b8db7a20f1aa859143c716b38a1443e3eca9a0)\] dynamically adjusts the pool size to reduce resource waste.

Other approaches leverage machine learning and reinforcement learning to predict and manage cold starts more efficiently. \[[8](https://www.semanticscholar.org/paper/27cd21426fe51167dd6ac79d1c83db55a07a2046)\] proposes a two-layer adaptive approach using reinforcement learning to determine the optimal time to keep containers warm and LSTM to predict future function invocations. This method reduces memory consumption by 12.73% and improves execution invocations on prewarmed containers by 22.65%. Similarly, \[[13](https://www.semanticscholar.org/paper/96d4fea8d034a7605af936f2e2b6a44becdf6585)\] introduces a Q-Learning agent to analyze function invocation patterns and prepare function instances in advance, thereby reducing cold start frequency.

Additionally, \[[9](https://www.semanticscholar.org/paper/1447da2da7c926dc68e31a89461409d09b08d77e)\] presents a middleware solution that uses application knowledge to trigger cold starts before they occur, effectively reducing the number of cold starts by up to 80% without significant overhead. This approach treats the FaaS service as a black box and leverages function composition knowledge to optimize container provisioning.

Moreover, \[[14](https://www.semanticscholar.org/paper/fbf4355d06ddb5f6c81e67cffadf57f6939b8940)\] introduces a framework that combines cold-start optimization with automatic workflow resource scheduling, significantly reducing cold start hit rates and achieving cost savings of approximately 30%. This work highlights the importance of integrating cold-start mitigation with broader resource management strategies.

The cold-start latency challenge in serverless computing has been extensively studied, with researchers proposing various solutions to mitigate its impact on performance. The core issue arises from the need to initialize runtime environments and load libraries for each function invocation, which introduces significant overhead, especially under high workload conditions \[[4](https://www.semanticscholar.org/paper/d911b03bfda4fc6fc92f8080bb81b3a967d6a9e7)\]. Recent work, such as Catalyzer, has introduced innovative solutions like checkpoint-based restoration and the sfork primitive to enable near-instant function startup by reusing state from previously executed instances \[[1](https://www.semanticscholar.org/paper/f14446970a5ed7145a6d350e1aff07ca203cece8)\]. Additionally, tools like SLIMSTART have been developed to analyze and optimize library usage patterns, leveraging profiling data to reduce initialization overhead and improve resource utilization \[[1](https://www.semanticscholar.org/paper/f14446970a5ed7145a6d350e1aff07ca203cece8)\]. These advancements highlight the ongoing efforts to address cold-start latency, though challenges remain in ensuring scalability and adaptability across diverse workloads \[[3](http://arxiv.org/abs/2310.08437)\].

Application-Level Library Optimization focuses on improving the efficiency of software by eliminating unnecessary library usage, particularly in serverless environments where cold-start latency is a critical issue \[[17](https://www.semanticscholar.org/paper/5ac5d4d4e725bcf9037efc1adfcc26f37afabdfd)\]. This category emphasizes the use of advanced static and dynamic analysis techniques to identify and remove unused or underutilized libraries, which can significantly reduce initialization time and resource consumption. Existing methods often rely on static analysis to detect unreachable code, but they struggle with workload-dependent inefficiencies, leading to limited performance gains \[[17](https://www.semanticscholar.org/paper/5ac5d4d4e725bcf9037efc1adfcc26f37afabdfd)\]. To address these limitations, new approaches leverage runtime data and profiling to adaptively optimize library usage, ensuring that only essential components are loaded during function initialization. This optimization is crucial for improving both the performance and cost-effectiveness of serverless applications, as it directly impacts the end-to-end latency and resource utilization \[[17](https://www.semanticscholar.org/paper/5ac5d4d4e725bcf9037efc1adfcc26f37afabdfd)\].
