## Related Works

The growing adoption of cloud-native technologies has spurred significant research into optimizing both operational and financial aspects of containerized applications. Kubernetes, as a leading container orchestration platform, has become a focal point for studies on security, performance, and cost efficiency. Prior work has explored system-level optimizations for resource efficiency and cost management, but network cost analysis in Kubernetes remains underexplored \[[1](http://arxiv.org/abs/2006.15275)\]. This paper contributes to the FinOps discipline by addressing the financial and operational aspects of managing network costs in cloud-native environments \[[1](http://arxiv.org/abs/2006.15275)\].

Several studies have investigated the security implications of Kubernetes deployments. For instance, \[[1](http://arxiv.org/abs/2006.15275)\] highlights that Kubernetes is susceptible to security vulnerabilities, such as those that occurred at Tesla in 2018. Security misconfigurations in Kubernetes manifests have been identified as a critical issue, with empirical studies revealing 11 categories of misconfigurations, including absent resource limits and insecure container settings \[[3](https://www.semanticscholar.org/paper/61020665f9134e56009b6e10606fc21348f59d53)\]. These findings underscore the need for rigorous security practices and static analysis tools like SLI-KUBE to detect and mitigate such risks \[[3](https://www.semanticscholar.org/paper/61020665f9134e56009b6e10606fc21348f59d53)\].

In terms of cost optimization, \[[4](http://arxiv.org/abs/2501.14753)\] presents ABACUS, a FinOps service that enables budgeting, enforcement of spending limits, and alerting mechanisms to control cloud costs. This aligns with the broader goal of FinOps to integrate financial management with cloud operations \[[4](http://arxiv.org/abs/2501.14753)\]. Additionally, \[[8](http://arxiv.org/abs/2307.12479)\] reviews strategies for cloud and AI infrastructure cost optimization, emphasizing techniques such as model quantization and GPU instance selection to reduce costs. These methods are particularly relevant for organizations with high GPU compute demands \[[8](http://arxiv.org/abs/2307.12479)\].

The integration of workflow systems with Kubernetes has also been a focus of recent research. \[[2](http://arxiv.org/abs/2207.01222)\] introduces KubeAdaptor, a docking framework that ensures consistency in task scheduling order between workflow systems and Kubernetes, improving execution efficiency. Similarly, \[[18](http://arxiv.org/abs/2301.08409)\] proposes an adaptive resource allocation scheme (ARAS) for Kubernetes-based workflow engines, which enhances resource utilization and reduces waste \[[18](http://arxiv.org/abs/2301.08409)\]. These contributions highlight the importance of optimizing resource management for performance and cost efficiency in Kubernetes environments.

Moreover, \[[12](http://arxiv.org/abs/2010.10350)\] investigates resource management schemes for cloud-native platforms, showing that changing default settings can significantly reduce completion times for computational-intensive applications. This underscores the importance of configuration tuning for performance optimization \[[12](http://arxiv.org/abs/2010.10350)\]. In addition, \[[16](https://www.semanticscholar.org/paper/2a7396b670ac72d37afbf5da2925116d35a4030a)\] discusses container security in Kubernetes clusters, emphasizing the need for real-time monitoring tools to detect and mitigate potential threats \[[16](https://www.semanticscholar.org/paper/2a7396b670ac72d37afbf5da2925116d35a4030a)\].
