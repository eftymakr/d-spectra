## Related Works

Modern databases often trade strong transaction isolation for weak isolation levels to achieve low latency and high throughput, particularly in distributed systems \[[1](http://arxiv.org/abs/2107.11458)\]. This trade-off, however, has led to the emergence of isolation bugs that violate data-consistency guarantees \[[1](http://arxiv.org/abs/2107.11458)\]. Black-box testing has emerged as a prominent technique for detecting such bugs by verifying whether transaction histories adhere to prescribed isolation levels \[[1](http://arxiv.org/abs/2107.11458)\]. Several tools have been developed for this purpose, but they often suffer from high computational complexity, limiting their applicability to large-scale workloads \[[1](http://arxiv.org/abs/2107.11458)\].

Early approaches to isolation testing focused on strong isolation levels such as serializability and snapshot isolation, which are known to be NP-complete \[[1](http://arxiv.org/abs/2107.11458)\]. However, recent research has shown that weak isolation levels, such as Read Committed (RC), Read Atomic (RA), and Causal Consistency (CC), can be tested in polynomial time, enabling the scalability of testing tools \[[1](http://arxiv.org/abs/2107.11458)\]. This breakthrough has spurred the development of more efficient algorithms for weak isolation testing \[[1](http://arxiv.org/abs/2107.11458)\].

Several tools have been proposed to improve the efficiency of isolation testing. For example, Plume is a black-box checker for weak isolation levels that leverages vectors and tree clocks to accelerate checking \[[3](https://www.semanticscholar.org/paper/cbe191bda20907994d45bc835d20446968370add)\]. Similarly, MonkeyDB is a mock storage system designed to test storage-backed applications under weak isolation levels by simulating all possible return values for read operations \[[4](http://arxiv.org/abs/2103.02830)\]. These tools provide valuable insights into the behavior of weak isolation levels but are limited in their efficiency for large-scale workloads \[[4](http://arxiv.org/abs/2103.02830)\].

The work in \[[6](http://arxiv.org/abs/2504.02344)\] introduces Mini-Transactions (MTs), a novel approach to reduce the overhead of isolation checking by using compact, short transactions that execute faster than general workloads. This approach significantly improves the efficiency of history generation and verification, making it suitable for large-scale databases \[[6](http://arxiv.org/abs/2504.02344)\]. Additionally, Viper is a fast Snapshot Isolation (SI) checker that is sound, complete, and efficient, leveraging BC-polygraphs to represent transaction dependencies \[[9](https://www.semanticscholar.org/paper/9f96a48d2bc0e77004b32960495685be6c301c63)\]. These advancements highlight the ongoing efforts to improve the efficiency and accuracy of isolation testing.

The complexity of isolation testing has also been studied in terms of theoretical bounds. For example, \[[8](http://arxiv.org/abs/1308.3946)\] presents optimal algorithms for testing the closeness of discrete distributions, which is relevant to the statistical analysis of transaction histories. These algorithms have sample complexity that is information-theoretically optimal, providing a foundation for more efficient testing methods \[[8](http://arxiv.org/abs/1308.3946)\].
