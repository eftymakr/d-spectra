## Related Works

Table discovery has emerged as a critical challenge in the era of abundant tabular data repositories. Traditional approaches often rely on query tables or vague keywords to retrieve relevant tables, requiring users to manually filter large result sets \[[6](http://arxiv.org/abs/2411.03356)\]. This limitation highlights the need for more sophisticated methods that can integrate natural language (NL) requirements into the search process. The proposed task, NL-conditional table discovery (nlcTD), addresses this by enabling users to refine search results using both a query table and NL conditions \[[6](http://arxiv.org/abs/2411.03356)\]. 

Several studies have explored the semantic connections between tables, aiming to improve the semantic capabilities of database systems \[[1](http://arxiv.org/abs/1208.4016)\]. For instance, the concept-driven framework for latent table discovery focuses on semantically connecting unrelated tables that are not syntactically related by design \[[1](http://arxiv.org/abs/1208.4016)\]. This work laid the groundwork for understanding how semantic relationships can enhance table discovery. However, these methods often lack the ability to handle complex NL conditions, which are essential for more nuanced queries.

Recent advancements in deep learning have shown promise in table detection, particularly with the introduction of diverse datasets like the STDW dataset, which contains over 7,000 samples with varied table structures \[[2](http://arxiv.org/abs/2209.09207)\]. This dataset has enabled the development of high-throughput deep learning methods for understanding document layout and tabular data processing. While these methods improve the detection of table structures, they do not directly address the integration of NL conditions into the discovery process.

The challenge of handling large tables and ensuring data privacy has also been addressed in recent works. The "HiddenTables" cooperative game and dataset "PyQTax" demonstrate how LLMs can interact with massive datasets while ensuring data security and minimizing generation costs \[[3](http://arxiv.org/abs/2406.10803)\]. This work highlights the limitations of current LLMs in handling complex queries and compositional dependencies, which is a key consideration for the nlcTD task. The proposed framework in "HiddenTables" allows for more efficient handling of large tables by not being constrained by the number of rows, which is a significant advantage for the nlcTD task.

In addition, the use of synthetic data generation to enhance table representations has been explored. The paper "Enhancing Table Representations with LLM-powered Synthetic Data Generation" proposes a novel pipeline that leverages LLMs to create synthetic datasets tailored for table-level representation learning \[[6](http://arxiv.org/abs/2411.03356)\]. This work addresses the lack of high-quality training data in existing approaches, which is a critical factor in improving the performance of table discovery methods.

[Snippet]: «A myriad of different Large Language Models (LLMs) face a common challenge in contextually analyzing table question-answering tasks. These challenges are engendered from (1) finite context windows for large tables, (2) multi-faceted discrepancies amongst tokenization patterns against cell boundaries, and (3) various limitations stemming from data confidentiality in the process of using external models such as gpt-3.5-turbo. We propose a cooperative game dubbed "HiddenTables" as a potential resolution to this challenge. In essence, "HiddenTables" is played between the code-generating LLM "Solver" and the "Oracle" which evaluates the ability of the LLM agents to solve Table QA tasks. This game is based on natural language schemas and importantly, ensures the security of the underlying data. We provide evidential experiments on a diverse set of tables that demonstrate an LLM's collective inability to generalize and perform on complex queries, handle compositional dependencies, and align natural language to programmatic commands when concrete table schemas are provided. Unlike encoder-based models, we have pushed the boundaries of "HiddenTables" to not be limited by the number of rows - therefore we exhibit improved efficiency in prompt and completion tokens. Our infrastructure has spawned a new dataset "PyQTax" that spans across 116,671 question-table-answer triplets and provides additional fine-grained breakdowns&labels for varying question taxonomies. Therefore, in tandem with our academic contributions regarding LLMs' deficiency in TableQA tasks, "HiddenTables" is a tactile manifestation of how LLMs can interact with massive datasets while ensuring data security and minimizing generation costs.»

[Snippet]: «When working with any sort of knowledge base (KB) one has to make sure it is as complete and also as up-to-date as possible. Both tasks are non-trivial as they require recall-oriented efforts to determine which entities and relationships are missing from the KB. As such they require a significant amount of labor. Tables on the Web on the other hand are abundant and have the distinct potential to assist with these tasks. In particular, we can leverage the content in such tables to discover new entities, properties, and relationships. Because web tables typically only contain raw textual content we first need to determine which cells refer to which known entities—a task we dub table-to-KB matching. This first task aims to infer table semantics by linking table cells and heading columns to elements of a KB. We propose a feature-based method and on two public test collections we demonstrate substantial improvements over the state-of-the-art in terms of precision whilst also improving recall. Then second task builds upon these linked entities and properties to not only identify novel ones in the same table but also to bootstrap their type and additional relationships. We refer to this process as novel entity discovery and, to the best of our knowledge, it is the first endeavor on mining the unlinked cells in web tables. Our method identifies not only out-of-KB (“novel”) information but also novel aliases for in-KB (“known”) entities. When evaluated using three purpose-built test collections, we find that our proposed approaches obtain a marked improvement in terms of precision over our baselines whilst keeping recall stable.»
