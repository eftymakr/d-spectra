## Related Works

Cold start latency remains a critical challenge in serverless computing, impacting both performance and resource utilization \[[1](http://arxiv.org/abs/2406.11734)\]. Several studies have explored this issue, proposing various mitigation strategies. One early approach, described in \[[8](http://arxiv.org/abs/1903.12221)\], involves maintaining a pool of warm containers to reduce the latency associated with on-demand provisioning. This method significantly reduces P99 response time by up to 85% for a single instance pool. However, it does not address the underlying inefficiencies in library initialization and usage, which are identified as major contributors to cold start latency in Python-based serverless applications \[[1](http://arxiv.org/abs/2406.11734)\].

To tackle these inefficiencies, researchers have proposed profiling tools that analyze runtime behavior. LibProf, for instance, uses dynamic program analysis to identify inefficient library initializations and provides detailed reports to guide developers \[[1](http://arxiv.org/abs/2406.11734)\]. This approach aligns with the need for runtime-based insights, as static analysis techniques often fail to capture workload-dependent inefficiencies \[[1](http://arxiv.org/abs/2406.11734)\]. Similarly, FaaSLight focuses on application-level optimization by separating essential code from optional code, thereby reducing code loading latency and cold start overhead \[[10](http://arxiv.org/abs/2207.08175)\]. This method is platform- and language-agnostic, making it broadly applicable across different serverless environments.

Another line of research leverages machine learning for predictive resource management. The work in \[[9](http://arxiv.org/abs/2304.00396)\] proposes using temporal convolutional networks (TCNs) to predict function instance arrivals and optimize resource provisioning. This approach outperforms traditional machine learning models for time series forecasting, demonstrating the potential of deep learning in mitigating cold starts. Similarly, \[[4](http://arxiv.org/abs/2206.15176)\] introduces a time series forecasting model, SARIMA, to predict incoming requests and adjust container allocation dynamically, reducing resource wastage and function launching time. These studies highlight the value of predictive models in managing cold start latency effectively.

Reinforcement learning has also been applied to address cold start issues. \[[7](http://arxiv.org/abs/2308.07541)\] proposes an RL-based approach that uses Q-learning to proactively initialize functions based on expected demand, improving throughput by up to 8.81% and reducing resource wastage. This method demonstrates the potential of adaptive learning in optimizing serverless function provisioning. Additionally, \[[16](http://arxiv.org/abs/2108.11240)\] introduces Pagurus, a runtime container management system that enables inter-action container sharing, effectively eliminating cold startup time by reusing warm containers across different actions.

While these approaches offer promising solutions, they often focus on specific aspects of cold start mitigation, such as container management or predictive resource allocation.
