However, a critical challenge remains: cold-start latency, which adversely impacts end-to-end performance \[[1](http://arxiv.org/abs/2008.12819)\]. Several studies have explored this issue, proposing various techniques to mitigate cold-start overhead. For instance, Fifer \[[1](http://arxiv.org/abs/2008.12819)\] addresses the underutilization of resources in serverless environments by introducing an adaptive resource management framework. This framework improves container utilization and cluster-wide energy consumption by 4x and 31%, respectively, without compromising on SLOs. Fifer leverages function-aware container scaling and intelligent request batching to reduce container over-provisioning during workload fluctuations \[[1](http://arxiv.org/abs/2008.12819)\].

### <a id='category-cold-start-latency-challenges'></a>Cold-Start Latency Challenges: 9 papers found.
Cold-start latency remains a critical challenge in serverless computing, particularly in Function-as-a-Service (FaaS) platforms, where functions face significant delays during their initial execution \[[3](http://arxiv.org/abs/2207.08175)\]. Existing studies have identified that the primary contributor to this issue is the loading of unnecessary code, which introduces substantial overhead \[[3](http://arxiv.org/abs/2207.08175)\]. To address this, researchers have proposed various optimization strategies, such as identifying and excluding unused code through static analysis or runtime profiling \[[3](http://arxiv.org/abs/2207.08175)\]. For instance, some approaches leverage call graphs to distinguish between essential and optional code, allowing optional components to be loaded on demand \[[3](http://arxiv.org/abs/2207.08175)\]. However, these methods often struggle with accurately identifying indispensable code, risking application failures \[[3](http://arxiv.org/abs/2207.08175)\]. More recent work, such as SLIMSTART, has introduced profile-guided optimization techniques that collect runtime library usage data and apply automated code transformations to reduce cold-start overhead \[[3](http://arxiv.org/abs/2207.08175)\]. These methods not only improve initialization and end-to-end latency but also integrate with CI/CD pipelines for continuous optimization \[[3](http://arxiv.org/abs/2207.08175)\]. Despite these advances, there is still room for improvement, particularly in handling workload-dependent inefficiencies and ensuring platform- and language-agnostic solutions \[[3](http://arxiv.org/abs/2207.08175)\]. Further research is needed to refine these techniques and ensure broader applicability across different serverless environments.
