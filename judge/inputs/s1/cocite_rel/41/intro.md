## Related Works

Serverless computing has emerged as a transformative paradigm in cloud computing, offering automatic scaling, efficient resource utilization, and cost-effective pricing models \[[16](http://arxiv.org/abs/1911.01296)\]. However, a significant challenge persists in the form of cold-start latency, which occurs when a function is invoked and no pre-initialized container is available to execute it \[[1](https://www.semanticscholar.org/paper/d911b03bfda4fc6fc92f8080bb81b3a967d6a9e7)\]. This delay can significantly impact end-to-end performance, particularly in workflows where multiple functions are executed sequentially \[[4](https://www.semanticscholar.org/paper/36338d869d7589b01c3707d70bece8c320e439e2)\]. 

Several approaches have been proposed to mitigate cold-start latency. One line of research focuses on reducing the initialization time of function containers. For instance, Catalyzer introduces a sandbox system that restores a function instance from a checkpoint image, thereby skipping the initialization on the critical path and achieving sub-millisecond startup latency \[[2](https://www.semanticscholar.org/paper/f14446970a5ed7145a6d350e1aff07ca203cece8)\]. Similarly, the prebaking technique restores snapshots of previously executed function processes, improving startup time by up to 71% for certain workloads \[[6](https://www.semanticscholar.org/paper/ab1c0062964a2df3d7f8d11da4a774530286b801)\]. These methods aim to reduce the time required to initialize a function, but they often require additional resources or storage, which may conflict with the resource efficiency goals of serverless computing \[[14](https://www.semanticscholar.org/paper/f85fde870a1eb9c98c62ded89602e2bd1bab6a86)\].

Another approach involves reducing the frequency of cold starts by keeping function containers warm. The LCS approach, which uses an LRU warm container selection strategy, has been shown to reduce cold starts by approximately 48% compared to the MRU approach \[[3](https://www.semanticscholar.org/paper/d45518ce5741587c4c37ccbc5e74b3fcfd6f80f1)\]. Similarly, FaasCache employs a caching-inspired keep-alive policy, reducing cold-start overhead by more than 3× compared to current approaches \[[11](https://www.semanticscholar.org/paper/3c05fec4087d94c61233a482e59b613388b2c3ae)\]. These methods leverage the reuse of previously executed functions to minimize the need for new container initialization, thus improving performance.

Function fusion has also been proposed as a way to reduce cold-start latency in workflows. By combining multiple functions into a single function, the cold start of the second function can be avoided. However, this approach may increase the response time of parallel functions that run sequentially \[[4](https://www.semanticscholar.org/paper/36338d869d7589b01c3707d70bece8c320e439e2)\]. The trade-off between reducing cold-start latency and maintaining parallelism is an important consideration in workflow optimization.

In addition to reducing cold-start latency, several studies have focused on optimizing resource allocation to minimize the number of cold starts. For example, the SSC framework introduces a gradient-based algorithm for pre-warming containers and a priority queue-based algorithm for resource allocation, achieving a 50% reduction in cold start hit rates and 30% cost savings \[[12](https://www.semanticscholar.org/paper/fbf4355d06ddb5f6c81e67cffadf57f6939b8940)\]. These methods aim to proactively allocate resources based on workload patterns, reducing the likelihood of cold starts.
