## Related Works

Efficient memory management and KV cache optimization have been central to improving the performance and scalability of large language model (LLM) serving systems. Prior work has focused on reducing memory usage through techniques such as quantization, cache eviction policies, and compression algorithms. For instance, \[[1](http://arxiv.org/abs/2309.06180)\] introduced PagedAttention, an attention algorithm inspired by virtual memory paging, which enables near-zero waste in KV cache memory and flexible sharing across requests. This approach significantly improves throughput, particularly for longer sequences and more complex decoding algorithms. Similarly, \[[2](http://arxiv.org/abs/2402.02750)\] proposed KIVI, a tuning-free 2bit quantization method for KV cache that reduces peak memory usage by 2.6×, allowing up to 4× larger batch sizes and substantial throughput improvements. These methods highlight the importance of reducing memory overhead for efficient LLM serving.

KV cache compression and management have also been explored to address memory bottlenecks. \[[3](http://arxiv.org/abs/2305.17118)\] introduced Scissorhands, which leverages the persistence of importance hypothesis to maintain a fixed memory budget for KV cache without model fine-tuning. This method reduces memory usage by up to 5× while preserving model quality. Furthermore, \[[4](http://arxiv.org/abs/2309.17453)\] proposed StreamingLLM, which enables LLMs to generalize to longer sequences by exploiting the attention sink phenomenon, where initial tokens have strong attention scores. This allows for efficient streaming inference with up to 4 million tokens. Additionally, \[[5](http://arxiv.org/abs/2306.14048)\] introduced H2O, a KV cache eviction policy based on the observation that a small subset of tokens, called heavy hitters, contributes most to attention scores. This approach reduces memory footprint and improves throughput by up to 29× on certain models.

Recent work has also focused on adaptive and workload-aware cache management. \[[6](http://arxiv.org/abs/2404.14469)\] introduced SnapKV, which minimizes KV cache size by identifying and compressing important KV positions for each attention head. This method achieves a 3.6× increase in generation speed and an 8.2× improvement in memory efficiency. \[[7](http://arxiv.org/abs/2310.01801)\] proposed adaptive KV cache compression, which dynamically constructs the cache based on the structure of attention modules. This method reduces GPU memory consumption with negligible quality loss. \[[8](http://arxiv.org/abs/2402.18096)\] further explored importance-aware mixed precision quantization, where important KV pairs are retained at higher precision to preserve generation quality, while less important ones are stored at lower precision. This approach balances compression ratio and performance effectively.

### <a id='category-kv-cache-optimization-techniques'></a>KV Cache Optimization Techniques: 5 papers found.
The category "KV Cache Optimization Techniques" encompasses several approaches aimed at reducing the memory footprint and improving the efficiency of key-value (KV) caches in large language models (LLMs). These techniques address the significant memory constraints posed by the exponential growth of KV caches with sequence length and batch size \[[3](http://arxiv.org/abs/2305.17118)\]. One approach, Scissorhands, leverages the hypothesis of the persistence of importance, where pivotal tokens that influence future generations are prioritized in the KV cache \[[3](http://arxiv.org/abs/2305.17118)\]. Another method, Heavy Hitter Oracle (H$_2$O), identifies and retains tokens that contribute most to attention scores, termed "Heavy Hitters," while dynamically balancing recent and critical tokens \[[5](http://arxiv.org/abs/2306.14048)\]. SnapKV, on the other hand, focuses on the consistent attention patterns of each head, enabling automatic compression by selecting clustered important KV positions \[[6](http://arxiv.org/abs/2404.14469)\]. Adaptive KV cache compression, as proposed in FastGen, introduces a plug-and-play method that tailors cache construction based on the attention structure, evicting unnecessary tokens while preserving essential ones \[[7](http://arxiv.org/abs/2310.01801)\]. InfiniGen further enhances KV cache management by speculating essential tokens for future attention layers, reducing fetch overhead in offloading-based systems \[[9](http://arxiv.org/abs/2406.19707)\]. These methods collectively highlight the importance of workload-aware strategies and fine-tuning-free approaches to optimize KV cache usage, ensuring efficient inference while maintaining model performance \[[3](http://arxiv.org/abs/2305.17118)\]\[[5](http://arxiv.org/abs/2306.14048)\]\[[6](http://arxiv.org/abs/2404.14469)\]\[[7](http://arxiv.org/abs/2310.01801)\]\[[9](http://arxiv.org/abs/2406.19707)\].

[Snippet]: «Deploying Large Language Models (LLMs) in streaming applications such as multi-round dialogue, where long interactions are expected, is urgently needed but poses two major challenges. Firstly, during the decoding stage, caching previous tokens' Key and Value states (KV) consumes extensive memory. Secondly, popular LLMs cannot generalize to longer texts than the training sequence length. Window attention, where only the most recent KVs are cached, is a natural approach -- but we show that it fails when the text length surpasses the cache size. We observe an interesting phenomenon, namely attention sink, that keeping the KV of initial tokens will largely recover the performance of window attention. In this paper, we first demonstrate that the emergence of attention sink is due to the strong attention scores towards initial tokens as a"sink"even if they are not semantically important. Based on the above analysis, we introduce StreamingLLM, an efficient framework that enables LLMs trained with a finite length attention window to generalize to infinite sequence lengths without any fine-tuning. We show that StreamingLLM can enable Llama-2, MPT, Falcon, and Pythia to perform stable and efficient language modeling with up to 4 million tokens and more. In addition, we discover that adding a placeholder token as a dedicated attention sink during pre-training can further improve streaming deployment. In streaming settings, StreamingLLM outperforms the sliding window recomputation baseline by up to 22.2x speedup. Code and datasets are provided at https://github.com/mit-han-lab/streaming-llm.»
