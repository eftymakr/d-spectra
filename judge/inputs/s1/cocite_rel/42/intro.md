## Related Works

The growing adoption of cloud-native applications has led to increased interest in optimizing both resource usage and financial expenditures. Several studies have explored the use of container orchestration platforms like Kubernetes for managing workloads and improving operational efficiency. For instance, Kubernetes has been widely adopted for deploying and managing containerized applications due to its robust scheduling, scaling, and monitoring capabilities \[[4](https://www.semanticscholar.org/paper/b5634b15badc73f3cda72b960fd51ef03ac1265d)\]. These features enable efficient resource utilization and support the development of scalable, resilient applications \[[11](http://arxiv.org/abs/2010.10350)\]. However, the financial implications of using such platforms, particularly in terms of network costs, remain underexplored in existing literature.

FinOps, an emerging discipline that combines financial management with cloud operations, has gained traction as a way to optimize cloud costs and improve accountability in cloud spend \[[1](http://arxiv.org/abs/2501.14753)\]. ABACUS, a FinOps solution, addresses these challenges by setting budgets, enforcing them through blocking new deployments, and alerting teams when spending exceeds thresholds \[[1](http://arxiv.org/abs/2501.14753)\]. This approach aligns with the broader goal of achieving cost visibility and optimization in cloud environments. While FinOps has been applied to general cloud cost management, its application to network costs within Kubernetes clusters is a relatively new area of research.

Several studies have examined the performance and resource management of containerized applications in cloud-native environments. For example, the use of Docker and Kubernetes for deploying compute-intensive workloads has been shown to significantly reduce completion times when optimized for resource allocation \[[11](http://arxiv.org/abs/2010.10350)\]. Additionally, the integration of Kubernetes with cloud platforms like Google Cloud Platform has enabled faster application development and management through automated container orchestration \[[4](https://www.semanticscholar.org/paper/b5634b15badc73f3cda72b960fd51ef03ac1265d)\]. These findings highlight the importance of resource scheduling and management in achieving both performance and cost efficiency.

In the context of network costs, the paper under review contributes to the FinOps discipline by investigating how containerized applications running on Kubernetes clusters impact network expenditures. This is a critical area, as network costs can constitute a significant portion of cloud expenses, especially for applications that require high bandwidth or frequent data transfers \[[3](http://arxiv.org/abs/2307.12479)\]. While existing studies have focused on system-level optimizations for resource efficiency \[[1](http://arxiv.org/abs/2501.14753)\], this work extends the discussion to include network cost analysis, which is essential for a comprehensive understanding of cloud financial management.

Moreover, the use of Kubernetes for managing microservices-based applications has been extensively studied, with a focus on availability, scalability, and fault tolerance \[[2](https://www.semanticscholar.org/paper/18a720c86ed6e166c26f7d39490bfd11b93ea3ec)\]. These studies emphasize the importance of efficient scheduling and resource allocation in Kubernetes to ensure high availability and performance. However, the financial implications of these configurations, particularly in terms of network costs, have not been thoroughly examined in prior work \[[3](http://arxiv.org/abs/2307.12479)\].
