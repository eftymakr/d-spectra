## Related Works

Cold start latency remains a critical challenge in serverless computing, impacting both performance and resource utilization \[[1](http://arxiv.org/abs/2406.11734)\]. Several studies have explored this issue, proposing various mitigation strategies. For instance, \[[1](http://arxiv.org/abs/2406.11734)\] highlights that inefficient library initialization and usage are major contributors to cold start latency in Python-based serverless applications. This work introduces LibProf, a Python profiler that identifies inefficient library initializations through dynamic program analysis and statistical sampling. LibProf's evaluations on 15 serverless applications showed a 2.26x speedup in cold-start execution time and a 1.51x reduction in memory usage \[[1](http://arxiv.org/abs/2406.11734)\]. 

Similarly, \[[8](http://arxiv.org/abs/1903.12221)\] addresses the cold start problem by maintaining a pool of warm containers, reducing P99 response time by 85% for a single instance pool. This approach leverages pre-provisioned containers to minimize the latency associated with on-demand provisioning. Another study, \[[14](http://arxiv.org/abs/2108.11240)\], proposes Pagurus, a runtime container management system that enables inter-action container sharing. By borrowing warm containers from other actions, Pagurus eliminates long cold startup times, allowing actions to start in as little as 10ms \[[14](http://arxiv.org/abs/2108.11240)\].

In addition to container-based solutions, \[[6](http://arxiv.org/abs/2105.13894)\] evaluates snapshot-based methods such as Prebaking and SEUSS to mitigate cold starts. The study shows that Prebaking significantly reduces startup time for functions with varying complexity, with a 69% improvement in Markdown function processing time \[[6](http://arxiv.org/abs/2105.13894)\]. \[[15](http://arxiv.org/abs/2309.15471)\] introduces ProFaaStinate, which delays asynchronous function calls to optimize platform performance. This approach reduces request response latency by up to 54% in a document preparation use case \[[15](http://arxiv.org/abs/2309.15471)\].

Machine learning and time series forecasting have also been applied to cold start mitigation. \[[4](http://arxiv.org/abs/2206.15176)\] uses SARIMA to predict incoming request times and dynamically adjust container counts, reducing resource wastage and function launching time. \[[9](http://arxiv.org/abs/2304.00396)\] proposes a temporal convolutional network (TCN) to predict function instance arrivals, achieving superior performance compared to other machine learning models \[[9](http://arxiv.org/abs/2304.00396)\]. \[[11](http://arxiv.org/abs/2504.11338)\] leverages Transformer models to accurately model function initialization delays, reducing cold start times by up to 79% \[[11](http://arxiv.org/abs/2504.11338)\].

Application-level optimizations have also been explored. \[[10](http://arxiv.org/abs/2207.08175)\] presents FaaSLight, which separates indispensable code from FaaS applications to reduce code loading latency.
