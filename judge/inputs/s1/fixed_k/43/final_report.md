## Related Works

Performance modeling for large-scale machine learning systems has been an active research area, with several studies focusing on the challenges of accurately predicting execution times and optimizing resource utilization. Early work on performance modeling for dense linear algebra algorithms emphasized the importance of ranking equivalent algorithms based on their performance characteristics, rather than creating highly accurate models for individual algorithms \[[6](http://arxiv.org/abs/1209.2364)\]. This approach laid the groundwork for more sophisticated models that could generalize across different architectures and workloads.

Recent advances in performance modeling have leveraged machine learning techniques to improve prediction accuracy. For instance, the LLMPerf study explored the use of large language models (LLMs) to estimate performance for OpenCL device source programs, achieving a mean absolute percentage error of 24.25% on a generated validation set \[[1](http://arxiv.org/abs/2503.11244)\]. However, this work also highlighted the difficulties in applying LLMs to performance modeling tasks, particularly in the context of complex and heterogeneous hardware environments.

The LLM-Pilot system further advanced the field by introducing a framework for characterizing and predicting the performance of LLM inference services across different hardware configurations \[[2](http://arxiv.org/abs/2410.02425)\]. This system not only benchmarks LLM inference services under realistic workloads but also learns predictive models to recommend cost-effective hardware for new models. LLM-Pilot demonstrated significant improvements over existing methods, achieving 33% higher performance satisfaction and 60% lower costs.

In the domain of distributed training, the Proteus simulator was introduced to model the performance of complex parallelization strategies by simulating execution time and runtime behaviors \[[5](http://arxiv.org/abs/2306.02267)\]. Proteus uses a hierarchical top-aware executor to simulate comp-comm overlap and bandwidth sharing, achieving a 3.0% average prediction error. This work highlights the importance of simulating complex runtime behaviors to accurately model distributed training performance.

Additionally, the work on distributed training of deep learning models has emphasized the need for scalable performance modeling techniques that can handle the increasing complexity of modern training systems \[[9](http://arxiv.org/abs/2007.03970)\]. The CM-DARE framework, for example, enables the analysis of distributed training performance under diverse cluster configurations, demonstrating the feasibility of using regression-based models to predict training speed and overhead \[[8](http://arxiv.org/abs/2004.03072)\].

The AIWC tool has also contributed to the field by providing architecture-independent features for characterizing OpenCL kernels, enabling accurate performance prediction across different compute devices \[[12](http://arxiv.org/abs/1811.00156)\]. This methodology has shown high accuracy, with an average error of just 1.2% in predicting execution times for a wide range of kernels.

### <a id='category-performance-modeling-techniques'></a>Performance Modeling Techniques: 3 papers found.
Performance modeling techniques for deep learning and high-performance computing have seen significant advancements, with a focus on accurately capturing and predicting execution behaviors in complex environments. Recent work has emphasized the importance of modeling both active and idle times on GPUs, as these factors significantly influence overall performance \[[1](http://arxiv.org/abs/2503.11244)\]. For instance, studies have shown that device idle time can be as critical as active time in determining the efficiency of GPU training for models like DLRM, necessitating the use of heuristic-based and ML-based kernel performance models to address this \[[3](http://arxiv.org/abs/2201.07821)\]. Additionally, there is a growing need for customizable and cross-machine performance models that can adapt to different architectures and workloads, enabling accurate predictions across diverse hardware platforms \[[4](http://arxiv.org/abs/1904.09538)\]. These models often rely on symbolic gathering of performance-relevant operation counts and mathematical formulations to ensure both accuracy and generalizability \[[4](http://arxiv.org/abs/1904.09538)\]. Furthermore, the ability to rank algorithms based on their performance, rather than just predicting individual execution times, has also been explored, particularly in the context of dense linear algebra routines, where hierarchical structures and library dependencies play a crucial role \[[6](http://arxiv.org/abs/1209.2364)\]. Such approaches highlight the evolving landscape of performance modeling, where the integration of trace-driven analysis and statistical modeling is becoming increasingly essential for guiding optimization efforts and system-level studies.

[Snippet]: «OpenCL is an attractive programming model for heterogeneous high-performance computing systems, with wide support from hardware vendors and significant performance portability. To support efficient scheduling on HPC systems it is necessary to perform accurate performance predictions for OpenCL workloads on varied compute devices, which is challenging due to diverse computation, communication and memory access characteristics which result in varying performance between devices. The Architecture Independent Workload Characterization (AIWC) tool can be used to characterize OpenCL kernels according to a set of architecture-independent features. This work presents a methodology where AIWC features are used to form a model capable of predicting accelerator execution times. We used this methodology to predict execution times for a set of 37 computational kernels running on 15 different devices representing a broad range of CPU, GPU and MIC architectures. The predictions are highly accurate, differing from the measured experimental run-times by an average of only 1.2%, and correspond to actual execution time mispredictions of 9 ps to 1 sec according to problem size. A previously unencountered code can be instrumented once and the AIWC metrics embedded in the kernel, to allow performance prediction across the full range of modelled devices. The results suggest that this methodology supports correct selection of the most appropriate device for a previously unencountered code, which is highly relevant to the HPC scheduling setting.»
