## Related Works

The growing adoption of cloud-native technologies, particularly Kubernetes, has spurred extensive research into optimizing both performance and security in containerized environments. Prior work has focused on system-level optimizations for resource efficiency and cost management, but network cost analysis in Kubernetes clusters remains underexplored \[[1](http://arxiv.org/abs/2006.15275)\]. This gap is addressed in this paper, which investigates network usage and cost implications of containerized applications running on Kubernetes clusters.

Several studies have examined Kubernetes security practices, highlighting the importance of role-based access control (RBAC) and regular patching to mitigate vulnerabilities \[[1](http://arxiv.org/abs/2006.15275)\]. Additionally, security misconfigurations in Kubernetes manifests have been identified as a significant risk, with 11 categories of misconfigurations reported in an empirical study of 2,039 manifests \[[2](https://www.semanticscholar.org/paper/61020665f9134e56009b6e10606fc21348f59d53)\]. These misconfigurations can lead to severe security breaches, as demonstrated by incidents at Tesla \[[1](http://arxiv.org/abs/2006.15275)\]. Furthermore, research has shown that security defects in Kubernetes manifests are under-reported, with only 0.79% of commits being security-related \[[9](https://www.semanticscholar.org/paper/3c2ac07d840d148085dc50dfa5bb9aebd33fabc9)\]. This underscores the need for rigorous security practices and automated tools to detect and mitigate misconfigurations.

In the realm of cost optimization, FinOps has emerged as a discipline combining financial management and cloud operations to reduce cloud expenditures \[[3](http://arxiv.org/abs/2501.14753)\]. While prior work has explored system-level optimizations for resource efficiency, this paper extends the discussion to network costs, which are often overlooked in FinOps strategies \[[1](http://arxiv.org/abs/2006.15275)\]. A FinOps solution called ABACUS has been proposed to optimize cloud costs by setting budgets, enforcing them through deployment blocking, and alerting teams when thresholds are exceeded \[[3](http://arxiv.org/abs/2501.14753)\]. This aligns with the broader goal of this paper to provide actionable insights into network cost optimization for Kubernetes-based applications.

The scheduling of containerized workloads on Kubernetes has also been a focus of recent research. Studies have identified challenges in maintaining task scheduling order when integrating workflow systems with Kubernetes, leading to inefficiencies in execution \[[4](http://arxiv.org/abs/2207.01222)\]. To address this, KubeAdaptor was proposed as a docking framework that ensures consistency in task scheduling order between workflow systems and Kubernetes \[[4](http://arxiv.org/abs/2207.01222)\]. Additionally, adaptive resource allocation strategies have been developed to improve resource utilization and reduce waste in Kubernetes-based workflow engines \[[17](http://arxiv.org/abs/2301.08409)\].

Finally, the security of Kubernetes deployments has been the subject of comparative studies, revealing differences in security postures across on-premises and cloud-managed clusters \[[8](https://www.semanticscholar.org/paper/00f68d85141a6981a05bb57b9e84610b2ef61941)\]. These findings highlight the need for continuous monitoring and automated security tools to ensure compliance and mitigate risks.
