## Related Works

The growing adoption of cloud-native technologies, particularly Kubernetes, has spurred extensive research into optimizing both performance and security in containerized environments. Prior work has focused on system-level optimizations for resource efficiency and cost management, but network cost analysis in Kubernetes clusters remains underexplored \[[1](http://arxiv.org/abs/2006.15275)\]. This gap is addressed in this paper, which investigates network usage and cost implications of containerized applications running on Kubernetes clusters.

Several studies have examined Kubernetes security practices, highlighting the importance of role-based access control (RBAC) and regular patching to mitigate vulnerabilities \[[1](http://arxiv.org/abs/2006.15275)\]. Additionally, security misconfigurations in Kubernetes manifests have been identified as a significant risk, with 11 categories of misconfigurations reported in an empirical study of 2,039 manifests \[[2](https://www.semanticscholar.org/paper/61020665f9134e56009b6e10606fc21348f59d53)\]. These misconfigurations can lead to severe security breaches, as demonstrated by incidents at Tesla \[[1](http://arxiv.org/abs/2006.15275)\]. Furthermore, research has shown that security defects in Kubernetes manifests are under-reported, with only 0.79% of commits being security-related \[[9](https://www.semanticscholar.org/paper/3c2ac07d840d148085dc50dfa5bb9aebd33fabc9)\]. This underscores the need for rigorous security practices and automated tools to detect and mitigate misconfigurations.

In the realm of cost optimization, FinOps has emerged as a discipline combining financial management and cloud operations to reduce cloud expenditures \[[3](http://arxiv.org/abs/2501.14753)\]. While prior work has explored system-level optimizations for resource efficiency, this paper extends the discussion to network costs, which are often overlooked in FinOps strategies \[[1](http://arxiv.org/abs/2006.15275)\]. A FinOps solution called ABACUS has been proposed to optimize cloud costs by setting budgets, enforcing them through deployment blocking, and alerting teams when thresholds are exceeded \[[3](http://arxiv.org/abs/2501.14753)\]. This aligns with the broader goal of this paper to provide actionable insights into network cost optimization for Kubernetes-based applications.

The scheduling of containerized workloads on Kubernetes has also been a focus of recent research. Studies have identified challenges in maintaining task scheduling order when integrating workflow systems with Kubernetes, leading to inefficiencies in execution \[[4](http://arxiv.org/abs/2207.01222)\]. To address this, KubeAdaptor was proposed as a docking framework that ensures consistency in task scheduling order between workflow systems and Kubernetes \[[4](http://arxiv.org/abs/2207.01222)\]. Additionally, adaptive resource allocation strategies have been developed to improve resource utilization and reduce waste in Kubernetes-based workflow engines \[[17](http://arxiv.org/abs/2301.08409)\].

Finally, the security of Kubernetes deployments has been the subject of comparative studies, revealing differences in security postures across on-premises and cloud-managed clusters \[[8](https://www.semanticscholar.org/paper/00f68d85141a6981a05bb57b9e84610b2ef61941)\]. These findings highlight the need for continuous monitoring and automated security tools to ensure compliance and mitigate risks.

The category "Empirical Studies on Kubernetes Security and Misconfigurations" encompasses a range of research focused on identifying and mitigating security vulnerabilities and misconfigurations in Kubernetes environments. These studies highlight that while Kubernetes offers significant benefits in terms of automation, scalability, and deployment efficiency, its complexity and configuration options can introduce security risks if not properly managed \[[1](http://arxiv.org/abs/2006.15275)\]. For instance, the systematization of security practices such as role-based access control (RBAC), regular patching, and pod-specific security policies is emphasized as critical for reducing vulnerabilities \[[1](http://arxiv.org/abs/2006.15275)\]. Additionally, empirical analyses reveal that security defects in Kubernetes manifests are under-reported, with only 0.79% of commits being security-related, indicating a need for more rigorous research into identifying and addressing these issues \[[3](http://arxiv.org/abs/2501.14753)\]. Furthermore, the use of Helm charts for Kubernetes deployments has been scrutinized, with findings showing that many charts contain outdated container images and are exposed to vulnerabilities, thereby jeopardizing the security of the applications they support \[[6](http://arxiv.org/abs/2307.12479)\]. The studies also underscore the importance of centralized logging and monitoring solutions to detect misconfigurations and improve system reliability \[[5](https://www.semanticscholar.org/paper/18a720c86ed6e166c26f7d39490bfd11b93ea3ec)\]. Overall, these works collectively emphasize the necessity of adopting comprehensive security practices and continuous monitoring to ensure the secure and efficient operation of Kubernetes-based systems.

### <a id='category-security-misconfigurations-in-kubernetes-manifests'></a>Security Misconfigurations in Kubernetes Manifests: 2 papers found.
Security misconfigurations in Kubernetes manifests have been identified as a critical area of concern, with studies revealing that such misconfigurations can lead to significant security vulnerabilities and potential breaches \[[1](http://arxiv.org/abs/2006.15275)\]. Research has shown that these misconfigurations often include issues like absent resource limits, missing security contexts, and improper settings for features such as hostIPC, which can expose clusters to attacks \[[1](http://arxiv.org/abs/2006.15275)\]. These vulnerabilities are not only prevalent in open-source repositories but also affect the reliability and security of applications deployed in domains such as edge computing and high-performance computing \[[1](http://arxiv.org/abs/2006.15275)\]. Furthermore, the impact of these misconfigurations extends to entities involved in mesh-related load balancing and stateful application provisioning, highlighting the need for rigorous security practices during Kubernetes deployment \[[1](http://arxiv.org/abs/2006.15275)\]. Additional studies emphasize that misconfigurations can be exploited for denial of service attacks and other security threats, underscoring the importance of adhering to security best practices and employing tools like static analysis to detect and mitigate these issues \[[2](https://www.semanticscholar.org/paper/61020665f9134e56009b6e10606fc21348f59d53)\]. Practitioners have also shown willingness to address these misconfigurations, with over 60% of reported issues being resolved, indicating a growing awareness and response to the security challenges in Kubernetes environments \[[1](http://arxiv.org/abs/2006.15275)\].

### <a id='category-finops-frameworks-and-cost-optimization'></a>FinOps Frameworks and Cost Optimization: 2 papers found.
FinOps frameworks and cost optimization have emerged as critical areas of research, particularly with the increasing reliance on cloud infrastructure for modern applications. These frameworks aim to bridge the gap between financial management and cloud operations, enabling organizations to achieve greater visibility into cloud spend and optimize costs effectively \[[3](http://arxiv.org/abs/2501.14753)\]. One such solution is ABACUS, which automates budget analysis and enforces cost controls by blocking new deployments that exceed predefined thresholds, while also providing cost estimates through Infrastructure-as-Code practices \[[3](http://arxiv.org/abs/2501.14753)\]. Additionally, the rapid growth of AI and machine learning workloads has intensified the need for cost optimization strategies, with GPU compute now accounting for a significant portion of technical budgets \[[6](http://arxiv.org/abs/2307.12479)\]. Techniques like model quantization, GPU instance selection, and inference optimization have been shown to reduce costs substantially, with some organizations achieving up to 90% savings through strategic approaches \[[6](http://arxiv.org/abs/2307.12479)\]. These efforts highlight the evolving nature of FinOps, which now extends beyond traditional cloud cost management to include specialized strategies for AI/ML workloads. The integration of measurement analysis, experimentation, and cost modeling further underscores the importance of data-driven decision-making in optimizing both resource efficiency and financial outcomes \[[3](http://arxiv.org/abs/2501.14753)\]. As the field continues to evolve, future research is likely to focus on automated optimization, sustainability, and the development of more sophisticated tools to support FinOps practices \[[3](http://arxiv.org/abs/2501.14753)\]\[[6](http://arxiv.org/abs/2307.12479)\].

### <a id='category-container-scheduling-and-workflow-integration'></a>Container Scheduling and Workflow Integration: 3 papers found.
The category "Container Scheduling and Workflow Integration" explores the challenges and solutions for aligning workflow systems with Kubernetes to ensure consistent task scheduling and improved execution efficiency \[[1](http://arxiv.org/abs/2006.15275)\]. A key issue is that Kubernetes' inherent scheduling mechanism does not follow the optimized task execution order used by workflow systems, leading to inefficiencies in workflow execution \[[1](http://arxiv.org/abs/2006.15275)\]. To address this, researchers have proposed frameworks like KubeAdaptor, which acts as a docking framework to enable workflow containerization on Kubernetes, ensuring consistency in task scheduling order \[[1](http://arxiv.org/abs/2006.15275)\]. This work highlights the need for tighter integration between workflow systems and Kubernetes to enhance performance and resource utilization \[[1](http://arxiv.org/abs/2006.15275)\]. Additionally, studies on Kubernetes scheduling emphasize the importance of designing scheduling algorithms based on Quality of Service (QoS) parameters to optimize resource allocation, response time, and energy consumption \[[2](https://www.semanticscholar.org/paper/61020665f9134e56009b6e10606fc21348f59d53)\]. These efforts underscore the growing interest in improving container orchestration and workflow integration to support modern cloud-native applications \[[1](http://arxiv.org/abs/2006.15275)\]\[[2](https://www.semanticscholar.org/paper/61020665f9134e56009b6e10606fc21348f59d53)\].

### <a id='category-resource-allocation-strategies-in-kubernetes'></a>Resource Allocation Strategies in Kubernetes: 3 papers found.
The category "Resource Allocation Strategies in Kubernetes" explores how Kubernetes can be optimized for performance, scalability, and resource efficiency, particularly in edge and cloud-native environments. Research indicates that Kubernetes' reliance on etcd for cluster state management can lead to increased write latency and reduced throughput at scale, impacting availability and performance \[[1](http://arxiv.org/abs/2006.15275)\]. To address these limitations, studies propose shifting from strong consistency to an eventually consistent approach, which enhances performance and scalability for edge deployments \[[1](http://arxiv.org/abs/2006.15275)\]. Additionally, the adoption of cloud-native applications, supported by technologies like Kubernetes, has driven the need for more efficient resource management, especially for compute-intensive workloads such as big data and deep learning \[[2](https://www.semanticscholar.org/paper/61020665f9134e56009b6e10606fc21348f59d53)\]. These applications often face challenges with resource allocation, including over- and under-provisioning, which can lead to resource waste and inefficiencies \[[3](http://arxiv.org/abs/2501.14753)\]. To mitigate these issues, adaptive resource allocation schemes, such as ARAS, have been introduced to improve resource discovery, evaluation, and allocation, resulting in significant performance gains and better resource utilization \[[3](http://arxiv.org/abs/2501.14753)\]. These strategies highlight the ongoing evolution of Kubernetes to meet the demands of modern, dynamic, and performance-critical workloads in cloud-native environments.
