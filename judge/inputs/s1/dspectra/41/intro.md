## Related Works

Serverless computing has gained significant traction due to its ability to abstract away server management, enabling automatic scaling, efficient resource utilization, and cost-effective pricing models \[[14](http://arxiv.org/abs/1706.03178)\]. However, the cold-start latency issue remains a critical challenge, impacting end-to-end performance \[[18](http://arxiv.org/abs/1903.12221)\]. This problem arises when a function is invoked and no pre-provisioned "warm" container is available, leading to increased initialization time and overhead \[[18](http://arxiv.org/abs/1903.12221)\]. Several approaches have been proposed to mitigate this issue, ranging from container pre-warming strategies to advanced machine learning-based solutions.

Early work focused on reducing cold start latency by maintaining a pool of warm containers, anticipating future requests \[[18](http://arxiv.org/abs/1903.12221)\]. This approach, however, can lead to resource inefficiencies if the warm container window is too long or too short \[[3](https://www.semanticscholar.org/paper/b99668ae35c4b6796b827657a318fe4b84a757ff)\]. To address this, adaptive models have been proposed to predict the optimal length of the idle container window and the number of pre-warmed containers required, based on historical function invocation patterns \[[3](https://www.semanticscholar.org/paper/b99668ae35c4b6796b827657a318fe4b84a757ff)\]. These models use deep neural networks and LSTM to improve prediction accuracy \[[3](https://www.semanticscholar.org/paper/b99668ae35c4b6796b827657a318fe4b84a757ff)\].

Recent research has also explored the use of reinforcement learning to dynamically adjust container warm-up strategies based on function invocation patterns \[[6](https://www.semanticscholar.org/paper/27cd21426fe51167dd6ac79d1c83db55a07a2046)\]. This two-layer approach first identifies invocation patterns using reinforcement learning and then predicts future invocation times using LSTM to determine the required pre-warmed containers \[[6](https://www.semanticscholar.org/paper/27cd21426fe51167dd6ac79d1c83db55a07a2046)\]. The results showed a reduction in memory consumption and improved execution invocations on prewarmed containers \[[6](https://www.semanticscholar.org/paper/27cd21426fe51167dd6ac79d1c83db55a07a2046)\].

Another line of work focuses on reducing the number of cold starts by leveraging application knowledge to trigger container provisioning before the function is invoked \[[13](https://www.semanticscholar.org/paper/1447da2da7c926dc68e31a89461409d09b08d77e)\]. This approach, implemented as part of a lightweight choreography middleware, significantly reduces cold starts while maintaining minimal cost overhead \[[13](https://www.semanticscholar.org/paper/1447da2da7c926dc68e31a89461409d09b08d77e)\].

Additionally, there are efforts to optimize the initialization process by identifying and eliminating unnecessary library loading \[[16](http://arxiv.org/abs/2207.08175)\]. This is particularly relevant to the current study, as it highlights the inefficiencies caused by loading rarely used libraries during cold starts \[[16](http://arxiv.org/abs/2207.08175)\]. While static analysis techniques can identify unreachable libraries, they often fail to account for workload-dependent inefficiencies \[[16](http://arxiv.org/abs/2207.08175)\].

Furthermore, the use of checkpointing and state restoration has been proposed to reduce cold start latency by avoiding the need to initialize the runtime environment from scratch \[[5](https://www.semanticscholar.org/paper/f14446970a5ed7145a6d350e1aff07ca203cece8)\]. This approach, known as "init-less" booting, enables sub-millisecond startup times by restoring a virtualization-based function instance from a checkpoint image \[[5](https://www.semanticscholar.org/paper/f14446970a5ed7145a6d350e1aff07ca203cece8)\].
