## Related Works

Modern databases often trade strong transaction isolation for weak isolation levels to achieve high throughput and partition tolerance, which is a key design choice in distributed systems \[[1](http://arxiv.org/abs/2107.11458)\]. However, this trade-off has led to the emergence of isolation bugs, which can compromise data consistency \[[1](http://arxiv.org/abs/2107.11458)\]. Black-box testing has emerged as a prominent technique for detecting such bugs by verifying whether transaction histories adhere to prescribed isolation levels \[[1](http://arxiv.org/abs/2107.11458)\]. 

Several studies have explored the efficiency of black-box isolation testing, particularly for weak isolation levels. For example, Plume was introduced as the first efficient and complete black-box checker for weak isolation levels, supporting read committed, read atomicity, and transactional causal consistency \[[3](https://www.semanticscholar.org/paper/cbe191bda20907994d45bc835d20446968370add)\]. It leverages vectors and tree clocks to accelerate isolation checking, demonstrating effectiveness in detecting anomalies in production databases \[[3](https://www.semanticscholar.org/paper/cbe191bda20907994d45bc835d20446968370add)\]. Similarly, MonkeyDB was designed as a mock storage system to test correctness under weak isolation levels, supporting key-value interfaces and SQL queries under various isolation levels \[[6](https://www.semanticscholar.org/paper/615ff2896b52bee2cbfd64ced324106a29b73397)\]. It uses logical specifications to compute possible return values for read operations, enabling robust testing of application resilience to weak isolation behaviors \[[6](https://www.semanticscholar.org/paper/615ff2896b52bee2cbfd64ced324106a29b73397)\].

The complexity of isolation testing has also been a focus of research. While testing strong isolation levels is known to be NP-complete, weak isolation levels have been shown to be testable in polynomial time, enabling scalability of testing tools \[[1](http://arxiv.org/abs/2107.11458)\]. However, existing testers often have large polynomial complexity, limiting their applicability to large-scale workloads \[[1](http://arxiv.org/abs/2107.11458)\]. To address this, the paper introduces AWDIT, a highly-efficient and provably optimal tester for weak isolation levels, achieving time complexities of $O(n^(3/2))$, $O(n^(3/2))$, and $O(n \cdot k)$ for Read Committed (RC), Read Atomic (RA), and Causal Consistency (CC), respectively \[[1](http://arxiv.org/abs/2107.11458)\]. This represents a significant improvement over the state of the art. Furthermore, AWDIT is shown to be essentially optimal, with a conditional lower bound of $n^(3/2)$ for any weak isolation level between RC and CC \[[1](http://arxiv.org/abs/2107.11458)\].
