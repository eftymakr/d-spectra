## Related Works

Cold start latency remains a critical challenge in serverless computing, impacting both the responsiveness and efficiency of function-as-a-service (FaaS) platforms \[[1](https://www.semanticscholar.org/paper/f14446970a5ed7145a6d350e1aff07ca203cece8)\]. Existing research has explored various strategies to mitigate this issue, ranging from optimizing container initialization to leveraging predictive models for resource pre-warming. For instance, Catalyzer introduces a novel approach to serverless sandboxing by restoring function instances from checkpoint images, thereby eliminating initialization overhead and achieving sub-millisecond startup times \[[2](https://www.semanticscholar.org/paper/d911b03bfda4fc6fc92f8080bb81b3a967d6a9e7)\]. Similarly, FaaSLight focuses on reducing code loading latency by identifying and loading only the necessary code for function execution, resulting in significant reductions in cold-start latency \[[3](https://www.semanticscholar.org/paper/81b8db7a20f1aa859143c716b38a1443e3eca9a0)\]. These methods, however, often rely on platform-specific modifications or require changes to the underlying infrastructure, limiting their applicability across different serverless environments.

Other approaches focus on reducing the frequency of cold starts through adaptive resource management. For example, the Adaptive Warm-Up Strategy (AWUS) predicts function invocation times and pre-warms containers, while the Adaptive Container Pool Scaling Strategy (ACPSS) dynamically adjusts the container pool size to minimize resource waste \[[4](https://www.semanticscholar.org/paper/c066cf85b94846ddc057a113ce110e045f587375)\]. These strategies aim to balance the trade-off between reducing cold start latency and minimizing resource consumption. Additionally, the Reinforcement Learning-based approach proposed in \[[5](http://arxiv.org/abs/2207.08175)\] uses Q-Learning to analyze function invocation patterns and optimize the number of pre-warmed instances, demonstrating the potential of machine learning in improving cold start mitigation.

Prebaking functions by restoring snapshots from previously executed processes has also been explored as a means to accelerate cold starts. This technique, evaluated using the CRIU tool, showed improvements in startup times for various functions, with the most significant gains observed for functions with high runtime initialization overhead \[[6](http://arxiv.org/abs/2003.03423)\]. Similarly, the FaasCache system introduces a caching-inspired keep-alive policy that reduces cold-start overhead by more than 3× compared to current approaches, leveraging reuse distances and hit-ratio curves for resource provisioning \[[7](https://www.semanticscholar.org/paper/96d4fea8d034a7605af936f2e2b6a44becdf6585)\]. These methods highlight the importance of maintaining warm containers and efficiently managing resource allocation to minimize cold start delays.

The cold start problem is further exacerbated in function chain deployments, where cascading delays occur due to the sequential provisioning of resources for each function in the workflow. Xanadu addresses this issue by implementing speculative and just-in-time provisioning, effectively eliminating cascading cold starts with minimal overhead \[[8](https://www.semanticscholar.org/paper/ab1c0062964a2df3d7f8d11da4a774530286b801)\]. Meanwhile, the WLEC architecture introduces a modified S2LRU structure to minimize cold start time, achieving a 31% reduction in average cold start duration and 50% less memory consumption compared to other methods
