## Related Works

Modern databases often trade strong transaction isolation for weak isolation guarantees to achieve low latency and high throughput, particularly in distributed systems \[[1](http://arxiv.org/abs/1908.04509)\]. This trade-off has led to the emergence of weak isolation levels such as Read Committed (RC), Read Atomic (RA), and Causal Consistency (CC), which are widely used in production databases \[[2](https://www.semanticscholar.org/paper/cbe191bda20907994d45bc835d20446968370add)\]. However, these weaker isolation levels can introduce bugs that violate data consistency \[[3](https://www.semanticscholar.org/paper/9f96a48d2bc0e77004b32960495685be6c301c63)\]. For example, several production databases have been found to suffer from isolation bugs, breaking their data-consistency contract \[[4](https://www.semanticscholar.org/paper/615ff2896b52bee2cbfd64ced324106a29b73397)\].

Black-box testing has emerged as a prominent technique for detecting these isolation bugs by checking whether transaction histories adhere to a prescribed isolation level \[[5](https://www.semanticscholar.org/paper/38c443a37914e287c42a3238ccebd7372847d5f9)\]. This approach is particularly useful because it does not require access to the internal implementation of the database \[[6](http://arxiv.org/abs/2103.02830)\]. However, testing databases on large workloads requires isolation testers to be highly efficient, as existing tools often have large polynomial complexity, limiting their applicability to moderate-sized workloads \[[7](https://www.semanticscholar.org/paper/e7ab23d011e5183db78cfea48e303210f6e57e2e)\].

The complexity of checking transactional consistency has been extensively studied. For instance, serializability, a strong isolation level, is known to be NP-complete \[[8](https://www.semanticscholar.org/paper/32257d8d2b08c87e58c7b7f4b2430d58e4b51a81)\]. In contrast, weak isolation levels such as RC, RA, and CC have been shown to be testable in polynomial time, which has improved the scalability of testing tools \[[9](https://www.semanticscholar.org/paper/592950c96053778e9b58ce4c461c1cfa8d32e334)\]. However, existing testers still face challenges in efficiently handling large-scale workloads .

Recent work has introduced tools like Plume, which provides an efficient and complete black-box checker for weak isolation levels . Plume leverages vectors and tree clocks to accelerate isolation checking and has been able to detect new isolation bugs in production databases . Similarly, Viper is a fast Snapshot Isolation (SI) checker that is sound, complete, and efficient, supporting various SI variants . These tools have significantly improved the practicality of black-box testing for weak isolation levels .

MonkeyDB is another mock storage system designed to test the robustness of applications against weak isolation levels . It supports multiple isolation levels and uses a logical specification to compute possible return values for read operations, enabling developers to test their applications under weak isolation conditions . These tools collectively highlight the ongoing efforts to improve the efficiency and effectiveness of black-box testing for weak isolation levels .
