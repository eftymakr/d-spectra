## Related Works

Semi-supervised learning (SSL) has emerged as a powerful paradigm for improving model performance by leveraging both labeled and unlabeled data. However, traditional SSL methods assume that labeled and unlabeled data share the same class distribution, an assumption that is often violated in practice due to the presence of outliers in the unlabeled data \[[1' 2021-05-28](http://arxiv.org/abs/2105.14148v2)\]. Outliers, which represent unknown classes, can significantly degrade SSL performance by introducing noise and bias into the learning process \[[2' 2024-05-11](http://arxiv.org/abs/2405.06979v2)\]. To address this issue, several open-set SSL approaches have been proposed, aiming to handle the presence of out-of-distribution (OOD) samples during training \[[3' 2023-03-21](http://arxiv.org/abs/2303.12091v4)\].

One such approach is OpenMatch, which combines FixMatch with novelty detection using one-vs-all (OVA) classifiers to identify inliers and outliers \[[1' 2021-05-28](http://arxiv.org/abs/2105.14148v2)\]. The OVA classifier provides confidence scores that help threshold outlier detection, while an open-set soft-consistency regularization loss enhances the smoothness of the classifier with respect to input transformations \[[1' 2021-05-28](http://arxiv.org/abs/2105.14148v2)\]. Similarly, OpenCoS introduces a framework based on contrastive learning to identify out-of-class samples in the unlabeled dataset, enabling the use of one-hot pseudo-labels for inliers and soft-labels for outliers \[[4' 2021-06-29](http://arxiv.org/abs/2107.08943v3)\]. This approach improves the robustness of existing SSL methods by addressing the failure modes caused by OOD samples \[[4' 2021-06-29](http://arxiv.org/abs/2107.08943v3)\].

Another line of work focuses on improving the selection of open-set data during training. WiseOpen proposes a robust open-set data selection strategy that leverages a gradient-variance-based mechanism to filter out unfriendly samples, thereby enhancing the model's ability to classify in-distribution data \[[2' 2024-05-11](http://arxiv.org/abs/2405.06979v2)\]. This approach reduces the computational burden by focusing on a subset of open-set data that is more compatible with the SSL task \[[2' 2024-05-11](http://arxiv.org/abs/2405.06979v2)\].

In addition to outlier detection, some methods have explored the use of generative models to improve SSL performance. For example, the Bad GAN approach learns a classifier using unrealistic samples distributed on the complement of the input data's support, while Triple GAN leverages good generated samples to improve classification results \[[13' 2019-05-16](http://arxiv.org/abs/1905.06484v2)\]. ### <a id='category-open-set-ssl-frameworks'></a>Open-Set SSL Frameworks: 4 papers found.
Open-set semi-supervised learning (Open-set SSL) addresses the limitations of conventional SSL methods, which assume that labeled and unlabeled data share the same class distribution \[[1' 2021-05-28](http://arxiv.org/abs/2105.14148v2)\]. In practice, unlabeled data often contains outliers—categories not present in the labeled set—which can severely degrade model performance \[[3' 2023-03-21](http://arxiv.org/abs/2303.12091v4)\]. To mitigate this, several frameworks have been proposed. For instance, OpenMatch introduces a novel approach that combines FixMatch with novelty detection using one-vs-all (OVA) classifiers, enabling the model to distinguish between inliers and outliers by learning robust representations \[[1' 2021-05-28](http://arxiv.org/abs/2105.14148v2)\]. Similarly, Adaptive Negative Evidential Deep Learning (ANEDL) improves scalability and uncertainty distinction by incorporating evidential deep learning (EDL) and an adaptive negative optimization strategy \[[3' 2023-03-21](http://arxiv.org/abs/2303.12091v4)\]. OpenCoS further advances this field by leveraging self-supervised contrastive learning to identify out-of-class samples in open-set unlabeled data, then using one-hot and soft-labels to improve performance \[[4' 2021-06-29](http://arxiv.org/abs/2107.08943v3)\]. Additionally, OSTIM introduces a model-agnostic approach for few-shot open-set recognition, utilizing transduction and mutual information maximization to detect outliers while maintaining strong classification performance \[[9' 2022-06-18](http://arxiv.org/abs/2206.09236v1)\]. These methods collectively highlight the growing focus on robustness against outliers and the need for scalable, adaptable frameworks in open-set SSL.

### <a id='category-contrastive-learning-in-ssl'></a>Contrastive Learning in SSL: 2 papers found.
Contrastive learning has emerged as a powerful technique in semi-supervised learning (SSL), offering improvements over traditional consistency regularization methods by leveraging well-clustered features of unlabeled data \[[6' 2022-01-17](http://arxiv.org/abs/2201.06247v2)\]. While consistency regularization focuses on maintaining label consistency across augmented views, it often struggles with propagating reliable pseudo-labels due to the exclusion of uncertain samples during model updates \[[6' 2022-01-17](http://arxiv.org/abs/2201.06247v2)\]. In contrast, contrastive regularization addresses this limitation by encouraging features with confident pseudo-labels to cluster closely within their respective groups while pushing apart features from different clusters \[[6' 2022-01-17](http://arxiv.org/abs/2201.06247v2)\]. This approach enables more effective propagation of reliable labeling information across unlabeled samples, leading to improved efficiency and accuracy in SSL tasks \[[6' 2022-01-17](http://arxiv.org/abs/2201.06247v2)\]. Furthermore, contrastive learning has been applied to detect subtle biases in large language models (LLMs), where it integrates contextual analysis, attention mechanisms, and counterfactual data augmentation to uncover hidden biases in model responses \[[24' 2025-03-08](http://arxiv.org/abs/2503.06054v1)\]. These methods highlight the versatility of contrastive learning in enhancing both the robustness of SSL frameworks and the fairness of AI systems \[[6' 2022-01-17](http://arxiv.org/abs/2201.06247v2)\]\[[24' 2025-03-08](http://arxiv.org/abs/2503.06054v1)\].
