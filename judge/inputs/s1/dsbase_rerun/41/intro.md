## Related Works

Serverless computing has gained significant traction due to its ability to abstract away server management, enabling automatic scaling, efficient resource utilization, and cost-effective pricing models \[[1' 2024-06-17](http://arxiv.org/abs/2406.11734v1)\]. However, a critical challenge persists: the cold-start latency, which significantly impacts end-to-end performance \[[2' 2021-05-28](http://arxiv.org/abs/2105.13894v1)\]. This issue arises when a serverless function is invoked after being idle, requiring a full initialization process that introduces unnecessary overhead \[[3' 2025-04-15](http://arxiv.org/abs/2504.11338v1)\]. Several studies have explored solutions to mitigate this problem, focusing on both architectural and runtime-level optimizations.

Existing static analysis techniques have been used to identify unreachable libraries, which can reduce initialization overhead \[[4' 2023-10-12](http://arxiv.org/abs/2310.08437v2)\]. However, these approaches fail to address workload-dependent inefficiencies, resulting in limited performance improvements \[[5' 2020-10-09](http://arxiv.org/abs/2010.04312v1)\]. For example, LibProf, a Python profiler, identifies inefficient library initializations through dynamic program analysis and statistical sampling, leading to a 2.26x speedup in cold-start execution time and a 1.51x reduction in memory usage \[[6' 2024-10-08](http://arxiv.org/abs/2410.06145v1)\]. Similarly, the Transformer-based model proposed in \[[7' 2023-08-15](http://arxiv.org/abs/2308.07541v2)\] leverages deep learning to model function initialization delays, achieving up to a 79% reduction in cold-start times compared to conventional methods.

Another approach to reducing cold-start latency involves snapshot-based warm-up techniques, such as Prebaking and SEUSS \[[8' 2022-10-09](http://arxiv.org/abs/2210.04212v1)\]. These methods aim to pre-initialize functions, reducing the time required to respond to incoming requests. For instance, Prebaking reduced the Markdown function's first request processing time by 69% \[[9' 2019-11-18](http://arxiv.org/abs/1911.07449v4)\]. Additionally, reinforcement learning has been applied to proactively initialize functions based on expected demand, improving throughput by up to 8.81% and reducing resource wastage \[[10' 2023-12-12](http://arxiv.org/abs/2312.07090v1)\]. This aligns with the goal of SLIMSTART, which uses profile-guided optimization to identify and mitigate inefficient library usage patterns \[[11' 2023-04-01](http://arxiv.org/abs/2304.00396v1)\].

The cold-start problem has also been studied in the context of multi-region scheduling, where factors such as trigger types, runtime languages, and function resource allocations influence the number and duration of cold starts \[[12' 2022-11-15](http://arxiv.org/abs/2211.08056v1)\]. For example, cold starts in Region 1 can take up to 7 seconds, dominated by dependency deployment time and scheduling \[[13' 2021-03-10](http://arxiv.org/abs/2103.05861v1)\]. These findings highlight the need for adaptive strategies to reduce cold-start latency across different environments.

In addition to runtime optimizations, there is growing interest in architectural-level solutions, such as memory-safe software and hardware designs, which aim to improve the efficiency and security of serverless platforms \[[14' 2022-06-30](http://arxiv.org/abs/2206.15176v1)\].
