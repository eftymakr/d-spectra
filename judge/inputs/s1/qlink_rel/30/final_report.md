## Related Works

Modern databases often trade strong transaction isolation for weak isolation guarantees to achieve low latency and high throughput, particularly in distributed systems \[[1](http://arxiv.org/abs/1908.04509)\]. This trade-off has led to the emergence of weak isolation levels such as Read Committed (RC), Read Atomic (RA), and Causal Consistency (CC), which are increasingly adopted in production environments \[[5](https://www.semanticscholar.org/paper/38c443a37914e287c42a3238ccebd7372847d5f9)\]. However, these weaker isolation levels can introduce bugs that violate data consistency, as evidenced by several real-world cases \[[3](https://www.semanticscholar.org/paper/cbe191bda20907994d45bc835d20446968370add)\]. 

Black-box testing has emerged as a critical technique for detecting such isolation bugs by verifying whether transaction histories adhere to a given isolation level \[[3](https://www.semanticscholar.org/paper/cbe191bda20907994d45bc835d20446968370add)\]. Early work on transactional consistency, such as the study of serializability, showed that checking consistency is NP-complete in general \[[1](http://arxiv.org/abs/1908.04509)\]. More recently, it was demonstrated that certain weak isolation models, including RC, RA, and CC, can be checked in polynomial time \[[1](http://arxiv.org/abs/1908.04509)\]. This has enabled the development of scalable testing tools, but existing solutions often suffer from high polynomial complexity, limiting their applicability to large-scale workloads \[[1](http://arxiv.org/abs/1908.04509)\].

Several tools have been proposed to address these limitations. Viper, for instance, introduces BC-polygraphs to efficiently check Snapshot Isolation (SI) and supports variants like Strong SI and Strong Session SI \[[2](https://www.semanticscholar.org/paper/9f96a48d2bc0e77004b32960495685be6c301c63)\]. Similarly, Plume presents a black-box checker for weak isolation levels, leveraging vectors and tree clocks to accelerate isolation checking and detect anomalies in production databases \[[3](https://www.semanticscholar.org/paper/cbe191bda20907994d45bc835d20446968370add)\]. MonkeyDB, on the other hand, provides a mock storage system for testing applications under weak isolation levels, offering a logical specification of isolation levels to simulate possible return values during read operations \[[4](https://www.semanticscholar.org/paper/615ff2896b52bee2cbfd64ced324106a29b73397)\].

The complexity of testing weak isolation levels has also been studied in the context of distribution testing. For example, the problem of closeness testing for discrete distributions has been shown to have optimal algorithms with sample complexity that is information-theoretically optimal \[[7](http://arxiv.org/abs/1308.3946)\]. These results align with the findings of our work, which demonstrates that AWDIT achieves optimal performance for RC, RA, and CC, with time complexities of $O(n^(3/2))$, $O(n^(3/2))$, and $O(n \cdot k)$, respectively \[[1](http://arxiv.org/abs/1908.04509)\].

AWDIT improves upon existing tools by achieving significant speedups, particularly for large histories. For instance, it provides an average speedup of $245\times$, $193\times$, and $62\times$ over the best baseline for RC, RA, and CC, respectively \[[1](http://arxiv.org/abs/1908.04509)\]. [Snippet]: «Snapshot isolation (SI) is supported by most commercial databases and is widely used by applications. However, checking SI today---given a set of transactions, checking if they obey SI---is either slow or gives up soundness. We present viper, an SI checker that is sound, complete, and fast. Viper checks black-box databases and hence is transparent to both users and databases. To be fast, viper introduces BC-polygraphs, a new representation of transaction dependencies. A BC-polygraph is acyclic iff transactions are SI, a theorem that we prove. Viper also introduces heuristic pruning, an optimization to accelerate checking SI by leveraging common knowledge of real-world database implementations. Besides vanilla SI, viper supports major SI variants including Strong SI, Generalized SI, and Strong Session SI. Our experiments show that given the same time budget, viper improves over baselines by 15× in the workload sizes being checked.»

[Snippet]: «Modern applications, such as social networking systems and e-commerce platforms are centered around using large-scale storage systems for storing and retrieving data. In the presence of concurrent accesses, these storage systems trade off isolation for performance. The weaker the isolation level, the more behaviors a storage system is allowed to exhibit and it is up to the developer to ensure that their application can tolerate those behaviors. However, these weak behaviors only occur rarely in practice and outside the control of the application, making it difficult for developers to test the robustness of their code against weak isolation levels. This paper presents MonkeyDB, a mock storage system for testing storage-backed applications. MonkeyDB supports a key-value interface as well as SQL queries under multiple isolation levels. It uses a logical specification of the isolation level to compute, on a read operation, the set of all possible return values. MonkeyDB then returns a value randomly from this set. We show that MonkeyDB provides good coverage of weak behaviors, which is complete in the limit. We test a variety of applications for assertions that fail only under weak isolation. MonkeyDB is able to break each of those assertions in a small number of attempts.»
