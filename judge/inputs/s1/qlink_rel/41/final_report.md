## Related Works

Serverless computing has gained significant traction due to its ability to abstract away server management, enabling automatic scaling, efficient resource utilization, and cost-effective pricing models \[[17](https://www.semanticscholar.org/paper/d9eaeccc9cca929af052aa362efaf83267daf614)\]. However, the cold start problem remains a critical challenge, where the platform incurs additional latency to provision runtime containers for function execution \[[1](https://www.semanticscholar.org/paper/d911b03bfda4fc6fc92f8080bb81b3a967d6a9e7)\]. This issue is exacerbated by the need to initialize libraries and dependencies, which are often not used under typical workloads \[[1](https://www.semanticscholar.org/paper/d911b03bfda4fc6fc92f8080bb81b3a967d6a9e7)\]. Existing static analysis techniques can identify unreachable libraries, but they fail to address workload-dependent inefficiencies, resulting in limited performance improvements \[[1](https://www.semanticscholar.org/paper/d911b03bfda4fc6fc92f8080bb81b3a967d6a9e7)\].

Several studies have explored solutions to mitigate cold start latency. For instance, Catalyzer proposes a serverless sandbox system that restores function instances from checkpoint images, thereby skipping initialization on the critical path and achieving sub-millisecond startup times \[[2](https://www.semanticscholar.org/paper/f14446970a5ed7145a6d350e1aff07ca203cece8)\]. Similarly, FaaSLight focuses on application-level optimization by identifying and loading only the indispensable code required for function execution, significantly reducing code loading latency \[[10](http://arxiv.org/abs/2207.08175)\]. This approach is platform- and language-agnostic, making it applicable across various serverless platforms \[[10](http://arxiv.org/abs/2207.08175)\].

Prebaking functions to warm the serverless cold start has also been explored. This technique restores snapshots from previously executed function processes, improving startup time by up to 71% for certain workloads \[[8](https://www.semanticscholar.org/paper/ab1c0062964a2df3d7f8d11da4a774530286b801)\]. Another approach, Adaptive Function Launching Acceleration, introduces strategies to predict function invocation times and warm up functions in advance, reducing cold start latency while minimizing resource consumption \[[5](https://www.semanticscholar.org/paper/81b8db7a20f1aa859143c716b38a1443e3eca9a0)\]. The Adaptive Warm-Up Strategy (AWUS) and Adaptive Container Pool Scaling Strategy (ACPSS) work together to achieve this, demonstrating effectiveness through extensive evaluation \[[5](https://www.semanticscholar.org/paper/81b8db7a20f1aa859143c716b38a1443e3eca9a0)\].

The cold start problem also affects the performance of serverless function chains, where cascading delays occur due to the sequential provisioning of resources for each function in a workflow \[[12](https://www.semanticscholar.org/paper/1cd137e77753ee6c51c97c520d64f91d484dbddc)\]. Xanadu addresses this by employing speculative and just-in-time provisioning of resources, effectively eliminating cascading cold starts with minimal overhead \[[12](https://www.semanticscholar.org/paper/1cd137e77753ee6c51c97c520d64f91d484dbddc)\]. Similarly, FaasCache introduces a greedy-dual caching policy inspired by caching principles, reducing cold-start overhead by more than 3× compared to current approaches \[[15](https://www.semanticscholar.org/paper/3c05fec4087d94c61233a482e59b613388b2c3ae)\].

### <a id='category-cold-start-mitigation-strategies'></a>Cold Start Mitigation Strategies: 10 papers found.
Cold start mitigation strategies in serverless computing have been extensively studied, with various approaches aimed at reducing the latency associated with initializing function instances. Several techniques focus on minimizing startup overhead by leveraging pre-warmed containers, optimizing code loading, or using predictive models to anticipate function invocations \[[5](https://www.semanticscholar.org/paper/81b8db7a20f1aa859143c716b38a1443e3eca9a0)\]. For example, the Adaptive Warm-Up Strategy (AWUS) predicts function invocation times and pre-warms functions, while the Adaptive Container Pool Scaling Strategy (ACPSS) dynamically adjusts container pool capacity to reduce resource waste \[[5](https://www.semanticscholar.org/paper/81b8db7a20f1aa859143c716b38a1443e3eca9a0)\]. Similarly, the FaaSLight approach optimizes code loading by identifying and loading only essential code, significantly reducing cold start latency \[[10](http://arxiv.org/abs/2207.08175)\]. Other works, such as Catalyzer, propose restoring function instances from checkpoints to bypass initialization overhead, achieving sub-millisecond startup times \[[1](https://www.semanticscholar.org/paper/d911b03bfda4fc6fc92f8080bb81b3a967d6a9e7)\]. Additionally, the Xanadu system mitigates cascading cold starts by speculatively provisioning resources based on workflow patterns, offering near-complete elimination of cascading overheads \[[6](http://arxiv.org/abs/2003.03423)\]. Reinforcement Learning (Q-Learning) agents have also been employed to learn invocation patterns and proactively prepare function instances, reducing cold start frequency \[[4](https://www.semanticscholar.org/paper/c066cf85b94846ddc057a113ce110e045f587375)\]. Furthermore, caching-inspired keep-alive policies, such as Greedy-Dual, have been proposed to maintain function instances warm based on usage patterns, reducing cold start overhead by over 3× \[[9](https://www.semanticscholar.org/paper/96d4fea8d034a7605af936f2e2b6a44becdf6585)\]. These strategies collectively highlight the importance of both runtime optimization and proactive resource management in addressing the cold start problem.
