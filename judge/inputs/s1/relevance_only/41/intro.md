## Related Works

Cold start latency remains a critical challenge in serverless computing, impacting both performance and resource utilization \[[1](http://arxiv.org/abs/2406.11734)\]. Several studies have explored this issue, proposing various mitigation strategies. For instance, LibProf \[[1](http://arxiv.org/abs/2406.11734)\] introduces a Python profiler that identifies inefficient library initializations using dynamic program analysis, offering insights into cold start inefficiencies. This work aligns with our approach of analyzing runtime behavior to optimize library usage. Similarly, the work by \[[15](https://www.semanticscholar.org/paper/d45518ce5741587c4c37ccbc5e74b3fcfd6f80f1)\] proposes an LRU-based warm container selection approach to reduce cold start occurrences, demonstrating the importance of container management in mitigating latency.

Existing solutions often rely on static analysis to identify unused libraries, but they fail to account for workload-dependent inefficiencies \[[1](http://arxiv.org/abs/2406.11734)\]. This limitation is also noted in \[[16](https://www.semanticscholar.org/paper/69cb9bb1154a606a16bdcebb22feb8a05003913a)\], where deep learning models are used to predict cold start occurrences based on historical and real-time data, highlighting the need for dynamic and adaptive strategies. Our tool, SLIMSTART, extends this by leveraging statistical sampling and call-path profiling to collect runtime library usage data, enabling more accurate and workload-aware optimizations.

Several studies have proposed reinforcement learning-based approaches to address cold start latency. For example, \[[14](https://www.semanticscholar.org/paper/96d4fea8d034a7605af936f2e2b6a44becdf6585)\] introduces a Q-Learning agent to analyze function invocation patterns and reduce cold start frequency by preparing function instances in advance. This aligns with our approach of using profile-guided optimizations to adapt to evolving workloads. Similarly, \[[3](https://www.semanticscholar.org/paper/27cd21426fe51167dd6ac79d1c83db55a07a2046)\] presents a two-layer adaptive approach that uses reinforcement learning to determine optimal container warm-up times and LSTM to predict future invocation times, demonstrating the effectiveness of machine learning in cold start mitigation.

Time series forecasting methods have also been applied to predict function call volumes and reduce cold start occurrences. \[[17](https://www.semanticscholar.org/paper/7412ca941221b24fe57ae995a3ce5db100cf068b)\] employs the SARIMA model to forecast future function calls, enabling dynamic resource allocation and reducing cold start times. This approach is similar to our use of runtime data to guide optimization decisions. Additionally, \[[12](http://arxiv.org/abs/2206.15176)\] proposes a prediction-based autoscaler (PBA) that outperforms the default HPA in Kubernetes, demonstrating the value of predictive models in resource management.

Efforts to reduce cold start latency have also focused on caching and container pre-warming. \[[15](https://www.semanticscholar.org/paper/d45518ce5741587c4c37ccbc5e74b3fcfd6f80f1)\] introduces an LRU-based warm container selection approach, while \[[18](https://www.semanticscholar.org/paper/f85fde870a1eb9c98c62ded89602e2bd1bab6a86)\] proposes an adaptive caching policy that considers container frequency, size, and cold start time. These strategies highlight the trade-offs between resource usage and performance, a challenge our tool addresses by integrating optimization into CI/CD pipelines for continuous adaptation.
