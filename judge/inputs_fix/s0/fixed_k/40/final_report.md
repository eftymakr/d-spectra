## Related Works

Zero-Knowledge Proofs (ZKPs) have garnered significant attention for their ability to enable secure and private computation, allowing a prover to demonstrate the truth of a statement without revealing additional information \[[1](http://arxiv.org/abs/2408.05890)\]. This capability has led to their application in blockchain technologies, verifiable machine learning, and electronic voting \[[1](http://arxiv.org/abs/2408.05890)\]. However, the computational complexity of the proving process has hindered widespread adoption \[[1](http://arxiv.org/abs/2408.05890)\]. Recent efforts have focused on accelerating the key primitives of ZKP protocols using hardware, particularly GPUs and ASICs \[[1](http://arxiv.org/abs/2408.05890)\]. For instance, SZKP presents a scalable accelerator framework that leverages structured dataflows for both Number Theoretic Transform (NTT) and Multi-scalar Multiplication (MSM) operations, achieving speedups of over 400×, 3×, and 12× over CPU, ASIC, and GPU implementations \[[2](http://arxiv.org/abs/2412.12481)\]. Similarly, if-ZKP introduces an FPGA-based architecture for accelerating the multi-scalar multiplication (MSM) operation in zk-SNARKs, achieving 110x-150x speedup over software for the BLS12-381 and BN128 elliptic curves \[[3](http://arxiv.org/abs/2206.13350)\]. These works highlight the importance of optimizing the computationally intensive parts of ZKP protocols to enable practical deployment.

Despite these advancements, existing protocols often face challenges such as requiring a trusted setup for each application or generating larger proof sizes with higher verification costs, which limits their applicability in scenarios with numerous verifiers or strict verification time constraints \[[1](http://arxiv.org/abs/2408.05890)\]. For example, some protocols rely on complex cryptographic constructions that are not suitable for resource-constrained environments \[[4](http://arxiv.org/abs/2307.00521)\]. In contrast, the proposed accelerator, zkSpeed, is designed to support both one-time, universal setup and small proof sizes, making it suitable for publicly verifiable, consensus-based systems \[[1](http://arxiv.org/abs/2408.05890)\]. This approach aligns with the broader trend of developing more efficient and scalable ZKP solutions, as seen in works like zksk, which provides a Python library for defining and computing sigma protocols \[[5](http://arxiv.org/abs/1911.02459)\], and zkDL, which introduces an efficient zero-knowledge proof for deep learning training \[[6](http://arxiv.org/abs/2504.01198)\].

Moreover, recent research has explored the integration of ZK-friendly hash functions, such as MiMC, into hardware accelerators to improve performance in ZKP generation \[[7](http://arxiv.org/abs/2012.10452)\]. AMAZE, a hardware-optimized framework for computing MiMC, demonstrates significant improvements over standard CPU implementations, achieving more than 13× speedup \[[7](http://arxiv.org/abs/2012.10452)\]. These developments underscore the ongoing efforts to enhance the efficiency and practicality of ZKP systems, addressing both computational and resource constraints \[[7](http://arxiv.org/abs/2012.10452)\].

In addition, there is growing interest in zero-knowledge protocols that can handle more complex computational tasks, such as proving the equivalence of regular expressions \[[8](http://arxiv.org/abs/2307.16273)\]. Crêpe, a novel ZK protocol, addresses this by using a custom calculus of proof rules based on regular expression derivatives and coinduction, enabling the validation of large proofs in seconds \[[8](http://arxiv.org/abs/2307.16273)\]. This work highlights the potential of ZKPs to support advanced computational tasks while maintaining privacy and security \[[8](http://arxiv.org/abs/2307.16273)\].

Finally, the use of physical principles, such as special relativity, to enforce security in zero-knowledge protocols has also been explored \[[9](http://arxiv.org/abs/2301.02161)\]. Experimental relativistic zero-knowledge proofs demonstrate the feasibility of secure identification tasks without relying on computational assumptions \[[9](http://arxiv.org/abs/2301.02161)\]. These approaches expand the scope of ZKP applications, ensuring their relevance in a wide range of domains \[[9](http://arxiv.org/abs/2301.02161)\].

Hardware acceleration techniques for Zero-Knowledge Proofs (ZKPs) have seen significant advancements, particularly in accelerating key primitives such as the Number Theoretic Transform (NTT) and Multi-scalar Multiplication (MSM) \[[1](http://arxiv.org/abs/2408.05890)\]. These operations are critical for proof generation in ZKP systems like zkSNARKs, where proof generation is computationally intensive \[[1](http://arxiv.org/abs/2408.05890)\]. Prior works have explored GPU implementations and custom RTL designs to improve performance, but these approaches often struggle with the complex dataflow patterns inherent in NTTs and MSMs \[[1](http://arxiv.org/abs/2408.05890)\]. For instance, standard NTTs involve irregular memory accesses during butterfly computations, while MSMs using Pippenger's algorithm exhibit data-dependent memory accesses for partial sum calculations \[[1](http://arxiv.org/abs/2408.05890)\]. To address these challenges, researchers have proposed specialized accelerators, such as SZKP, which is the first ASIC to accelerate an entire proof on-chip by leveraging structured dataflows for both NTTs and MSMs \[[1](http://arxiv.org/abs/2408.05890)\]. This approach achieves substantial speedups, with conservative full-proof improvements of over 400×, 3×, and 12× compared to CPU, ASIC, and GPU implementations, respectively \[[1](http://arxiv.org/abs/2408.05890)\]. Similarly, an FPGA-based architecture has been developed to accelerate the MSM operation in zk-SNARKs, exploiting inherent parallelism and using optimized IP for modular arithmetic, resulting in 110×–150× speedups over software implementations for specific elliptic curves \[[2](http://arxiv.org/abs/2412.12481)\]. These efforts highlight the growing importance of hardware acceleration in overcoming the computational bottlenecks of ZKP systems, enabling broader adoption in privacy-preserving applications.
