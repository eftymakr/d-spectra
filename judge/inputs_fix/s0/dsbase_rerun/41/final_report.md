## Related Works

Cold-start latency remains a critical challenge in serverless computing, impacting both performance and resource utilization \[[1' 2024-06-17](http://arxiv.org/abs/2406.11734v1)\]. Several studies have explored this issue, proposing various mitigation strategies. For instance, \[[6' 2019-03-28](http://arxiv.org/abs/1903.12221v1)\] highlights that cold-start latency is primarily caused by the time required to provision new function instances, which can lead to significant delays in response times. This problem is exacerbated by the need for on-demand resource allocation, which is a core feature of serverless platforms \[[11' 2018-10-12](http://arxiv.org/abs/1810.05633v2)\]. 

To address cold-start latency, researchers have proposed a range of techniques. One approach involves maintaining a pool of warm containers to reduce the time required to launch new instances \[[6' 2019-03-28](http://arxiv.org/abs/1903.12221v1)\]. This method has been implemented in platforms like Knative Serving, where a pool of function instances is kept ready to serve incoming requests, significantly reducing P99 response time \[[6' 2019-03-28](http://arxiv.org/abs/1903.12221v1)\]. Similarly, \[[10' 2021-08-25](http://arxiv.org/abs/2108.11240v1)\] introduces Pagurus, a system that enables inter-action container sharing, allowing new actions to reuse existing containers, thus eliminating the need for cold starts. This approach dramatically reduces the startup time of new containers, with some actions starting in as little as 10ms \[[10' 2021-08-25](http://arxiv.org/abs/2108.11240v1)\].

Another line of research focuses on predictive techniques to anticipate function demand and pre-load necessary resources. \[[8' 2023-08-15](http://arxiv.org/abs/2308.07541v2)\] proposes the use of off-policy reinforcement learning to proactively initialize functions based on expected demand, reducing the frequency of cold starts. This approach improves throughput by up to 8.81% and reduces computation load and resource wastage by up to 55% and 37%, respectively \[[8' 2023-08-15](http://arxiv.org/abs/2308.07541v2)\]. Similarly, \[[2' 2023-04-01](http://arxiv.org/abs/2304.00396v1)\] introduces a temporal convolutional network (TCN) to predict function instance arrivals, enabling more efficient resource provisioning and reducing cold-start latency \[[2' 2023-04-01](http://arxiv.org/abs/2304.00396v1)\].

Application-level optimizations have also been explored as a means to reduce cold-start overhead. \[[3' 2022-07-17](http://arxiv.org/abs/2207.08175v2)\] presents FaaSLight, an approach that separates essential code from optional code in FaaS applications, allowing only necessary code to be loaded during cold starts. This reduces code loading latency by up to 78.95%, leading to a 42.05% reduction in total response latency \[[3' 2022-07-17](http://arxiv.org/abs/2207.08175v2)\]. Similarly, \[[1' 2024-06-17](http://arxiv.org/abs/2406.11734v1)\] introduces LibProf, a Python profiler that identifies inefficient library initializations, enabling developers to optimize their applications for better performance \[[1' 2024-06-17](http://arxiv.org/abs/2406.11734v1)\].

In addition to these approaches, \[[9' 2024-03-26](http://arxiv.org/abs/2403.17574v2)\] proposes SPES, a scheduler that optimizes the trade-off between cold-start latency and resource waste by leveraging invocation patterns to pre-load or unload function instances. This method reduces cold-start rates by 49.77% and wasted memory time by 56.43% compared to existing solutions \[[9' 2024-03-26](http://arxiv.org/abs/2403.17574v2)\]. These studies collectively demonstrate the diverse strategies being explored to mitigate cold-start latency in serverless computing.
