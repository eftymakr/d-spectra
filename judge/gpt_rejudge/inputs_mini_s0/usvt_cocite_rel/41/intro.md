## Related Works

Serverless computing, particularly Function-as-a-Service (FaaS), has transformed cloud application deployment by abstracting server management, offering automatic scaling, and enabling cost-effective pay-as-you-go models \[[1911.01296](http://arxiv.org/abs/1911.01296)\]. Despite these benefits, the cold-start problem, which introduces latency when initializing function instances, remains a significant challenge impacting overall system responsiveness \[[https://www.semanticscholar.org/paper/81b8db7a20f1aa859143c716b38a1443e3eca9a0](https://www.semanticscholar.org/paper/81b8db7a20f1aa859143c716b38a1443e3eca9a0)\]\[[https://www.semanticscholar.org/paper/d911b03bfda4fc6fc92f8080bb81b3a967d6a9e7](https://www.semanticscholar.org/paper/d911b03bfda4fc6fc92f8080bb81b3a967d6a9e7)\]. This latency primarily arises from the overhead of provisioning runtime containers and loading dependencies prior to execution \[[2207.08175](http://arxiv.org/abs/2207.08175)\]\[[https://www.semanticscholar.org/paper/d911b03bfda4fc6fc92f8080bb81b3a967d6a9e7](https://www.semanticscholar.org/paper/d911b03bfda4fc6fc92f8080bb81b3a967d6a9e7)\].

Much research has focused on mitigating cold-start latency through various strategies. One common approach involves maintaining warm containers or pre-warmed pools to reduce initialization time. Adaptive container pool scaling and warm-up strategies have been proposed to predict invocation patterns and dynamically keep containers ready, reducing cold starts while managing resource waste \[[https://www.semanticscholar.org/paper/81b8db7a20f1aa859143c716b38a1443e3eca9a0](https://www.semanticscholar.org/paper/81b8db7a20f1aa859143c716b38a1443e3eca9a0)\]\[[https://www.semanticscholar.org/paper/b99668ae35c4b6796b827657a318fe4b84a757ff](https://www.semanticscholar.org/paper/b99668ae35c4b6796b827657a318fe4b84a757ff)\]\[[https://www.semanticscholar.org/paper/27cd21426fe51167dd6ac79d1c83db55a07a2046](https://www.semanticscholar.org/paper/27cd21426fe51167dd6ac79d1c83db55a07a2046)\]\[[https://www.semanticscholar.org/paper/96d4fea8d034a7605af936f2e2b6a44becdf6585](https://www.semanticscholar.org/paper/96d4fea8d034a7605af936f2e2b6a44becdf6585)\]. For example, deep learning methods like LSTM have been used to model invocation traces and adjust the idle container window adaptively \[[https://www.semanticscholar.org/paper/b99668ae35c4b6796b827657a318fe4b84a757ff](https://www.semanticscholar.org/paper/b99668ae35c4b6796b827657a318fe4b84a757ff)\]\[[https://www.semanticscholar.org/paper/27cd21426fe51167dd6ac79d1c83db55a07a2046](https://www.semanticscholar.org/paper/27cd21426fe51167dd6ac79d1c83db55a07a2046)\]. Reinforcement learning techniques have also been applied to learn optimal container warm-up policies, balancing latency reduction and resource efficiency \[[https://www.semanticscholar.org/paper/27cd21426fe51167dd6ac79d1c83db55a07a2046](https://www.semanticscholar.org/paper/27cd21426fe51167dd6ac79d1c83db55a07a2046)\]\[[https://www.semanticscholar.org/paper/96d4fea8d034a7605af936f2e2b6a44becdf6585](https://www.semanticscholar.org/paper/96d4fea8d034a7605af936f2e2b6a44becdf6585)\].

Application-level optimizations have gained attention as an effective means to reduce cold-start overhead beyond infrastructure-level improvements. FaaSLight demonstrates that selectively loading only indispensable code based on function-level call graphs can substantially decrease code loading latency and thus cold start time, achieving up to 78.95% reduction in code loading latency \[[2207.08175](http://arxiv.org/abs/2207.08175)\]. Similarly, SLIMSTART’s profile-guided approach aligns with this direction by leveraging runtime profiling to identify inefficient library initialization patterns and applying automated code transformations to reduce unnecessary overhead.

Checkpoint/restore mechanisms and container snapshotting have also been explored to accelerate startup times by restoring pre-initialized function states. Techniques such as prebaking functions using process snapshots (e.g., CRIU-based) have shown speedups of up to 71% in startup times, especially when snapshots are created from warm functions, significantly lowering cold start latency \[[https://www.semanticscholar.org/paper/ab1c0062964a2df3d7f8d11da4a774530286b801](https://www.semanticscholar.org/paper/ab1c0062964a2df3d7f8d11da4a774530286b801)\]. Catalyzer extends this idea by restoring virtualization-based sandbox images and employing OS primitives to skip initialization phases, achieving sub-millisecond startup latencies \[[https://www.semanticscholar.org/paper/f14446970a5ed7145a6d350e1aff07ca203cece8](https://www.semanticscholar.org/paper/f14446970a5ed7145a6d350e1aff07ca203cece8)\].

Caching-inspired keep-alive policies present another angle, where function instances are treated like cache entries and managed to maximize reuse and minimize cold starts. FaasCache leverages greedy-dual caching algorithms for intelligent function instance retention, reducing cold-start overhead by over 3× and decreasing resource usage by up to 30% \[[https://www.semanticscholar.org/paper/3c05fec4087d94c61233a482e59b613388b2c3ae](https://www.semanticscholar.org/paper/3c05fec4087d94c61233a482e59b613388b2c3ae)\].

Workflows and function chains introduce additional complexities, as cold starts can cascade across sequential function invocations, compounding latency. Xanadu addresses this by speculative and just-in-time provisioning along function chains, effectively eliminating cascading cold starts with minimal overhead \[[https://www.semanticscholar.org/paper/1cd137e77753ee6c51c97c520d64f91d484dbddc](https://www.semanticscholar.org/paper/1cd137e77753ee6c51c97c520d64f91d484dbddc)\]. Function fusion techniques also aim to minimize cold start impact by merging multiple functions into one, thereby reducing the number of cold starts per workflow at the potential cost of increased sequential execution time \[[https://www.semanticscholar.org/paper/36338d869d7589b01c3707d70bece8c320e439e2](https://www.semanticscholar.org/paper/36338d869d7589b01c3707d70bece8c320e439e2)\].

Static analysis approaches have been proposed to identify unreachable or unnecessary libraries to reduce cold start overhead. However, these methods often lack sensitivity to dynamic workloads, failing to address runtime inefficiencies \[[https://www.semanticscholar.org/paper/1a937f78c2d968d134981b5c82adba6495e470e5](https://www.semanticscholar.org/paper/1a937f78c2d968d134981b5c82adba6495e470e5)\]\[[https://www.semanticscholar.org/paper/1447da2da7c926dc68e31a89461409d09b08d77e](https://www.semanticscholar.org/paper/1447da2da7c926dc68e31a89461409d09b08d77e)\]. Profile-guided and runtime-driven methods like SLIMSTART and LibProf improve upon static techniques by incorporating workload-dependent data to optimize library usage and code loading dynamically \[[2207.08175](http://arxiv.org/abs/2207.08175)\]\[[https://www.semanticscholar.org/paper/1a937f78c2d968d134981b5c82adba6495e470e5](https://www.semanticscholar.org/paper/1a937f78c2d968d134981b5c82adba6495e470e5)\].

Finally, large-scale empirical studies of FaaS workloads have revealed highly skewed invocation patterns and highlighted the need for nuanced resource management policies that reduce cold starts while maintaining efficiency \[[2003.03423](http://arxiv.org/abs/2003.03423)\]. These findings motivate adaptive and predictive mechanisms that leverage invocation frequency and temporal locality to optimize container lifecycle management.

In summary, existing work on cold-start mitigation spans infrastructure-level optimizations such as warm container pools and checkpoint/restore techniques, application-level strategies including selective code loading and profiling, workflow-aware provisioning, and adaptive resource management driven by machine learning. SLIMSTART builds on these foundations by combining profile-guided optimization with automated transformations tailored to workload-specific library usage, enabling significant reductions in initialization latency and memory consumption while integrating seamlessly with CI/CD pipelines for continuous adaptation.
