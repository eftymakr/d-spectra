## Related Works

The orchestration of containerized applications using Kubernetes has become a cornerstone of modern cloud-native architectures, enabling scalable, flexible, and maintainable deployments. Extensive research addresses various aspects of Kubernetes, including resource management, scheduling, security, and cost optimization, but the specific focus on network cost implications remains limited.

Resource scheduling and performance management in Kubernetes have been widely studied to improve efficiency and reduce operational costs. Scheduling algorithms aim to optimize Quality of Service (QoS) parameters such as response time, energy consumption, and resource utilization, which indirectly affect cost efficiency \[[https://www.semanticscholar.org/paper/d11e5c5c08af88ee8abb9ebaa166b1d6fd198501](https://www.semanticscholar.org/paper/d11e5c5c08af88ee8abb9ebaa166b1d6fd198501)\]. Research on Kubernetes’ resource scheduling schemes highlights ongoing challenges in achieving optimal resource allocation under dynamic workloads \[[https://www.semanticscholar.org/paper/0f4ac27e56efd714e3425bd9784eb76c7cd8c2a9](https://www.semanticscholar.org/paper/0f4ac27e56efd714e3425bd9784eb76c7cd8c2a9)\]\[[https://www.semanticscholar.org/paper/8eabcc47a99622184fc35b731992f10ff9f19444](https://www.semanticscholar.org/paper/8eabcc47a99622184fc35b731992f10ff9f19444)\]\[[https://www.semanticscholar.org/paper/d11e5c5c08af88ee8abb9ebaa166b1d6fd198501](https://www.semanticscholar.org/paper/d11e5c5c08af88ee8abb9ebaa166b1d6fd198501)\]. These scheduling improvements contribute to cost efficiency by minimizing wasted resources and improving cluster utilization, yet network cost considerations are rarely integrated into these models.

High availability and failure recovery are other critical areas of investigation. Kubernetes inherently supports recovery mechanisms to improve application availability, but experiments have demonstrated that service outages can still be significant under default configurations, influencing operational costs related to downtime and SLA violations \[[https://www.semanticscholar.org/paper/18a720c86ed6e166c26f7d39490bfd11b93ea3ec](https://www.semanticscholar.org/paper/18a720c86ed6e166c26f7d39490bfd11b93ea3ec)\]. Furthermore, auto-scaling mechanisms based on Kubernetes and monitoring tools (e.g., Prometheus) have been designed to dynamically adjust application instances to balance load and resource use, which also impacts cost \[[https://www.semanticscholar.org/paper/4d4080e1a2e26fe1ead433741602ab6eccc22b72](https://www.semanticscholar.org/paper/4d4080e1a2e26fe1ead433741602ab6eccc22b72)\].

Security practices in Kubernetes have received substantial attention, given the rise of microservices and container-based environments. Systematized security guidelines, including the implementation of role-based access control (RBAC), network policies, and patch management, are essential to mitigate vulnerabilities and protect workloads \[[2006.15275](http://arxiv.org/abs/2006.15275)\]. While security management is distinct from cost optimization, robust security reduces risks of costly breaches and downtime, indirectly influencing financial management in Kubernetes environments \[[https://www.semanticscholar.org/paper/b0fa8fd1b1638f4afad41956b65a15a9096e309f](https://www.semanticscholar.org/paper/b0fa8fd1b1638f4afad41956b65a15a9096e309f)\]\[[2006.15275](http://arxiv.org/abs/2006.15275)\]. Additionally, Helm charts, widely used for Kubernetes application deployment, pose security risks due to outdated or vulnerable container images, which can lead to compromised deployments and additional operational costs \[[https://www.semanticscholar.org/paper/8e853411a33651b57251f5f2bac46b774a180607](https://www.semanticscholar.org/paper/8e853411a33651b57251f5f2bac46b774a180607)\]\[[https://www.semanticscholar.org/paper/c5d1825555ad1c38501d67496e2cdc251d2d6de4](https://www.semanticscholar.org/paper/c5d1825555ad1c38501d67496e2cdc251d2d6de4)\].

The emergence of FinOps—a discipline integrating financial governance with cloud operations—has addressed the increasing complexity of managing cloud costs. While FinOps broadly covers cost optimization strategies, including budget enforcement and usage monitoring tools such as ABACUS, its application to Kubernetes environments has primarily focused on compute and storage costs, with limited emphasis on network expenditures . Existing FinOps tools provide budget control and alerting mechanisms crucial for managing cloud spend but often lack granular insights into network traffic costs within Kubernetes clusters.

Recent work in decentralized optimization and network topology analysis provides foundational understanding relevant to network cost management in distributed systems, which may inform future Kubernetes networking cost models \[[1709.08765](http://arxiv.org/abs/1709.08765)\]. Additionally, emerging research on adapting Kubernetes for edge environments reveals performance bottlenecks influenced by distributed state management and latency, indirectly affecting network resource usage and costs \[[2104.02423](http://arxiv.org/abs/2104.02423)\].

In bioinformatics and data-intensive workflows, container orchestration platforms like Pachyderm leverage Kubernetes for scalable data pipelines, demonstrating the importance of efficient resource and network management in complex applications \[[https://www.semanticscholar.org/paper/51e2cba5a013cbd11f2ab760a4e3906cfff44780](https://www.semanticscholar.org/paper/51e2cba5a013cbd11f2ab760a4e3906cfff44780)\]. These use cases underscore the need for comprehensive cost models that encompass network traffic, especially as data movement in cloud-native applications significantly impacts overall expenses.

Despite advances across these domains, the specific analysis of network usage and cost implications in Kubernetes clusters remains underexplored. Existing literature largely treats network as a secondary concern compared to compute and storage costs. This gap is critical because network traffic—both intra-cluster and external—can constitute a significant portion of cloud expenses, especially in multi-tenant or data-intensive applications. Addressing this gap requires integrated methodologies combining measurement, experimentation, and cost modeling tailored to Kubernetes networking, which this paper aims to provide.

In summary, prior research offers a rich background in Kubernetes resource management, scaling, security, and general cost optimization through FinOps principles. However, the financial and operational impacts of network usage within Kubernetes clusters have received limited dedicated attention. This paper extends the FinOps discourse by focusing on network cost analysis, presenting actionable insights for organizations deploying containerized applications in cloud-native environments.
