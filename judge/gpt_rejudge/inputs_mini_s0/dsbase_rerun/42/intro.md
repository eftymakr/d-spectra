## Related Works

The management of cloud-native applications, especially those leveraging container orchestration platforms like Kubernetes, has attracted significant research attention in recent years. Kubernetes has become the de facto standard for automating deployment, scaling, and management of containerized applications. Several studies have focused on improving Kubernetes workflow efficiency and security. For instance, KubeAdaptor addresses inconsistencies in task scheduling order between workflow systems and Kubernetes, enhancing execution performance and resource utilization \[[2207.01222v1](http://arxiv.org/abs/2207.01222v1)\]. Meanwhile, security considerations in Kubernetes have been systematized through practices such as role-based access control (RBAC), patch management, and implementing pod- and network-specific policies to mitigate vulnerabilities \[[2006.15275v1](http://arxiv.org/abs/2006.15275v1)\].

Despite advances in container orchestration and security, financial and cost management in cloud-native environments remains a challenging area. The emerging discipline of FinOps integrates financial accountability with cloud operations, aiming to optimize cloud expenditures while maintaining operational agility. ABACUS exemplifies this approach by automating budget setting, enforcement, and alerting mechanisms, leveraging Infrastructure-as-Code to estimate deployment costs proactively \[[2501.14753v1](http://arxiv.org/abs/2501.14753v1)\]. These tools facilitate holistic cloud cost visibility and help organizations enforce cost controls effectively.

While prior research has predominantly addressed system-level optimization of compute and storage resources in cloud environments, the network usage and associated cost implications in Kubernetes clusters are less explored. Network costs can constitute a significant portion of cloud expenditures, particularly as applications scale and inter-container or inter-service communication increases. Existing FinOps literature broadly covers cloud cost optimization strategies, including resource allocation and AI infrastructure efficiencies like model quantization and GPU instance selection \[[2501.05323v1](http://arxiv.org/abs/2501.05323v1)\]. However, the specific analysis of network-related expenses within Kubernetes-managed containerized applications is notably underrepresented.

Network performance and scalability challenges in Kubernetes, particularly in large-scale or edge deployments, have been investigated, revealing that Kubernetes’ reliance on strongly consistent storage (etcd) can limit availability and increase latency under high loads \[[2104.02423v1](http://arxiv.org/abs/2104.02423v1)\]. Extensions to Kubernetes networking, such as integrating Segment Routing over IPv6 (SRv6) with Calico plugins, aim to enhance overlay networking capabilities for distributed, multi-datacenter scenarios, improving traffic engineering and network efficiency \[[2301.01178v1](http://arxiv.org/abs/2301.01178v1)\]. These networking innovations provide a foundation for addressing cost and performance trade-offs in Kubernetes networking.

In the context of 5G and edge computing environments, network slicing and resource isolation techniques have been studied to ensure low latency and service quality, with experiments demonstrating that CPU resource limits can improve slice performance while memory restrictions have less impact \[[2502.02842v2](http://arxiv.org/abs/2502.02842v2)\]. Such insights into resource isolation and allocation are relevant for containerized applications requiring stringent network performance guarantees and cost-effective resource provisioning.

Moreover, decentralized and distributed AI training and inference frameworks highlight the growing complexity of managing distributed workloads, which inherently involve significant network communication and associated costs \[[2501.05323v1](http://arxiv.org/abs/2501.05323v1)\]. Understanding these network dynamics within Kubernetes clusters is essential for accurate cost modelling and optimization.

Overall, while there is a rich body of work on Kubernetes orchestration, security, cloud cost optimization frameworks, and network enhancements, there remains a critical gap in comprehensive studies focusing on network usage and cost implications for containerized applications in Kubernetes clusters. This paper contributes to filling this gap by combining measurement analysis, experimentation, and cost modelling to provide actionable insights into network cost optimization in cloud-native environments.
