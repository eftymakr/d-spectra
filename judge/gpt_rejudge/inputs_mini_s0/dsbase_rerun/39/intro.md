## Related Works

De novo genome assembly reconstructs unknown genomes from sequencing reads without relying on reference genomes, enabling critical applications such as personalized medicine and genomic research \[[1106.2603v1](http://arxiv.org/abs/1106.2603v1)\]. The process faces substantial computational challenges, including massive data volumes, complex graph structures, and irregular memory access patterns. Traditional approaches predominantly rely on graph-based models such as de Bruijn graphs and string graphs to represent sequence overlaps and assemble contigs \[[1106.2603v1](http://arxiv.org/abs/1106.2603v1)\]\[[1203.6364v2](http://arxiv.org/abs/1203.6364v2)\]. However, these methods demand large memory footprints and exhibit memory-bound behavior, limiting scalability and performance, especially for large and complex genomes \[[1106.2603v1](http://arxiv.org/abs/1106.2603v1)\]\[[2309.07270v2](http://arxiv.org/abs/2309.07270v2)\].

To address the memory and scalability issues, distributed-memory parallel algorithms have emerged as a primary approach. For instance, PPA-assembler uses Google's Pregel framework to perform scalable de Bruijn graph assembly in distributed settings, showing improved efficiency over traditional single-node methods \[[1801.04453v1](http://arxiv.org/abs/1801.04453v1)\]\[[1506.05538v1](http://arxiv.org/abs/1506.05538v1)\]. Similarly, distributed-memory algorithms have been developed for contig generation and graph traversal using sparse matrix abstractions, achieving good parallel efficiency and load balancing on large clusters \[[2207.04350v1](http://arxiv.org/abs/2207.04350v1)\]. These methods reduce computational bottlenecks by distributing both data and computation but still face challenges with load imbalance and communication overhead inherent to the irregular graph structures of genome assembly.

Memory optimization techniques have also been explored. SparseAssembler employs a sparse de Bruijn graph structure that skips intermediate k-mers to reduce memory consumption dramatically—down to about 10% of that required by standard de Bruijn graph methods—while maintaining comparable assembly quality \[[1106.2603v1](http://arxiv.org/abs/1106.2603v1)\]\[[2207.04350v1](http://arxiv.org/abs/2207.04350v1)\]. Additionally, algorithms leveraging bidirectional k-mer sizes, as in Bermuda for transcriptome assembly, adapt to uneven coverage and improve contiguity with moderate memory use \[[1506.05538v1](http://arxiv.org/abs/1506.05538v1)\]. Such adaptive strategies highlight the importance of memory footprint reduction alongside assembly accuracy.

GPU acceleration has been investigated to overcome computational intensity in overlap detection and layout simplification steps. ELBA, a state-of-the-art distributed-memory assembler, integrates GPU schedulers to enable multiple MPI processes to perform GPU computations concurrently, achieving up to 7-8× speedup compared to baseline GPU schedulers \[[2309.07270v2](http://arxiv.org/abs/2309.07270v2)\]. Despite these advances, GPU approaches can be limited by bandwidth and data transfer overheads, especially when dealing with large, irregular datasets characteristic of genome assembly.

Long-read sequencing technologies, such as SMRT and Oxford Nanopore, provide reads exceeding 10kb but with high error rates (~10-15%), posing additional challenges. Tools like minimap and miniasm efficiently assemble these noisy long reads without prior error correction, drastically reducing assembly runtime compared to traditional pipelines \[[1512.01801v2](http://arxiv.org/abs/1512.01801v2)\]. Moreover, haplotype-resolved assemblers like hifiasm leverage long high-fidelity reads to produce phased assembly graphs that preserve haplotype-specific contiguity, improving assembly quality for complex genomes \[[2008.01237v1](http://arxiv.org/abs/2008.01237v1)\]. These algorithmic advancements emphasize the need to handle data heterogeneity and error profiles effectively.

Recent developments also explore hardware-software co-design to mitigate the inherent memory bottlenecks and irregular data patterns in genome assembly. For example, HySortK introduces a distributed-memory, sorting-based k-mer counting approach with flexible hybrid parallelism to reduce memory usage and communication volume, achieving up to 2× speedup and 30% memory reduction compared to CPU-based software \[[2407.07718v1](http://arxiv.org/abs/2407.07718v1)\]. Similarly, proposals for near-memory processing (NMP) architectures aim to place computation closer to memory, minimizing data movement and improving throughput for memory-bound workloads characteristic of genome assembly \[[2404.07164v2](http://arxiv.org/abs/2404.07164v2)\]. These approaches underscore the potential of specialized hardware integration to enhance performance beyond purely software-based optimizations.

Beyond classical architectures, quantum and quantum-inspired annealing techniques have been experimentally applied to genome assembly problems, showing promise for future efficiency gains in solving combinatorial optimization challenges inherent in assembly \[[2004.06719v3](http://arxiv.org/abs/2004.06719v3)\]. Although still in nascent stages, such approaches could complement or transform the computational landscape of de novo assembly.

In summary, existing methods have advanced de novo genome assembly through distributed computing frameworks, memory-efficient graph representations, GPU acceleration, and leveraging long-read data. However, challenges remain in reducing memory footprints, handling irregular data patterns, and improving computational efficiency. Hardware-software co-design, including near-memory processing and specialized accelerators, offers a promising direction to address these limitations and enable scalable, efficient assembly for increasingly large and complex genomic datasets \[[1106.2603v1](http://arxiv.org/abs/1106.2603v1)\]\[[1801.04453v1](http://arxiv.org/abs/1801.04453v1)\]\[[2309.07270v2](http://arxiv.org/abs/2309.07270v2)\]\[[1512.01801v2](http://arxiv.org/abs/1512.01801v2)\]\[[2008.01237v1](http://arxiv.org/abs/2008.01237v1)\]\[[2207.04350v1](http://arxiv.org/abs/2207.04350v1)\]\[[2004.06719v3](http://arxiv.org/abs/2004.06719v3)\]\[[2407.07718v1](http://arxiv.org/abs/2407.07718v1)\]\[[2404.07164v2](http://arxiv.org/abs/2404.07164v2)\].
