## Related Works

The optimization of cloud-native applications, particularly those deployed using container orchestration platforms like Kubernetes, has been extensively studied with a focus on resource efficiency, cost management, and operational reliability. Kubernetes is widely acknowledged for its capabilities in deploying, managing, and scaling containerized microservices, yet challenges remain in optimizing both infrastructure and network costs within such environments.

Research into Kubernetes availability and management has demonstrated its ability to orchestrate microservices and maintain application availability through features like healing and redundancy, although some studies report significant service outages under default configurations, highlighting the need for further improvements in operational resilience \[[1901.04946](http://arxiv.org/abs/1901.04946)\]. Additionally, Kubernetes’ architecture, which relies on the strongly consistent etcd for cluster state storage, presents performance and scalability challenges, especially in edge computing scenarios where latency and availability are critical. Proposals to adopt eventual consistency models aim to enhance Kubernetes’ suitability for dynamic, performance-sensitive environments \[[2104.02423](http://arxiv.org/abs/2104.02423)\].

Cost optimization in cloud environments has been a growing focus, particularly within the FinOps discipline that integrates financial management with cloud operations. ABACUS, an automated FinOps service, exemplifies the approach of enforcing budgets, alerting on budget breaches, and incorporating Infrastructure-as-Code to predict deployment costs before resource provisioning, thereby offering a systematic mechanism for controlling cloud spend \[[2307.12479](http://arxiv.org/abs/2307.12479)\]. Similarly, SpotKube leverages Kubernetes with spot pricing and cluster autoscaling, using genetic algorithms to dynamically optimize resource allocation for microservices, balancing cost savings with performance and availability in public cloud settings \[[2405.12311](http://arxiv.org/abs/2405.12311)\]. These tools underscore the potential of combining container orchestration with intelligent cost management to achieve substantial operational savings.

Network costs within Kubernetes clusters, however, remain a relatively underexplored aspect of cost optimization. Extensions to Kubernetes networking, such as incorporating Segment Routing over IPv6 (SRv6) via the Calico CNI plugin, aim to improve performance and scalability in large-scale, distributed multi-datacenter deployments. This approach enables advanced traffic engineering capabilities while maintaining performance comparable to traditional overlays, suggesting avenues for optimizing network efficiency in complex Kubernetes environments \[[2301.01178](http://arxiv.org/abs/2301.01178)\]. Despite these advances, the financial impact of network usage in containerized cloud applications has not been thoroughly analyzed in prior work.

Broader cloud infrastructure cost optimization strategies, especially in AI and machine learning contexts, provide relevant insights into managing high-cost resources such as GPUs through techniques like model quantization and instance selection, achieving significant cost reductions \[[2307.12479](http://arxiv.org/abs/2307.12479)\]. While these techniques primarily target compute costs, they illustrate the effectiveness of specialized approaches that could inspire analogous methods for network cost management in Kubernetes.

Security considerations, though somewhat distinct from cost optimization, are crucial for the reliable operation of containerized applications. Best practices including role-based access control, security patching, and network-specific security policies form an essential part of Kubernetes management and impact operational stability and indirectly influence cost through mitigating vulnerabilities and service disruptions \[[2006.15275](http://arxiv.org/abs/2006.15275)\].

Workflow scheduling on Kubernetes has also been enhanced by frameworks like KubeAdaptor, which ensure alignment between workflow task execution order and Kubernetes scheduling to improve overall efficiency and resource usage \[[2207.01222](http://arxiv.org/abs/2207.01222)\]. Such optimizations contribute to minimizing resource wastage, which can translate into cost savings.

In summary, while extensive research addresses Kubernetes orchestration, availability, security, and cloud infrastructure cost optimization, the specific dimension of network cost analysis and optimization in Kubernetes clusters remains insufficiently addressed. This gap motivates the present work’s focus on measuring, modeling, and optimizing network expenditures within containerized cloud-native applications, thereby extending the FinOps discipline to encompass network financial management alongside compute and storage considerations.
