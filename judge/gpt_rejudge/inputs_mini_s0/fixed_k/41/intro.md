## Related Works

Serverless computing, particularly the Function-as-a-Service (FaaS) model, offers significant advantages including automatic scaling, efficient resource utilization, and a cost-effective pay-as-you-go pricing model. However, one of the most critical challenges affecting serverless performance is cold-start latency, which occurs when new function instances are initialized, causing noticeable delays in response times \[[2310.08437](http://arxiv.org/abs/2310.08437)\]. This latency is often exacerbated by unnecessary overheads such as the initialization of libraries that are rarely or never used during typical workloads \[[2406.11734](http://arxiv.org/abs/2406.11734)\]\[[2310.08437](http://arxiv.org/abs/2310.08437)\].

Efforts to mitigate cold-start latency have explored multiple dimensions, including infrastructure-level, application-level, and predictive resource management techniques. At the infrastructure level, maintaining pools of warm containers has been shown to reduce cold-start latency significantly. For example, a pool-based approach under the Knative Serving platform achieved an 85% reduction in P99 response time by pre-warming containers to serve incoming requests \[[1903.12221](http://arxiv.org/abs/1903.12221)\]\[[2504.11338](http://arxiv.org/abs/2504.11338)\]. Complementing this, Pagurus proposes inter-action container sharing, which allows borrowing warm containers from other actions to eliminate cold startup times, achieving function start times as low as 10ms even without dedicated warm containers \[[2108.1124](http://arxiv.org/abs/2108.11240)\].

Application-level optimizations focus on reducing code loading overheads, which have been identified as a major cold-start bottleneck. FaaSLight exemplifies this approach by constructing function-level call graphs to separate indispensable from optional code, loading the latter on demand. This method achieved up to 78.95% reduction in code loading latency and up to 42.05% in total response latency across various FaaS applications, without requiring platform modifications \[[2207.08175](http://arxiv.org/abs/2207.08175)\]. Similarly, LibProf targets Python-based serverless applications by profiling library usage dynamically to uncover inefficient library initializations. This guided optimization led to up to 2.26× speedup in cold-start time and 1.51× memory reduction, directly addressing workload-dependent inefficiencies missed by static analysis \[[2406.11734](http://arxiv.org/abs/2406.11734)\].

Predictive and machine learning approaches have also been applied to anticipate function invocations and optimize resource provisioning to reduce cold starts. Time series forecasting models like SARIMA have been used to predict request arrival patterns and adjust container provisioning accordingly, outperforming default Kubernetes autoscalers in reducing cold start delays and resource wastage \[[2206.15176](http://arxiv.org/abs/2206.15176)\]. More advanced deep learning techniques, such as Temporal Convolutional Networks (TCNs), have demonstrated superior performance in forecasting function arrival rates, enabling proactive resource allocation that outperforms other machine learning models for time series data \[[2304.00396](http://arxiv.org/abs/2304.00396)\]. Reinforcement learning methods leveraging Q-learning have been applied for on-demand cold start frequency reduction by proactively initializing functions based on system metrics, improving throughput and reducing resource wastage significantly \[[2308.07541](http://arxiv.org/abs/2308.07541)\]. Furthermore, transformer-based models have recently shown promise for accurate modeling of function initialization delays, achieving up to 79% cold start time reduction compared to conventional methods \[[2504.11338](http://arxiv.org/abs/2504.11338)\].

Snapshot-based warmup techniques like Prebaking and SEUSS provide another angle by capturing and restoring runtime snapshots to accelerate function startup. Prebaking, for example, improved startup times for simple and moderately complex functions by 25–33%, and reduced first request processing time by up to 69% \[[2105.13894](http://arxiv.org/abs/2105.13894)\]. In a related vein, proactive techniques such as the "freshen" primitive allow execution of preparatory tasks before function invocation to mitigate cold start overheads, offering further opportunities for latency reduction \[[2010.04312](http://arxiv.org/abs/2010.04312)\].

Other approaches explore resource management trade-offs between cold start latency and resource wastage. SPES uses fine-grained invocation pattern categorization to optimize function instance pre-loading and unloading, achieving nearly 50% reduction in cold start rates and over 56% reduction in wasted memory time \[[2403.17574](http://arxiv.org/abs/2403.17574)\]. ProFaaStinate proposes delaying asynchronous function calls to execute them at times of higher resource availability, reducing response latency by 54% and preventing system overload during peak periods \[[2309.15471](http://arxiv.org/abs/2309.15471)\]. HydraServe targets cold start latency in serverless large language model serving by distributing models proactively and consolidating pipelines, reducing cold start latency by 1.7–4.7× \[[2502.15524](http://arxiv.org/abs/2502.15524)\].

Studies on open-source serverless platforms reveal that simplistic autoscaling policies based solely on CPU or workload metrics are insufficient to handle cold starts effectively, underscoring the need for more nuanced approaches \[[1911.07449](http://arxiv.org/abs/1911.07449)\]. Additionally, efforts to improve robustness in heterogeneous serverless systems through probabilistic task pruning have demonstrated up to 35% improvements in meeting deadline requirements under oversubscription, indirectly benefiting cold start management \[[1905.04456](http://arxiv.org/abs/1905.04456)\].

Collectively, these works illustrate a broad spectrum of strategies addressing cold start latency through dynamic profiling, predictive analytics, container reuse, snapshot techniques, and machine learning. The proposed SLIMSTART tool builds on this foundation by focusing on profile-guided, workload-aware optimization of library initialization in serverless functions, using statistical sampling and call-path profiling to capture runtime inefficiencies and automate code transformations. This approach complements existing static and predictive methods by adapting continuously to workload changes, achieving significant improvements in cold-start latency, end-to-end function performance, and memory usage \[[2406.11734](http://arxiv.org/abs/2406.11734)\].
