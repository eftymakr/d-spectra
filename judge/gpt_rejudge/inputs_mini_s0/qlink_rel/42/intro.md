## Related Works

Cloud-native computing has evolved significantly with the widespread adoption of containerization technologies such as Docker and orchestration platforms like Kubernetes. These technologies enable rapid application deployment, scalability, and improved resource utilization by abstracting infrastructure management \[[2010.10350](http://arxiv.org/abs/2010.10350)\]\[[https://www.semanticscholar.org/paper/b5634b15badc73f3cda72b960fd51ef03ac1265d](https://www.semanticscholar.org/paper/b5634b15badc73f3cda72b960fd51ef03ac1265d)\]. Kubernetes, in particular, is widely recognized for its ability to automate container deployment, scaling, and management across clusters, fostering the microservices architectural style that enhances maintainability and availability \[[https://www.semanticscholar.org/paper/18a720c86ed6e166c26f7d39490bfd11b93ea3ec](https://www.semanticscholar.org/paper/18a720c86ed6e166c26f7d39490bfd11b93ea3ec)\]. However, the default Kubernetes scheduling and resource management mechanisms may not always align with optimized execution workflows, prompting frameworks like KubeAdaptor to integrate workflow-aware scheduling to improve efficiency and reduce resource overhead \[[2207.01222](http://arxiv.org/abs/2207.01222)\].

Resource management in cloud-native platforms has been studied extensively, focusing on performance optimization and overhead reduction for computationally intensive workloads such as big data and deep learning applications. Adjustments to default container and Kubernetes settings can drastically affect completion times and resource release behaviors, highlighting the impact of fine-tuned resource management schemes on operational efficiency \[[2010.10350](http://arxiv.org/abs/2010.10350)\]. Auto-scaling systems leveraging Kubernetes and monitoring tools like Prometheus have been designed to dynamically adjust application instances based on load, further improving resource utilization and service quality \[[https://www.semanticscholar.org/paper/4d4080e1a2e26fe1ead433741602ab6eccc22b72](https://www.semanticscholar.org/paper/4d4080e1a2e26fe1ead433741602ab6eccc22b72)\].

While Kubernetes offers robust functionality, security remains a critical concern. Studies systematizing Kubernetes security practices emphasize role-based access control (RBAC), pod and network security policies, and timely patching to mitigate vulnerabilities inherent in container orchestration environments \[[2006.15275](http://arxiv.org/abs/2006.15275)\]. Although security is paramount, it is distinct from cost optimization; nevertheless, secure configurations can influence operational costs and network traffic patterns.

The emerging discipline of FinOps integrates financial management with cloud operations to address the complexity of cloud cost optimization. FinOps frameworks provide visibility, accountability, and automation to manage cloud expenditures effectively. ABACUS, for example, is a FinOps service designed to enforce budget constraints by monitoring cloud usage, blocking deployments when budgets are breached, and alerting relevant teams. It also utilizes Infrastructure-as-Code to provide cost estimates before resource deployment, thus enabling proactive financial governance \[[2501.14753](http://arxiv.org/abs/2501.14753)\].

Cost optimization strategies for cloud and AI infrastructure have been comprehensively reviewed, encompassing traditional pricing models, resource allocation techniques, and AI/ML-specific optimizations such as model quantization and GPU instance selection. These approaches have demonstrated substantial cost savings (50-90%) in real-world deployments, yet the specific financial implications of network usage within containerized Kubernetes clusters have received limited attention \[[2307.12479](http://arxiv.org/abs/2307.12479)\]. Network costs, which can be significant in distributed cloud-native applications, require focused analysis to complement existing resource and compute cost optimizations.

Prior works have also explored container-based workflow orchestration and data management systems like Pachyderm, which leverage Kubernetes for scalable and reproducible bioinformatics pipelines. These frameworks underscore the importance of container orchestration beyond compute resource management, including data movement and network interactions, both of which bear cost implications \[[https://www.semanticscholar.org/paper/51e2cba5a013cbd11f2ab760a4e3906cfff44780](https://www.semanticscholar.org/paper/51e2cba5a013cbd11f2ab760a4e3906cfff44780)\]. Kubernetes scheduling research highlights ongoing challenges in balancing quality of service parameters such as response time, energy consumption, and resource utilization, often overlooking network traffic patterns and their associated costs \[[https://www.semanticscholar.org/paper/d11e5c5c08af88ee8abb9ebaa166b1d6fd198501](https://www.semanticscholar.org/paper/d11e5c5c08af88ee8abb9ebaa166b1d6fd198501)\].

In summary, although existing literature provides extensive insights into Kubernetes orchestration, resource management, security, and cloud cost optimization, the analysis of network costs within Kubernetes-based containerized applications remains underexplored. This paper contributes by focusing on network usage and its financial impact in Kubernetes clusters, bridging a critical gap that complements FinOps practices and system-level optimization strategies.
