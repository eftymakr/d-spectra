## Related Works

Serverless computing, particularly the Function-as-a-Service (FaaS) model, has gained prominence for abstracting server management, enabling automatic scaling, and offering cost-effective resource utilization \[[1911.01296](http://arxiv.org/abs/1911.01296)\]. Despite these advantages, cold-start latency—a delay incurred when initializing function instances—remains a critical bottleneck affecting application responsiveness and end-to-end performance \[[https://www.semanticscholar.org/paper/d911b03bfda4fc6fc92f8080bb81b3a967d6a9e7](https://www.semanticscholar.org/paper/d911b03bfda4fc6fc92f8080bb81b3a967d6a9e7)\]. This latency is largely due to the overhead of provisioning runtime environments, loading code and dependencies, and initializing libraries, many of which may be infrequently used or unnecessary under typical workloads \[[https://www.semanticscholar.org/paper/1447da2da7c926dc68e31a89461409d09b08d77e](https://www.semanticscholar.org/paper/1447da2da7c926dc68e31a89461409d09b08d77e)\].

Prior research has extensively explored cold-start mitigation strategies across various dimensions. One prominent approach involves maintaining pools of warm containers to reduce cold-start delays by reusing pre-initialized runtime environments. For example, a pool-based method showed an 85% reduction in the 99th percentile response time by keeping ready-to-serve function instances \[[https://www.semanticscholar.org/paper/81b8db7a20f1aa859143c716b38a1443e3eca9a0](https://www.semanticscholar.org/paper/81b8db7a20f1aa859143c716b38a1443e3eca9a0)\]. Techniques such as container snapshotting and restoration, as implemented in Catalyzer, achieve sub-millisecond startup times by restoring function instances from checkpointed snapshots, significantly lowering initialization overhead \[[https://www.semanticscholar.org/paper/f14446970a5ed7145a6d350e1aff07ca203cece8](https://www.semanticscholar.org/paper/f14446970a5ed7145a6d350e1aff07ca203cece8)\]\[[https://www.semanticscholar.org/paper/ab1c0062964a2df3d7f8d11da4a774530286b801](https://www.semanticscholar.org/paper/ab1c0062964a2df3d7f8d11da4a774530286b801)\]. Similarly, prebaking functions via process checkpoint/restore (CRIU) reduces startup time by up to 71%, demonstrating the importance of runtime initialization optimization \[[https://www.semanticscholar.org/paper/ab1c0062964a2df3d7f8d11da4a774530286b801](https://www.semanticscholar.org/paper/ab1c0062964a2df3d7f8d11da4a774530286b801)\].

Application-level optimizations have gained attention as cold starts are often dominated by code loading latency. FaaSLight exemplifies this by separating indispensable from optional code via call-graph analysis, achieving up to 78.95% reduction in code loading latency and a substantial overall latency improvement \[[2207.08175](http://arxiv.org/abs/2207.08175)\]. Complementary to static analysis, profile-guided methods like LibProf identify inefficient library usage dynamically to further reduce cold-start overhead \[[https://www.semanticscholar.org/paper/1447da2da7c926dc68e31a89461409d09b08d77e](https://www.semanticscholar.org/paper/1447da2da7c926dc68e31a89461409d09b08d77e)\]. These approaches highlight that workload-dependent inefficiencies cannot be fully addressed by static code analysis alone, necessitating adaptive optimization based on runtime behavior.

Predictive and adaptive resource management techniques also contribute to mitigating cold starts. Reinforcement learning (Q-learning) agents have been employed to predict invocation patterns and pre-warm function containers accordingly, reducing cold-start frequency without excessive resource consumption \[[https://www.semanticscholar.org/paper/96d4fea8d034a7605af936f2e2b6a44becdf6585](https://www.semanticscholar.org/paper/96d4fea8d034a7605af936f2e2b6a44becdf6585)\]. Similarly, adaptive warm-up and container pool scaling strategies optimize resource allocation dynamically to balance latency and cost \[[https://www.semanticscholar.org/paper/81b8db7a20f1aa859143c716b38a1443e3eca9a0](https://www.semanticscholar.org/paper/81b8db7a20f1aa859143c716b38a1443e3eca9a0)\]. Caching-inspired keep-alive policies, such as FaasCache, exploit workload diversity to maintain hot containers more effectively, reducing cold-start overhead by over 3× and lowering resource usage by 30% \[[https://www.semanticscholar.org/paper/3c05fec4087d94c61233a482e59b613388b2c3ae](https://www.semanticscholar.org/paper/3c05fec4087d94c61233a482e59b613388b2c3ae)\].

Function chaining and workflow orchestration introduce additional challenges, notably cascading cold starts where sequential function invocations each incur startup latency. Xanadu addresses this by speculative and just-in-time provisioning of resources across function chains, significantly reducing cumulative latency and outperforming existing platforms by an order of magnitude \[[https://www.semanticscholar.org/paper/1cd137e77753ee6c51c97c520d64f91d484dbddc](https://www.semanticscholar.org/paper/1cd137e77753ee6c51c97c520d64f91d484dbddc)\]. Middleware approaches leveraging application knowledge to trigger function pre-warming based on function composition have demonstrated cold-start reductions of 40–80% with minimal overhead \[[https://www.semanticscholar.org/paper/1447da2da7c926dc68e31a89461409d09b08d77e](https://www.semanticscholar.org/paper/1447da2da7c926dc68e31a89461409d09b08d77e)\].

Comprehensive surveys and systematic reviews classify cold-start mitigation techniques into categories such as caching, application-level optimization, and machine learning-based solutions, recognizing the multifaceted nature of the problem and the need for combined strategies \[[https://www.semanticscholar.org/paper/d911b03bfda4fc6fc92f8080bb81b3a967d6a9e7](https://www.semanticscholar.org/paper/d911b03bfda4fc6fc92f8080bb81b3a967d6a9e7)\]\[[2310.08437](http://arxiv.org/abs/2310.08437)\]. These reviews emphasize the trade-off between reducing latency and resource cost, and the importance of workload characterization to tailor solutions effectively \[[2003.03423](http://arxiv.org/abs/2003.03423)\].

In contrast to existing static and coarse-grained methods, SLIMSTART’s profile-guided optimization leverages statistical sampling and call-path profiling to capture fine-grained, workload-dependent library usage patterns. This enables targeted code transformation and pruning of rarely used libraries during cold starts, improving initialization latency, end-to-end performance, and memory utilization. SLIMSTART’s integration into CI/CD pipelines supports continuous adaptation to evolving workloads, addressing a key limitation in prior approaches that rely on static or heuristic-based optimizations \[[2207.08175](http://arxiv.org/abs/2207.08175)\]\[[https://www.semanticscholar.org/paper/1447da2da7c926dc68e31a89461409d09b08d77e](https://www.semanticscholar.org/paper/1447da2da7c926dc68e31a89461409d09b08d77e)\].

Overall, the landscape of cold-start mitigation in serverless computing spans infrastructure-level innovations (e.g., container pooling, snapshotting), application-level optimizations (e.g., code loading reduction, library pruning), and intelligent resource management (e.g., learning-based prediction, caching policies). SLIMSTART builds upon these foundations by combining application-aware profiling with automated code optimization to effectively reduce cold-start overheads in diverse serverless workloads.
