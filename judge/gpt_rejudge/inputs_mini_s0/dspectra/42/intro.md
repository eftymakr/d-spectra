## Related Works

The landscape of cloud-native computing and container orchestration has significantly evolved, with Kubernetes emerging as the de facto standard for managing containerized applications. This evolution has spurred extensive research into performance optimization, security, and cost management within Kubernetes environments.

Cost optimization in cloud-native environments has become increasingly critical as organizations scale their Kubernetes deployments. FinOps, a discipline combining financial management and cloud operations, has been developed to address these challenges by optimizing cloud expenditures and enforcing budget accountability . ABACUS exemplifies this approach, offering automated budget analysis, spending surveillance, and deployment blocking mechanisms to maintain cost control within cloud infrastructures . Despite these advancements, the specific domain of network cost optimization within Kubernetes clusters remains underexplored, highlighting a gap that this paper aims to fill .

Significant research has focused on resource allocation and scheduling within Kubernetes to improve operational efficiency and reduce waste. Frameworks like KubeAdaptor integrate workflow systems with Kubernetes to preserve optimized task execution orders, thereby improving execution time and resource usage \[[2006.15275](http://arxiv.org/abs/2006.15275)\]\[[2301.08409](http://arxiv.org/abs/2301.08409)\]. Adaptive resource allocation schemes further enhance efficiency by anticipating workload spikes and dynamically scaling resources, which indirectly contributes to cost savings by reducing over-provisioning \[[2301.08409](http://arxiv.org/abs/2301.08409)\]. These works provide foundational insights into resource management but largely emphasize compute and memory resources rather than network usage and costs.

From a security perspective, Kubernetes manifests and Helm charts—the primary configuration formats for Kubernetes deployments—have been shown to frequently contain misconfigurations and vulnerabilities that can compromise cluster security \[[2501.14753](http://arxiv.org/abs/2501.14753)\]\[[https://www.semanticscholar.org/paper/61020665f9134e56009b6e10606fc21348f59d53](https://www.semanticscholar.org/paper/61020665f9134e56009b6e10606fc21348f59d53)\]\[[https://www.semanticscholar.org/paper/b0fa8fd1b1638f4afad41956b65a15a9096e309f](https://www.semanticscholar.org/paper/b0fa8fd1b1638f4afad41956b65a15a9096e309f)\]\[[https://www.semanticscholar.org/paper/3c2ac07d840d148085dc50dfa5bb9aebd33fabc9](https://www.semanticscholar.org/paper/3c2ac07d840d148085dc50dfa5bb9aebd33fabc9)\]\[[https://www.semanticscholar.org/paper/c5d1825555ad1c38501d67496e2cdc251d2d6de4](https://www.semanticscholar.org/paper/c5d1825555ad1c38501d67496e2cdc251d2d6de4)\]\[[https://www.semanticscholar.org/paper/8e853411a33651b57251f5f2bac46b774a180607](https://www.semanticscholar.org/paper/8e853411a33651b57251f5f2bac46b774a180607)\]. While these studies largely focus on the security implications, they underscore the complexity of Kubernetes configurations and the importance of rigorous validation, which indirectly affects operational costs through potential downtime or breach remediation. Centralized logging and static analysis tools have been proposed to detect and mitigate misconfigurations effectively \[[2408.03714](http://arxiv.org/abs/2408.03714)\]. Security remains a critical factor in overall cluster management but is distinct from cost optimization, particularly network-related expenditures.

The broader domain of cloud infrastructure cost optimization includes strategies for AI and machine learning workloads, which often dominate cloud budgets due to resource-intensive GPU consumption . Techniques such as model quantization, GPU instance selection, and inference optimization have demonstrated substantial cost savings in AI/ML workloads . Though informative, these techniques primarily target processing costs rather than network traffic or egress fees, which are a growing concern in distributed Kubernetes environments.

Research on Kubernetes scheduling has explored various Quality of Service (QoS) parameters, resource utilization, and energy efficiency to improve container orchestration \[[https://www.semanticscholar.org/paper/d11e5c5c08af88ee8abb9ebaa166b1d6fd198501](https://www.semanticscholar.org/paper/d11e5c5c08af88ee8abb9ebaa166b1d6fd198501)\]\[[2010.10350](http://arxiv.org/abs/2010.10350)\]. These scheduling improvements can reduce unnecessary resource consumption, including network bandwidth, but detailed analyses of network cost implications remain limited. Similarly, efforts to extend Kubernetes for edge environments address latency and availability challenges but do not focus specifically on network cost optimization \[[2104.02423](http://arxiv.org/abs/2104.02423)\].

Several studies emphasize the importance of container image management and deployment practices impacting both security and operational costs. For example, many Helm charts use outdated container images with known vulnerabilities, indirectly increasing the risk and potential cost of maintenance \[[https://www.semanticscholar.org/paper/8e853411a33651b57251f5f2bac46b774a180607](https://www.semanticscholar.org/paper/8e853411a33651b57251f5f2bac46b774a180607)\]. Moreover, the complexity of managing microservice architectures via Kubernetes affects availability and scalability, factors that contribute to overall cost but have not been explicitly connected to network expenditure in prior work \[[https://www.semanticscholar.org/paper/18a720c86ed6e166c26f7d39490bfd11b93ea3ec](https://www.semanticscholar.org/paper/18a720c86ed6e166c26f7d39490bfd11b93ea3ec)\].

In summary, while extensive research addresses Kubernetes security, resource scheduling, workflow execution, and general cloud cost management, the explicit analysis of network usage and cost implications for containerized applications on Kubernetes remains sparse. This paper contributes to filling this gap by combining measurement, experimentation, and cost modeling to provide actionable insights for FinOps practitioners focusing on network cost optimization in cloud-native environments.
