## Related Works

Serverless computing has emerged as a transformative cloud paradigm, abstracting server management and enabling automatic scaling, efficient resource utilization, and cost-effective pricing models \[[2310.08437](http://arxiv.org/abs/2310.08437)\]. However, the cold-start latency—delay incurred when initializing function instances—remains a fundamental bottleneck affecting performance and user experience \[[2310.08437](http://arxiv.org/abs/2310.08437)\]. This latency primarily stems from the overhead of provisioning runtime containers, loading application code, and initializing dependencies, which can range from hundreds of milliseconds to several seconds \[[https://www.semanticscholar.org/paper/f14446970a5ed7145a6d350e1aff07ca203cece8](https://www.semanticscholar.org/paper/f14446970a5ed7145a6d350e1aff07ca203cece8)\]\[[https://www.semanticscholar.org/paper/ab1c0062964a2df3d7f8d11da4a774530286b801](https://www.semanticscholar.org/paper/ab1c0062964a2df3d7f8d11da4a774530286b801)\].

Early efforts to mitigate cold starts focused on maintaining pools of warm containers to reduce startup latency. For instance, a pool-based approach demonstrated an 85% reduction in tail latency by keeping pre-initialized function instances ready to serve requests \[[https://www.semanticscholar.org/paper/96d4fea8d034a7605af936f2e2b6a44becdf6585](https://www.semanticscholar.org/paper/96d4fea8d034a7605af936f2e2b6a44becdf6585)\]. Complementary techniques employ adaptive warm-up strategies that predict function invocation patterns to pre-warm containers dynamically, balancing latency reduction with resource efficiency \[[https://www.semanticscholar.org/paper/81b8db7a20f1aa859143c716b38a1443e3eca9a0](https://www.semanticscholar.org/paper/81b8db7a20f1aa859143c716b38a1443e3eca9a0)\]\[[https://www.semanticscholar.org/paper/27cd21426fe51167dd6ac79d1c83db55a07a2046](https://www.semanticscholar.org/paper/27cd21426fe51167dd6ac79d1c83db55a07a2046)\]. Reinforcement learning methods have also been proposed to intelligently manage container lifecycle and scale resources based on workload patterns, further reducing cold-start frequency without excessive resource consumption \[[https://www.semanticscholar.org/paper/96d4fea8d034a7605af936f2e2b6a44becdf6585](https://www.semanticscholar.org/paper/96d4fea8d034a7605af936f2e2b6a44becdf6585)\]\[[https://www.semanticscholar.org/paper/27cd21426fe51167dd6ac79d1c83db55a07a2046](https://www.semanticscholar.org/paper/27cd21426fe51167dd6ac79d1c83db55a07a2046)\]\[[https://www.semanticscholar.org/paper/891a89fad669dc7d107ad2d5a047b288b5cc9832](https://www.semanticscholar.org/paper/891a89fad669dc7d107ad2d5a047b288b5cc9832)\].

Another prominent direction targets startup overhead by optimizing container and runtime initialization itself. Catalyzer introduced an initialization-less booting mechanism that restores function instances from checkpoint images rather than booting from scratch, achieving sub-millisecond startup latencies and strong isolation \[[https://www.semanticscholar.org/paper/f14446970a5ed7145a6d350e1aff07ca203cece8](https://www.semanticscholar.org/paper/f14446970a5ed7145a6d350e1aff07ca203cece8)\]. Similarly, prebaking techniques using process checkpoint/restore mechanisms have demonstrated up to 70% reductions in startup times by capturing and restoring runtime states of warm functions \[[https://www.semanticscholar.org/paper/ab1c0062964a2df3d7f8d11da4a774530286b801](https://www.semanticscholar.org/paper/ab1c0062964a2df3d7f8d11da4a774530286b801)\]. These approaches highlight the critical role of runtime initialization in cold-start delay.

At the application level, significant overhead arises from loading unused or rarely used libraries during function startup. FaaSLight addresses this by separating indispensable from optional code via function-level call graphs, reducing code loading latency by up to 79% and total response latency by up to 42% \[[https://www.semanticscholar.org/paper/b99668ae35c4b6796b827657a318fe4b84a757ff](https://www.semanticscholar.org/paper/b99668ae35c4b6796b827657a318fe4b84a757ff)\]. This approach aligns with the observation that static analysis alone is insufficient to capture workload-dependent inefficiencies, necessitating profile-guided or dynamic methods to optimize code loading and library usage effectively.

Workflows and function chains introduce additional challenges due to cascading cold starts, where sequential functions in a workflow trigger cumulative latency. Xanadu mitigates this by employing speculative and just-in-time provisioning strategies to nearly eliminate cascading cold start overheads, outperforming existing platforms by an order of magnitude \[[https://www.semanticscholar.org/paper/1cd137e77753ee6c51c97c520d64f91d484dbddc](https://www.semanticscholar.org/paper/1cd137e77753ee6c51c97c520d64f91d484dbddc)\]. This highlights the importance of workflow-aware optimizations in complex serverless applications.

Recent advances also explore AI-driven optimization frameworks for serverless environments, including edge computing contexts. ATOM utilizes deep reinforcement learning to predict cold-start occurrences, optimizing resource allocation in resource-constrained edge devices while considering energy consumption and carbon emissions \[[https://www.semanticscholar.org/paper/891a89fad669dc7d107ad2d5a047b288b5cc9832](https://www.semanticscholar.org/paper/891a89fad669dc7d107ad2d5a047b288b5cc9832)\]. Similarly, temporal convolutional networks have been used to forecast function invocation patterns, enabling proactive scaling and resource management \[[https://www.semanticscholar.org/paper/27cd21426fe51167dd6ac79d1c83db55a07a2046](https://www.semanticscholar.org/paper/27cd21426fe51167dd6ac79d1c83db55a07a2046)\].

Resource scheduling and pre-warming frameworks like SSC combine gradient-based container pre-warming with workflow-aware resource allocation to reduce cold start hit rates by nearly 50% and cut costs by approximately 30% \[[https://www.semanticscholar.org/paper/fbf4355d06ddb5f6c81e67cffadf57f6939b8940](https://www.semanticscholar.org/paper/fbf4355d06ddb5f6c81e67cffadf57f6939b8940)\]. These integrated approaches underscore the need for holistic solutions that jointly address cold start latency and resource efficiency.

Overall, the literature reveals a broad spectrum of complementary strategies for cold-start mitigation: container pool management, adaptive and predictive pre-warming, runtime checkpoint-restore optimizations, application-level code loading reductions, workflow-aware provisioning, and AI-driven resource scheduling \[[2310.08437](http://arxiv.org/abs/2310.08437)\]\[[https://www.semanticscholar.org/paper/f14446970a5ed7145a6d350e1aff07ca203cece8](https://www.semanticscholar.org/paper/f14446970a5ed7145a6d350e1aff07ca203cece8)\]\[[https://www.semanticscholar.org/paper/b99668ae35c4b6796b827657a318fe4b84a757ff](https://www.semanticscholar.org/paper/b99668ae35c4b6796b827657a318fe4b84a757ff)\]\[[https://www.semanticscholar.org/paper/81b8db7a20f1aa859143c716b38a1443e3eca9a0](https://www.semanticscholar.org/paper/81b8db7a20f1aa859143c716b38a1443e3eca9a0)\]\[[https://www.semanticscholar.org/paper/96d4fea8d034a7605af936f2e2b6a44becdf6585](https://www.semanticscholar.org/paper/96d4fea8d034a7605af936f2e2b6a44becdf6585)\]\[[https://www.semanticscholar.org/paper/27cd21426fe51167dd6ac79d1c83db55a07a2046](https://www.semanticscholar.org/paper/27cd21426fe51167dd6ac79d1c83db55a07a2046)\]\[[https://www.semanticscholar.org/paper/fbf4355d06ddb5f6c81e67cffadf57f6939b8940](https://www.semanticscholar.org/paper/fbf4355d06ddb5f6c81e67cffadf57f6939b8940)\]\[[https://www.semanticscholar.org/paper/ab1c0062964a2df3d7f8d11da4a774530286b801](https://www.semanticscholar.org/paper/ab1c0062964a2df3d7f8d11da4a774530286b801)\]\[[https://www.semanticscholar.org/paper/891a89fad669dc7d107ad2d5a047b288b5cc9832](https://www.semanticscholar.org/paper/891a89fad669dc7d107ad2d5a047b288b5cc9832)\]\[[https://www.semanticscholar.org/paper/1cd137e77753ee6c51c97c520d64f91d484dbddc](https://www.semanticscholar.org/paper/1cd137e77753ee6c51c97c520d64f91d484dbddc)\]. The proposed SLIMSTART tool builds on these insights by introducing profile-guided optimization focused specifically on workload-dependent inefficient library usage patterns, enabling automated code transformations that reduce initialization overhead and memory footprint while adapting continuously through integration with CI/CD pipelines.

This approach addresses the limitations of static analysis techniques and complements existing container and application-level optimizations, positioning SLIMSTART as a novel contribution targeting a critical aspect of cold-start inefficiency in serverless computing.
