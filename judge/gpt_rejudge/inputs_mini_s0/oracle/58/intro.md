## Related Works

Table discovery has been an active research area addressing the challenge of retrieving relevant tables from large repositories or data lakes. Traditional methods typically rely on keyword queries or query tables to locate candidate tables, which often generate large, imprecise result sets requiring manual filtering \[[1802.06159](http://arxiv.org/abs/1802.06159)\]. This limitation has motivated recent efforts to incorporate richer semantic understanding and structural awareness into table retrieval systems, as well as to support more expressive query modalities including natural language (NL).

Early work in ad hoc table retrieval explored semantic matching between keyword queries and tables by representing both in multiple semantic spaces, combining sparse and dense vector representations, and applying supervised ranking models \[[1802.06159](http://arxiv.org/abs/1802.06159)\]. While effective for keyword-based retrieval, these approaches do not fully capture complex table layouts or multi-granular content dependencies, which are essential for understanding diverse real-world tables. To address this, graph-based methods represent tables as tabular graphs with nodes for cells, rows, and columns, and use graph transformers to encode both content and layout structures, improving robustness and generalizability across datasets \[[2105.01736](http://arxiv.org/abs/2105.01736)\].

Recent advances also include structure-aware language models like StruBERT, which fuse textual and structural information of tables to generate context-aware representations for various table-related tasks such as keyword- and content-based retrieval, and table similarity matching \[[2203.14278](http://arxiv.org/abs/2203.14278)\]. Such models demonstrate substantial improvements over prior methods by jointly modeling textual metadata and tabular structure.

Beyond retrieval, joinable and unionable table discovery in data lakes has been a significant focus, aiming to support data integration and enrichment tasks. Conventional equi-join approaches are limited by exact matching constraints and fail to tolerate misspellings or semantic variations. Embedding-based frameworks such as PEXESO and DeepJoin leverage high-dimensional vector representations of column values and pre-trained language models to perform semantic joins efficiently at scale, with DeepJoin achieving superior precision and faster retrieval times through approximate nearest neighbor search and fine-tuned contextual embeddings \[[2010.13273](http://arxiv.org/abs/2010.13273)\]\[[2212.07588](http://arxiv.org/abs/2212.07588)\]. Similarly, union search methods like SANTOS advance unionability definitions by considering semantic relationships between column pairs, derived from external knowledge bases or synthesized from the data lake itself, improving union search accuracy beyond schema or domain similarity alone \[[2209.13589](http://arxiv.org/abs/2209.13589)\].

End-to-end frameworks such as Starmie utilize contrastive learning on column representations extracted from pre-trained language models to capture rich contextual semantics for dataset discovery tasks, achieving notable gains in effectiveness and query processing efficiency by employing indexing structures like HNSW for fast retrieval \[[2210.01922](http://arxiv.org/abs/2210.01922)\]. Other approaches like TURL leverage pre-training with structure-aware transformers and masked entity recovery objectives to learn deep contextualized representations of relational tables, enabling wide applicability across table understanding tasks with minimal fine-tuning \[[2006.14806](http://arxiv.org/abs/2006.14806)\].

Incorporating natural language into table discovery has also gained attention. Systems like Solo propose self-supervised strategies to generate training data and train discovery models capable of understanding natural language questions directly, significantly advancing beyond traditional keyword-based search methods \[[2301.0356](http://arxiv.org/abs/2301.03560)\]. These approaches address challenges in dataset assembly, table representation, and relevance modeling essential for natural language-driven table retrieval.

Data enrichment and augmentation systems complement discovery efforts by selecting joinable tables and relevant columns from data lakes to improve predictive model accuracy. For instance, automatic relational data augmentation frameworks and table enrichment systems implement multi-stage pipelines combining join row search, table selection, alignment, and feature evaluation to efficiently produce enriched datasets tailored for machine learning tasks \[[2003.09758](http://arxiv.org/abs/2003.09758)\]\[[2204.08235](http://arxiv.org/abs/2204.08235)\]. These systems depend heavily on accurate and scalable join and union discovery methods.

Despite these advances, current methods predominantly focus on either keyword or query-table-based retrieval, with limited support for combining query tables with complex natural language conditions to refine search results. Our proposed task of NL-conditional table discovery (nlcTD) addresses this gap by enabling users to specify both a query table and expressive NL requirements, which is a more practical and powerful paradigm for real-world data exploration. The nlcTables benchmark, with its diverse queries spanning NL-only, union, join, and fuzzy conditions, as well as extensive annotations and candidate tables, facilitates systematic evaluation and development of methods capable of handling this challenging scenario.

In summary, existing literature provides a rich foundation in semantic and structural table representation, join and union discovery, and natural language integration for table retrieval. However, there remains a substantial performance gap in holistic approaches that combine query tables with natural language conditions for refined table discovery, motivating the introduction of nlcTD and the nlcTables benchmark to advance research in this critical area \[[1802.06159](http://arxiv.org/abs/1802.06159)\]\[[2105.01736](http://arxiv.org/abs/2105.01736)\]\[[2203.14278](http://arxiv.org/abs/2203.14278)\]\[[2010.13273](http://arxiv.org/abs/2010.13273)\]\[[2209.13589](http://arxiv.org/abs/2209.13589)\]\[[2210.01922](http://arxiv.org/abs/2210.01922)\]\[[2212.07588](http://arxiv.org/abs/2212.07588)\]\[[2006.14806](http://arxiv.org/abs/2006.14806)\]\[[2301.0356](http://arxiv.org/abs/2301.03560)\]\[[2003.09758](http://arxiv.org/abs/2003.09758)\]\[[2204.08235](http://arxiv.org/abs/2204.08235)\].
