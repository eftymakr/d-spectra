## Related Works

Serverless computing has emerged as a transformative cloud paradigm by abstracting server management and providing automatic scaling, efficient resource utilization, and pay-per-use pricing models. However, the cold-start latency problem—where function invocations experience delays due to initialization overhead—remains a major obstacle impacting overall system performance . This latency often stems from the initialization of libraries and application code that are infrequently or never used during typical function executions, leading to wasted resources and increased response times .

Several studies have analyzed the characteristics and challenges of serverless workloads. For example, an extensive characterization of production Function-as-a-Service (FaaS) workloads demonstrated a highly skewed invocation frequency distribution, with most functions invoked infrequently, complicating resource provisioning and cold-start mitigation \[[2003.03423](http://arxiv.org/abs/2003.03423)\]. Such workload variability introduces challenges for container provisioning and resource management frameworks, which often treat microservice-based serverless applications like monolithic ones, resulting in over-provisioning and underutilization \[[2008.12819](http://arxiv.org/abs/2008.12819)\]. Addressing these inefficiencies, frameworks like Fifer adopt function-aware container scaling and intelligent request batching to improve container utilization and reduce energy consumption without violating service-level objectives (SLOs) \[[2008.12819](http://arxiv.org/abs/2008.12819)\].

In tackling cold-start latency specifically, both static and dynamic approaches have been proposed. Static analysis techniques can identify unreachable or unnecessary libraries but typically fail to capture workload-dependent inefficiencies caused by rarely used code paths, limiting their effectiveness . Complementing this, application-level optimizations such as FaaSLight leverage function-level call graphs to distinguish indispensable from optional code, loading optional components on demand. This approach significantly reduces code loading latency—by up to 78.95% in some cases—and consequently decreases total response latency by over 40% on average . Its platform- and language-agnostic design enhances general applicability across diverse FaaS environments.

Dynamic optimization strategies focus on proactive resource management and runtime adaptations. For example, pooling warm containers to reduce cold starts has demonstrated an 85% reduction in tail latency . Predictive methods employing time-series forecasting and temporal convolutional networks have further improved container provisioning by anticipating function invocation patterns, thereby reducing cold-start frequency and resource wastage . Additionally, proactive techniques like freshen enable execution of preparatory functionality before function invocation to mitigate cold-start overheads .

Profiling-based tools like LibProf identify inefficient library initialization patterns in Python serverless applications and achieve up to 2.26× speedup in cold-start execution time by focusing optimization efforts on costly library usage \[[2003.03423](http://arxiv.org/abs/2003.03423)\]. These profiling insights align with the motivations behind SLIMSTART’s profile-guided optimizations, which combine statistical sampling and call-path profiling to detect and mitigate inefficient library usage patterns dynamically, enabling more adaptive and workload-specific cold-start reductions.

The collective body of work highlights the multifaceted nature of cold-start latency mitigation in serverless computing, including workload characterization, static code analysis, dynamic resource management, application-level optimizations, and profiling-guided enhancements. SLIMSTART contributes to this landscape by integrating profile-driven, automated code transformations within CI/CD pipelines, allowing continuous adaptation to evolving workloads, and achieving substantial improvements in initialization latency, end-to-end latency, and memory usage. This approach addresses the limitations of purely static or reactive methods by leveraging runtime insights for targeted optimization.

Furthermore, research into microservice-aware scheduling frameworks such as Fifer demonstrates the importance of resource-conscious container management to improve utilization without compromising SLOs, complementing SLIMSTART’s focus on reducing initialization overhead \[[2008.12819](http://arxiv.org/abs/2008.12819)\]. Together, these efforts underscore the need for holistic solutions that optimize both the resource management and application execution layers to tackle the cold-start problem effectively.
