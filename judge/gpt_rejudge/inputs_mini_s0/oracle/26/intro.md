## Related Works

Differential Privacy (DP) has established itself as the standard for privacy-preserving data analysis, commonly implemented in either the central or local model. The central model assumes a trusted data aggregator, which enables higher utility and algorithmic expressibility but requires trust in the server. Conversely, the local model removes this trust assumption by having data owners perturb their data locally, though at the cost of reduced accuracy and expressiveness \[[1902.07756](http://arxiv.org/abs/1902.07756)\]. Addressing the limitations of these models, Cryptε introduced a framework employing two non-colluding untrusted servers that execute DP programs on encrypted data, thereby achieving central-model utility without requiring a trusted party \[[1902.07756](http://arxiv.org/abs/1902.07756)\].

While DP provides strong privacy guarantees, its implementation can be undermined by malicious entities manipulating noise generation or execution. This vulnerability introduces an attack surface not originally accounted for, where a malicious server might generate noise incorrectly or correlate noise samples, casting doubt on the veracity of the DP outputs. To counter such threats, the concept of Verifiable Differential Privacy (VDP) has been proposed. VDP requires the entity releasing DP outputs to produce zero-knowledge proofs (ZKPs) that the noise was generated correctly and that the output complies with DP guarantees. This approach closes the loophole where randomness can be misused to mask malfeasance \[[2208.09011](http://arxiv.org/abs/2208.09011)\]. However, while ZKPs provide a strong sufficiency condition for verifiability, they are not strictly necessary, as alternative cryptographic methods can enforce compliance without disclosing noise randomness \[[2208.09011](http://arxiv.org/abs/2208.09011)\].

Recent work has demonstrated practical implementations of verifiable DP using ZKPs for counting queries, balancing theoretical soundness with deployability \[[2208.09011](http://arxiv.org/abs/2208.09011)\]. These methods enable efficient verification that the output is both differentially private and reliable, even in the presence of adversarial servers. The necessity of computational assumptions for verifiability is also established, highlighting the inherent trade-offs between information-theoretic and computational privacy under verifiability constraints \[[2208.09011](http://arxiv.org/abs/2208.09011)\].

In the local DP setting, where clients randomize data before sending it to the server, additional vulnerabilities arise from malicious data providers manipulating their randomized outputs. Since the server estimates distribution parameters solely from randomized data, attackers can skew results undetectably, exploiting the plausible deniability afforded by local randomization mechanisms. To mitigate this, verifiable randomization mechanisms have been proposed that allow the server to verify that each client executed the agreed-upon randomization correctly, thereby preventing manipulation attacks and improving robustness of local DP protocols \[[2104.06569](http://arxiv.org/abs/2104.06569)\]. These mechanisms have been extended to multiple state-of-the-art local DP protocols, showing acceptable overheads while significantly reducing expected damage from attacks \[[2104.06569](http://arxiv.org/abs/2104.06569)\].

Cryptographic randomized response techniques have long been studied as a method to guarantee unconditional privacy for respondents, ensuring that no participant can disproportionately influence the aggregate tally beyond their own input. These techniques use traditional and quantum cryptographic primitives to prevent cheating and manipulation, underpinning the security of randomized mechanisms used in DP \[[https://doi.org/10.1007/978-3-540-24632-9\_31](https://doi.org/10.1007/978-3-540-24632-9\_31)\].

Further advancing the secure implementation of DP, secure multiparty computation (MPC) has been employed to sample noise jointly in distributed settings, enabling DP with utility comparable to the central model but without requiring a fully trusted server. Efficient protocols for securely sampling discrete noise distributions (e.g., discrete Laplace or Gaussian) are essential to this approach. While many protocols exist, they differ in security assumptions and performance, and benchmarking efforts have been conducted to evaluate their efficiency and resilience against Byzantine adversaries \[[2409.10667](http://arxiv.org/abs/2409.10667)\]. These efforts inform the design of noise sampling protocols that maintain DP guarantees even when some parties are malicious.

Combining cryptography and DP, homomorphic encryption and MPC have been used to build verifiable DP systems where computations on encrypted data ensure privacy and correctness without revealing sensitive inputs. Such approaches provide strong guarantees against server misbehavior, complementing the ZKP-based methods and enriching the toolset for verifiable DP \[[1902.07756](http://arxiv.org/abs/1902.07756)\]\[[2409.10667](http://arxiv.org/abs/2409.10667)\].

The present work builds upon these foundational efforts by defining Verifiable Distributed Differential Privacy (VDDP), which extends verifiability to a client-server-verifier architecture and addresses malicious noise generation and correlation in distributed DP mechanisms. By developing the Verifiable Distributed Discrete Laplacian Mechanism (VDDLM) and an improved Verifiable Randomized Response (VRR) protocol for local DP, this work achieves orders-of-magnitude improvements in proof generation efficiency and reductions in communication and verification overhead, advancing practical verifiable DP deployments \[[2208.09011](http://arxiv.org/abs/2208.09011)\]\[[2104.06569](http://arxiv.org/abs/2104.06569)\].

In summary, the landscape of verifiable DP encompasses frameworks combining zero-knowledge proofs, cryptographic randomization, MPC-based noise sampling, and verifiable local randomization. These contributions collectively address the trust challenges in DP deployments, enabling privacy guarantees to be enforced and audited even in adversarial distributed settings \[[1902.07756](http://arxiv.org/abs/1902.07756)\]\[[2208.09011](http://arxiv.org/abs/2208.09011)\]\[[2104.06569](http://arxiv.org/abs/2104.06569)\]\[[https://doi.org/10.1007/978-3-540-24632-9\_31](https://doi.org/10.1007/978-3-540-24632-9\_31)\]\[[2409.10667](http://arxiv.org/abs/2409.10667)\].
