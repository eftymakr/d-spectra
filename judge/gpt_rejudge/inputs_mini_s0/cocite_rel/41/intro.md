## Related Works

Serverless computing, or Function-as-a-Service (FaaS), offers automatic scaling, fine-grained resource utilization, and pay-as-you-go pricing, which simplify cloud application development by abstracting server management \[[1911.01296](http://arxiv.org/abs/1911.01296)\]. Despite these benefits, cold-start latency—delays caused by provisioning runtime containers and initializing function dependencies—remains a significant performance bottleneck, especially for latency-sensitive applications \[[1911.01296](http://arxiv.org/abs/1911.01296)\]\[[https://www.semanticscholar.org/paper/d911b03bfda4fc6fc92f8080bb81b3a967d6a9e7](https://www.semanticscholar.org/paper/d911b03bfda4fc6fc92f8080bb81b3a967d6a9e7)\]. Cold starts introduce overhead due to container startup, runtime initialization, and library loading, which can range from hundreds of milliseconds to several seconds \[[https://www.semanticscholar.org/paper/ab1c0062964a2df3d7f8d11da4a774530286b801](https://www.semanticscholar.org/paper/ab1c0062964a2df3d7f8d11da4a774530286b801)\]\[[https://www.semanticscholar.org/paper/d45518ce5741587c4c37ccbc5e74b3fcfd6f80f1](https://www.semanticscholar.org/paper/d45518ce5741587c4c37ccbc5e74b3fcfd6f80f1)\]\[[https://www.semanticscholar.org/paper/d911b03bfda4fc6fc92f8080bb81b3a967d6a9e7](https://www.semanticscholar.org/paper/d911b03bfda4fc6fc92f8080bb81b3a967d6a9e7)\].

Many approaches have been proposed to mitigate cold-start latency. A common strategy is to keep function containers "warm" by retaining them after execution, avoiding repeated initialization costs. Techniques such as caching and container reuse have been explored extensively. For example, FaasCache employs a caching-inspired greedy-dual keep-alive policy to reduce cold starts by more than threefold compared to existing methods, while also optimizing resource provisioning \[[https://www.semanticscholar.org/paper/3c05fec4087d94c61233a482e59b613388b2c3ae](https://www.semanticscholar.org/paper/3c05fec4087d94c61233a482e59b613388b2c3ae)\]. Similarly, the Least Recently Used (LRU) warm container approach schedules container reuse to reduce cold start occurrences, outperforming other heuristics by approximately 48% \[[https://www.semanticscholar.org/paper/d45518ce5741587c4c37ccbc5e74b3fcfd6f80f1](https://www.semanticscholar.org/paper/d45518ce5741587c4c37ccbc5e74b3fcfd6f80f1)\]. Adaptive container caching policies that consider container size, invocation frequency, and cold-start time have also been developed for serverless edge computing, demonstrating a 3× reduction in both response time and cold-start frequency \[[https://www.semanticscholar.org/paper/f85fde870a1eb9c98c62ded89602e2bd1bab6a86](https://www.semanticscholar.org/paper/f85fde870a1eb9c98c62ded89602e2bd1bab6a86)\].

Checkpoint/restore based methods provide another avenue for reducing startup latency. By restoring function state from snapshots, platforms can bypass costly runtime initialization. The Catalyzer system exemplifies this by using initialization-less booting, restoring virtualized sandbox states from checkpoints to achieve sub-millisecond startup latency with strong isolation guarantees \[[https://www.semanticscholar.org/paper/f14446970a5ed7145a6d350e1aff07ca203cece8](https://www.semanticscholar.org/paper/f14446970a5ed7145a6d350e1aff07ca203cece8)\]. Prebaking functions via process snapshots similarly improves startup times by 40–71%, with even higher gains when snapshots are taken from warm function states \[[https://www.semanticscholar.org/paper/ab1c0062964a2df3d7f8d11da4a774530286b801](https://www.semanticscholar.org/paper/ab1c0062964a2df3d7f8d11da4a774530286b801)\].

Workflow-level optimizations address cascading cold starts in function chains, where each function’s cold start compounds overall latency. Xanadu mitigates this by speculative and just-in-time provisioning of resources along workflows, significantly reducing cascading cold starts and achieving up to an 18× reduction in overhead compared to state-of-the-art platforms \[[https://www.semanticscholar.org/paper/1cd137e77753ee6c51c97c520d64f91d484dbddc](https://www.semanticscholar.org/paper/1cd137e77753ee6c51c97c520d64f91d484dbddc)\]. Function fusion, which combines multiple functions into a single executable unit, also reduces cold start overhead within workflows by eliminating the cold start of fused functions, though it requires careful analysis to avoid serializing parallel executions and increasing response time \[[https://www.semanticscholar.org/paper/36338d869d7589b01c3707d70bece8c320e439e2](https://www.semanticscholar.org/paper/36338d869d7589b01c3707d70bece8c320e439e2)\]. In addition, frameworks like SSC apply pre-warming and automatic resource scheduling for serverless workflows, using gradient-based algorithms to reduce cold start hit rates by nearly 50% and achieve substantial cost savings \[[https://www.semanticscholar.org/paper/fbf4355d06ddb5f6c81e67cffadf57f6939b8940](https://www.semanticscholar.org/paper/fbf4355d06ddb5f6c81e67cffadf57f6939b8940)\].

Machine learning techniques have been employed to predict invocation patterns and proactively prepare function instances, reducing cold start frequency. Reinforcement learning agents using Q-learning have been shown to learn invocation patterns and optimize the number of prepared instances dynamically, outperforming baseline autoscaling approaches \[[https://www.semanticscholar.org/paper/96d4fea8d034a7605af936f2e2b6a44becdf6585](https://www.semanticscholar.org/paper/96d4fea8d034a7605af936f2e2b6a44becdf6585)\]. Workload characterization studies of large-scale serverless platforms such as Azure Functions reveal highly skewed invocation patterns, enabling more effective resource management policies that reduce cold starts while minimizing resource waste \[[2003.03423](http://arxiv.org/abs/2003.03423)\].

Several studies have focused on code-level optimization to reduce cold start overhead. Static analysis can identify unreachable code or libraries, but fails to capture workload-dependent library usage inefficiencies. Application-level optimizations, such as FaaSLight, separate essential from optional code to reduce loading latency by up to 79% \[[https://www.semanticscholar.org/paper/d45518ce5741587c4c37ccbc5e74b3fcfd6f80f1](https://www.semanticscholar.org/paper/d45518ce5741587c4c37ccbc5e74b3fcfd6f80f1)\]. Profiling-based tools like LibProf analyze runtime Python library usage to detect inefficiencies and guide optimizations, achieving over 2× speedup in cold start execution time \[[https://www.semanticscholar.org/paper/ab1c0062964a2df3d7f8d11da4a774530286b801](https://www.semanticscholar.org/paper/ab1c0062964a2df3d7f8d11da4a774530286b801)\]. These dynamic, profile-guided approaches are particularly effective in addressing real-world workload variability and can be integrated into CI/CD pipelines for continuous optimization.

In summary, existing cold-start mitigation approaches span container management (warm container reuse, caching, checkpoint/restore), workflow orchestration (function fusion, speculative provisioning), machine learning-based prediction, and code-level optimization (static and dynamic analysis). However, many static techniques lack adaptability to varying runtime workloads, limiting their efficacy. The proposed SLIMSTART approach leverages profile-guided, workload-aware optimization to identify and reduce inefficient library usage dynamically, complementing prior work by focusing on fine-grained library initialization overheads rather than coarse container or workflow management. This integration of statistical sampling and call-path profiling enhances cold start reduction beyond static methods while maintaining compatibility with automated deployment pipelines.
