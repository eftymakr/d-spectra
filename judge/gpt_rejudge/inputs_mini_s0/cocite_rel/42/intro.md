## Related Works

Cloud-native applications increasingly rely on containerization and orchestration platforms such as Kubernetes to achieve scalable, flexible deployments. Kubernetes, as the de facto standard for container orchestration, provides automated deployment, scaling, and resource management of containerized applications, enabling microservices architectures with improved maintainability and availability \[[https://www.semanticscholar.org/paper/18a720c86ed6e166c26f7d39490bfd11b93ea3ec](https://www.semanticscholar.org/paper/18a720c86ed6e166c26f7d39490bfd11b93ea3ec)\]\[[https://www.semanticscholar.org/paper/b5634b15badc73f3cda72b960fd51ef03ac1265d](https://www.semanticscholar.org/paper/b5634b15badc73f3cda72b960fd51ef03ac1265d)\]. However, efficient scheduling and resource management in Kubernetes remain challenging due to dynamic workloads and complex resource requirements, with ongoing research focusing on scheduler design and performance optimization \[[https://www.semanticscholar.org/paper/d11e5c5c08af88ee8abb9ebaa166b1d6fd198501](https://www.semanticscholar.org/paper/d11e5c5c08af88ee8abb9ebaa166b1d6fd198501)\]\[[https://www.semanticscholar.org/paper/0f4ac27e56efd714e3425bd9784eb76c7cd8c2a9](https://www.semanticscholar.org/paper/0f4ac27e56efd714e3425bd9784eb76c7cd8c2a9)\]\[[https://www.semanticscholar.org/paper/8eabcc47a99622184fc35b731992f10ff9f19444](https://www.semanticscholar.org/paper/8eabcc47a99622184fc35b731992f10ff9f19444)\].

The financial management of cloud resources, particularly under a containerized infrastructure, has gained attention through the emerging FinOps discipline, which integrates financial accountability with operational cloud management to optimize costs \[[2501.14753](http://arxiv.org/abs/2501.14753)\]\[[2307.12479](http://arxiv.org/abs/2307.12479)\]. ABACUS, for example, is a FinOps solution that automates budget setting, cost surveillance, and enforcement actions such as blocking deployments when budgets are exceeded, thus bringing cost governance to cloud usage \[[2501.14753](http://arxiv.org/abs/2501.14753)\]\[[2307.12479](http://arxiv.org/abs/2307.12479)\]. Despite advances in cost optimization strategies—such as resource allocation improvements, model quantization, and GPU instance selection for AI workloads—the specific analysis of network-related costs in Kubernetes environments has been underexplored \[[2307.12479](http://arxiv.org/abs/2307.12479)\].

Cost optimization in cloud-native systems generally focuses on compute and storage resources, yet network expenditures can represent a significant portion of total cloud costs, especially for distributed microservice applications communicating frequently over the network. While Kubernetes provides mechanisms for scaling and resource monitoring, network usage and its associated cost implications have received limited systematic study. Existing works have addressed related performance issues in Kubernetes clusters, such as autoscaling API gateways using monitoring tools like Prometheus to dynamically adjust service instances and improve resource utilization \[[https://www.semanticscholar.org/paper/4d4080e1a2e26fe1ead433741602ab6eccc22b72](https://www.semanticscholar.org/paper/4d4080e1a2e26fe1ead433741602ab6eccc22b72)\]. However, these focus largely on CPU and memory resource management rather than network cost.

Bioinformatics workflows exemplify complex containerized applications deployed on Kubernetes, where reproducibility, scalability, and data management are critical. Solutions like PhenoMeNal integrate Docker containers and Kubernetes orchestration to provide scalable, workflow-driven analysis platforms that dynamically scale resources for large-scale computations, emphasizing cost-effective operation through cloud resource elasticity \[[https://www.semanticscholar.org/paper/d1b8c407ddcf31dba806e580de02cb8c873ea2a6](https://www.semanticscholar.org/paper/d1b8c407ddcf31dba806e580de02cb8c873ea2a6)\]\[[https://www.semanticscholar.org/paper/51e2cba5a013cbd11f2ab760a4e3906cfff44780](https://www.semanticscholar.org/paper/51e2cba5a013cbd11f2ab760a4e3906cfff44780)\]\[[https://www.semanticscholar.org/paper/d32b4e8ef3fbde009efa47249081feaa4aac8b27](https://www.semanticscholar.org/paper/d32b4e8ef3fbde009efa47249081feaa4aac8b27)\]. These frameworks underline the importance of container orchestration in managing resource consumption but do not explicitly address network cost optimization.

Resource management studies in cloud-native platforms have demonstrated that tuning Kubernetes’ default resource settings can significantly impact application completion times and resource release efficiency, highlighting the need for intelligent resource scheduling policies \[[2010.10350](http://arxiv.org/abs/2010.10350)\]. Furthermore, scheduling problems involving heterogeneous and unpredictable resource demands have led to algorithmic solutions that maximize cluster throughput without prior knowledge of traffic patterns, which could indirectly influence network usage patterns in Kubernetes clusters \[[1901.05998](http://arxiv.org/abs/1901.05998)\].

In summary, while substantial research has been conducted on Kubernetes scheduling, container orchestration for microservices, and cloud infrastructure cost optimization—including pioneering FinOps tools like ABACUS—network cost analysis within Kubernetes clusters remains a gap. This paper contributes to filling this gap by focusing on the measurement, modeling, and optimization of network costs in containerized cloud-native applications, thereby advancing both operational and financial management practices in Kubernetes-based environments.
