## Related Works

Serverless computing has gained significant traction due to its ability to abstract server management, enabling automatic scaling, efficient resource utilization, and cost-effective pricing models \[[Syed Salauddin Mohammad Tariq' 2024-06-17](http://arxiv.org/abs/2406.11734v1)\]. However, the cold-start latency issue remains a critical challenge, significantly impacting end-to-end performance \[[Paulo Silva' 2021-05-28](http://arxiv.org/abs/2105.13894v1)\]. Existing approaches to mitigate cold-start latency include caching, application-level optimizations, and AI/ML-based solutions \[[Paulo Silva' 2021-05-28](http://arxiv.org/abs/2105.13894v1)\]. For instance, caching mechanisms aim to reduce the time required to initialize new function instances by reusing previously loaded resources \[[Paulo Silva' 2021-05-28](http://arxiv.org/abs/2105.13894v1)\]. Application-level optimizations focus on minimizing initialization overhead by preloading necessary libraries or optimizing code structure \[[Paulo Silva' 2021-05-28](http://arxiv.org/abs/2105.13894v1)\]. AI/ML-based solutions leverage predictive models to anticipate function invocations and pre-allocate resources accordingly \[[Paulo Silva' 2021-05-28](http://arxiv.org/abs/2105.13894v1)\].

Several studies have explored the root causes of cold-start latency in serverless environments. For example, the paper by \[[Alexandre Savi Fayam Mbala Mouen' 2025-04-15](http://arxiv.org/abs/2504.11338v1)\] highlights that many serverless functions initialize libraries that are rarely or never used under typical workloads, leading to unnecessary overhead. This finding aligns with the observation that static analysis techniques, while useful for identifying unreachable libraries, often fail to address workload-dependent inefficiencies, resulting in limited performance improvements \[[Alexandre Savi Fayam Mbala Mouen' 2025-04-15](http://arxiv.org/abs/2504.11338v1)\]. The paper by \[[Muhammed Golec' 2023-10-12](http://arxiv.org/abs/2310.08437v2)\] further investigates the factors contributing to cold-start latency, including trigger types, request synchronicity, and function resource allocations, revealing that these factors significantly influence the duration and frequency of cold starts \[[Muhammed Golec' 2023-10-12](http://arxiv.org/abs/2310.08437v2)\].

To address these challenges, several approaches have been proposed. The paper by \[[Erika Hunhoff' 2020-10-09](http://arxiv.org/abs/2010.04312v1)\] introduces the concept of snapshot methods, such as Prebaking and SEUSS, to warm up serverless functions and reduce cold-start latency. Prebaking, in particular, has shown promising results, reducing the startup time of functions by up to 69% \[[Erika Hunhoff' 2020-10-09](http://arxiv.org/abs/2010.04312v1)\]. Similarly, the paper by \[[Artjom Joosen' 2024-10-08](http://arxiv.org/abs/2410.06145v1)\] proposes a proactive technique called freshen, which allows developers to specify functionality to perform before a given function executes, thereby mitigating overheads associated with serverless functions at execution time \[[Artjom Joosen' 2024-10-08](http://arxiv.org/abs/2410.06145v1)\]. The paper by \[[Siddharth Agarwal' 2023-08-15](http://arxiv.org/abs/2308.07541v2)\] introduces a system called HydraServe, which minimizes cold-start latency in public clouds by proactively distributing models across servers and overlapping cold-start stages within workers \[[Siddharth Agarwal' 2023-08-15](http://arxiv.org/abs/2308.07541v2)\].

Moreover, the paper by \[[Mohak Chadha' 2022-10-09](http://arxiv.org/abs/2210.04212v1)\] presents a system called FaaSLight, which optimizes cold-start latency by reducing code loading latency through application-level optimization. This approach separates indispensable code from optional code, allowing optional code to be loaded on demand, thereby reducing cold-start overhead \[[Mohak Chadha' 2022-10-09](http://arxiv.org/abs/2210.04212v1)\]. The paper by \[[Junfeng Li' 2019-11-18](http://arxiv.org/abs/1911.07449v4)\] introduces ProFaaStinate, which delays serverless function calls to optimize platform performance by executing calls at convenient times with higher resource availability or lower load \[[Junfeng Li' 2019-11-18](http://arxiv.org/abs/1911.07449v4)\]. These studies highlight the importance of both application-level and system-level optimizations in mitigating cold-start latency.

In addition to these approaches, the paper by \[[Aitor Arjona' 2023-12-12](http://arxiv.org/abs/2312.07090v1)\] proposes a pool-based approach to mitigate cold starts in serverless platforms by maintaining a pool of warm containers, significantly reducing response latency \[[Aitor Arjona' 2023-12-12](http://arxiv.org/abs/2312.07090v1)\]. The paper by \[[Tam N. Nguyen' 2023-04-01](http://arxiv.org/abs/2304.00396v1)\] introduces GreenCourier, a scheduling framework that enables carbon-aware scheduling of serverless functions across geographically distributed regions based on their carbon efficiencies \[[Tam N. Nguyen' 2023-04-01](http://arxiv.org/abs/2304.00396v1)\]. These studies collectively demonstrate the ongoing efforts to address cold-start latency through a variety of techniques, ranging from static analysis to dynamic resource allocation.
