## Related Works

Serverless computing has gained significant traction due to its ability to abstract away server management, enabling automatic scaling, efficient resource utilization, and cost-effective pricing models \[[Syed Salauddin Mohammad Tariq' 2024-06-17](http://arxiv.org/abs/2406.11734v1)\]. However, a critical challenge remains in the form of cold-start latency, which significantly impacts end-to-end performance \[[Cheryl Lee' 2024-03-26](http://arxiv.org/abs/2403.17574v2)\]. This issue arises when new function instances are initialized from scratch, leading to increased latency and reduced user experience \[[Muhammed Golec' 2023-10-12](http://arxiv.org/abs/2310.08437v2)\]. Several studies have explored solutions to mitigate this problem, focusing on reducing initialization time and improving resource utilization.

Existing approaches to cold-start mitigation include caching and application-level optimizations, as well as AI/ML-based solutions \[[Cheryl Lee' 2024-03-26](http://arxiv.org/abs/2403.17574v2)\]. For instance, some works focus on reducing cold-start latency by preloading function instances or using predictive models to anticipate demand \[[Alexandre Savi Fayam Mbala Mouen' 2025-04-15](http://arxiv.org/abs/2504.11338v1)\]. However, these methods often rely on simplistic strategies that fail to fully exploit invocation patterns, resulting in suboptimal performance \[[Erika Hunhoff' 2020-10-09](http://arxiv.org/abs/2010.04312v1)\]. Additionally, static analysis techniques, while useful for identifying unreachable libraries, are limited in their ability to address workload-dependent inefficiencies \[[Artjom Joosen' 2024-10-08](http://arxiv.org/abs/2410.06145v1)\].

A notable effort in this area is the work by LibProf, which introduces a Python profiler specifically designed to identify inefficient library initializations in Python-based serverless applications \[[Siddharth Agarwal' 2023-08-15](http://arxiv.org/abs/2308.07541v2)\]. LibProf uses dynamic program analysis to collect library usage data and generates reports to guide developers in optimizing their code. This approach has demonstrated significant improvements in cold-start performance, achieving up to a 2.26x speedup in initialization latency and a 1.51x reduction in memory usage \[[Siddharth Agarwal' 2023-08-15](http://arxiv.org/abs/2308.07541v2)\]. Similarly, FaaSLight proposes an application-level optimization strategy to reduce code loading latency by separating essential code from optional code, thereby minimizing unnecessary initialization overhead \[[Quoc Tran-Dinh' 2015-07-22](http://arxiv.org/abs/1507.06243v7)\].

Another relevant approach is the use of reinforcement learning to predict and proactively initialize functions based on expected demand . This method leverages function metrics such as CPU utilization and response failure rates to optimize function initialization, resulting in improved throughput and reduced resource wastage . Additionally, the work by HydraServe introduces a system designed to minimize cold-start latency in public clouds by proactively distributing models across servers and overlapping cold-start stages within workers \[[Akash Puliyadi Jegannathan' 2022-06-30](http://arxiv.org/abs/2206.15176v1)\].

In addition to these methods, there are studies that focus on reducing cold-start latency through architectural improvements. For example, the paper by Pagurus proposes a runtime container management system that eliminates cold-start latency by sharing containers across actions . This approach significantly reduces initialization time, with some actions starting in as little as 10ms .

These works collectively highlight the importance of addressing cold-start latency through a combination of static analysis, dynamic profiling, and predictive modeling. While existing solutions have made progress, there remains a need for more comprehensive and adaptive strategies that can effectively mitigate cold-start overhead in serverless environments.
